# Souvenir 대화형 계획 마법사

이 문서는 `$souvenir`가 한 번에 긴 설문을 던지지 않고, 사용자의 짧은 답을 받아 같은 여행에 순서대로 기록하기 위한 실행 계약이다. 실제 저장은 연결된 Notion 도구를 사용하고, 이 문서는 질문 순서·분기·보존 규칙을 정의한다.

## 실행 상태

대화가 이어지는 동안 아래 상태를 유지한다. Notion에는 비밀번호·쿠키·토큰을 저장하지 않는다.

```text
setup: notion_connection(unknown|connected|needs_user_action|unavailable) → skill_active → login → template
trip: trip_id, destination, start_date, end_date, duration_days,
      traveler_count, base_currency
plan: selected_parts, current_part, completed_parts
```

각 단계가 끝날 때 `Souvenir · 설치 기록` 또는 여행 요약 행의 상태를 갱신한다. 사용자가 중간에 멈추면 같은 `current_part`부터 재개하고, 이미 저장된 행은 제목·여행 키·원본 ID를 기준으로 재사용한다. `notion_connection`이 `needs_user_action` 또는 `unavailable`이면 여행 데이터 단계로 넘어가지 않고 연결 안내에서 멈춘다.

첫 실행의 연결 확인은 읽기 전용 Notion 요청 한 번으로 시작한다. 요청이 연결 UI를 반환하면 그 UI를 보여주고, 사용자가 승인했다고 답한 뒤 같은 요청을 한 번 재시도한다. Souvenir가 다른 플러그인을 자동 설치하거나 사용자의 OAuth 승인을 대신한다고 설명하지 않는다.

## 시작 질문

설치가 끝난 새 사용자에게는 아래 한 줄만 먼저 보여준다.

```text
여행지 / 출발일 / 종료일 또는 기간 / 인원 / 기준 통화
예: 후쿠오카 / 2026-12-12 / 2026-12-15 / 4명 / JPY
```

목적지와 날짜 또는 기간이 있으면 바로 여행 요약 행을 만든다. 인원·통화가 미정이어도 멈추지 않는다. 날짜가 없고 기간만 있으면 `duration_days`와 `1일차…N일차`만 준비하고 실제 날짜는 비워 둔다.

저장 직후에는 사용자가 이해할 수 있는 자동 결과만 보여준다.

```text
여행 일수 4일 · 숙박 3박 · 1~4일차 준비 · 기준 통화 JPY
```

## 파트 선택

필수 정보가 저장되면 아래 7개를 한 번에 보여주고, 번호 여러 개 또는 `전부`를 허용한다.

1. 여행 개요·취향
2. 날짜별 일정
3. 항공
4. 숙소
5. 장소 보관함
6. 예산·여행 지갑
7. 준비물·준비할 일

사용자가 선택하지 않으면 권장 순서인 `1 → 3 → 4 → 5 → 6 → 2 → 7`을 제시하고 1번부터 시작한다. 사용자가 `나중에`라고 답한 파트는 미정으로 남기고 다음 파트로 이동한다.

## 공통 입력·저장 규칙

- 질문은 한 번에 한 파트의 최소 입력만 받는다. 기본 질문은 3~5개 필드다.
- 사용자가 `미정`, `건너뛰기`, `없음`이라고 답하면 해당 속성을 비워 두고 상태를 `미정` 또는 `확인 필요`로 저장한다. 실제로 확인하지 않은 값을 `없음`, 0, 완료로 바꾸지 않는다.
- 작성 전에 기존 여행 키와 제목을 검색해 같은 행이 있으면 갱신하고, 새 행을 만들 때는 반드시 여행 키를 연결한다.
- 사용자가 링크·사진·파일을 주면 먼저 읽을 수 있는 정보만 추출한다. 원문을 확인하지 못한 값은 채우지 않고 `확인 필요`로 남긴다.
- 외부 검색 결과·예상 가격·운영 시간은 출처와 확인 시각을 함께 저장한다. 검색 결과만으로 예약·결제를 완료했다고 말하지 않는다.
- 항공권과 숙소 가격은 여행의 기준 통화와 관계없이 **KRW(원화)** 로 입력·표시한다. 원문이 엔화 등 다른 통화라면 확인된 환율 근거로 환산한 원화 금액을 입력하고, 근거가 없으면 자동 환산하지 않고 `확인 필요`로 남긴다.
- 여러 행을 바꾸는 파트는 저장 전에 변경 요약을 한 번 보여주고 `반영` 또는 `건너뛰기`를 받는다.

## 1. 여행 개요·취향

여행 인원이 미정이면 먼저 인원 수만 묻는다. 인원이 `N명`이면 동행자 행을 N개까지 준비하고, 이름을 모르면 `동행자 1…N`을 수정 가능한 자리로 만든다.

각 사람에게 한 줄 형식으로 답하게 한다.

```text
이름 | 역할 | 먹고 싶은 음식 | 선호 이동 | 숙소 취향 | 주의사항
예: 유성 | 예약 담당 | 라멘, 디저트 | 지하철 | 역 근처·조용한 방 | 견과류 알레르기
```

입력은 동행자 DB의 사람별 행에 저장한다. 역할·음식·이동·숙소·주의사항은 개인 정보이며 여행 전체 취향과 섞지 않는다. 여행 전체 방향·템포·가장 중요한 기준은 여행 요약 행에 한 번만 저장한다.

## 2. 날짜별 일정

여행 일수만큼 `1일차…N일차`를 차례로 준비한다. 날짜가 바뀌면 기존 일정의 날짜·일차를 다시 계산하되, 사용자가 쓴 일정명·메모·예약 연결은 보존한다. 기간이 늘어난 경우에만 빠진 일차를 추가한다.

각 일차는 아래 형식으로 짧게 받는다.

```text
일정명 | 시작-종료(선택) | 장소(선택) | 예약/메모(선택)
예: 공항 도착·체크인 | 14:00-16:00 | 후쿠오카 공항→숙소 | 이동 확인 필요
```

작성 후 `플랜 B를 만들까요? (예/아니오)`를 한 번 묻는다. 예라면 각 원래 일정 행의 `플랜 B`, 필요할 때 `플랜 C`만 채운다. 대안을 별도 활성 일정으로 만들지 않으며, 실제 적용은 영향 요약 뒤 사용자의 `반영`을 받아야 한다.

## 3. 항공

먼저 `이미 예약했나요? (예/아니오)`를 묻는다.

### 예약한 경우

텍스트·사진·파일 중 편한 방법을 받는다. 읽은 값은 다음 필드에 매핑한다.

```text
항공사 · 편명 · 가는 편 출발/도착 · 오는 편 출발/도착
공항/터미널 · 예약번호 · 좌석 · 수하물 · 체크인/탑승 마감 · 확인 링크
```

빠진 값은 한 번에 목록으로 보여주고 `입력 / 건너뛰기`를 받는다. 건너뛴 값은 `확인 필요`로 남긴다.

### 예약하지 않은 경우

```text
가는 편 선호 시간대 / 오는 편 선호 시간대 / 항공권 예산(KRW) / 출발 공항(선택)
```

사용자가 검색을 승인하면 최신 웹 검색 결과를 출처와 함께 후보 DB에 기록한다. 후보는 예약 상태를 `후보`로 두고, 선택된 뒤에만 최종 항공 행과 공통 예약 행으로 복사한다. 실제 예약·결제·좌석 확보는 사용자가 항공사/예약 사이트에서 완료해야 한다.

## 4. 숙소

여행 개요에서 숙소 취향을 이미 받았는지 먼저 확인한다. 없으면 아래만 묻는다.

```text
지역/역 선호 · 1박 예산(KRW) · 필수 조건(침대·조식·세탁 등)
```

후보는 텍스트·링크·사진으로 받는다. 각 후보에 아래 항목을 채운다.

```text
숙소명 · 주소 · 링크 · 체크인/체크아웃 · 장점 · 단점 · 1박 비용(KRW) · 숙박 총액(KRW)
```

최종 선택 전 후보 비교를 보여주고, 선택 후에만 `숙소 상태=확정`과 예약 DB 연결을 반영한다. 기존 예약번호·메모·사용자 사진은 삭제하지 않는다.

## 5. 장소 보관함

장소는 여러 개를 한 줄 목록으로 받아도 된다.

```text
장소명 | 지역 | 종류 | 링크/지도 URL | 메모
예: 오호리 공원 | 후쿠오카 | 관광 | https://… | 아침 산책
```

링크가 열리지 않거나 목적지와 맞지 않으면 저장하지 않고 확인을 요청한다. 장소 카드에는 공식 링크·지도·사진·예산 메모·출처·확인일을 저장할 수 있으며, 실제 방문 완료와 일정에 담은 상태는 구분한다.

## 6. 예산·여행 지갑

먼저 각 지갑의 준비 금액을 묻는다.

```text
지갑 이름 / 통화 / 준비 금액
예: 공용 지갑 / JPY / 100000
```

사용자가 사람별 금액을 주면 사람별 지갑 또는 계획 예산 행으로 분리한다. 실제 지출은 `사용처·유형·단계·수단·금액` 다섯 칸만 받고, 지갑 잔액·사용률·통화 표시는 자동 결과로 둔다. 환율은 사용자가 확인한 값과 근거가 있을 때만 입력한다.

## 7. 준비물·준비할 일

기본 목록을 먼저 보여주고, 사용자가 `추가: …` 또는 `빼기: …`로 답하게 한다.

```text
기본 준비물 8개와 출발 전 할 일 15개를 준비했습니다.
추가하거나 제외할 항목이 있나요?
```

개인 준비물은 동행자와 연결하고, 공용 준비물은 대표 담당자와 수량을 둔다. 상태 변경만 진행률에 반영하며 구매 완료·수량 입력을 준비 완료로 추정하지 않는다.

## 완료 판정

파트 저장 후 아래처럼만 보고한다.

```text
✅ 여행 개요 저장 · 동행자 4명
🟡 항공 후보 3개 · 최종 선택 필요
⚪ 숙소 미정 · 후보 입력 대기
```

모든 파트가 끝나면 여행 링크, 자동 결과, `확인 필요` 목록, 다음에 할 수 있는 작업(예약 확정·일정 검사·준비 진행)을 보여준다. 외부 예약·결제·최신 날씨·입국 요건은 자동 완료로 표시하지 않는다.

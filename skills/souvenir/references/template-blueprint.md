# Souvenir 내장 기본 템플릿 청사진

이 문서는 원본 Notion 페이지 링크 없이 Souvenir 템플릿을 대상 워크스페이스에 재생성하기 위한 설계도다. **원본 페이지·데이터베이스 ID를 복사하지 않는다.** 설치 중 생성된 대상 워크스페이스의 URL과 ID를 설치 기록에 저장한다.

## 설치 원칙

- 연결되지 않은 Notion에 쓰기를 시도하지 않는다. 새 워크스페이스에서는 연결 확인 뒤 설치 여부를 한 번만 묻고, 승인 전에는 페이지·데이터베이스를 만들지 않는다.
- 첫 실행 때 대상 워크스페이스에서 `Souvenir · 설치 기록`을 검색한다.
- 완료된 설치 기록이 있으면 그 기록의 매핑을 재사용한다. 데이터베이스·페이지를 다시 만들지 않는다.
- 설치 기록이 없거나 중단 상태면 현재 상태를 읽고 누락된 단계부터 재개한다.
- 사용자 데이터·예시 행·기존 예약·지출은 가져오지 않는다. 구조·속성·수식·뷰·레이아웃만 만든다.
- 사용자가 다른 템플릿 링크를 지정하면 이 청사진보다 해당 템플릿을 우선한다.
- 같은 워크스페이스에서 복제 권한이 있는 Notion 템플릿 링크가 있으면 네이티브 페이지 복제를 먼저 시도한다. 콜아웃·컬럼·커버·뷰·관계·수식을 그대로 보존할 수 있어 청사진 재구성보다 빠르고 원본과 가깝다.
- 다른 워크스페이스의 링크는 현재 Notion 연결 도구가 직접 복제하지 못한다. 사용자가 Notion에서 공개 템플릿을 `복제`한 뒤 대상 사본의 URL·ID를 주면 `manual_duplicate`로 기록하고 그 사본을 연결한다.
- 대상 사본이 없거나 링크가 없을 때만 이 청사진으로 재구성한다. 재구성 결과는 `blueprint_rebuild`로 기록하며 원본의 픽셀 단위 복제라고 표시하지 않는다.
- Notion 쓰기 권한이 없으면 설치를 가장하지 말고, 생성할 구조와 필요한 권한을 채팅에 보여준다.
- 외부 서버를 새로 운영하지 않는다. 저장소에 포함된 선택형 Python 설치기는 공식 Notion API와 사용자가 제공한 토큰만 사용하며, 토큰·쿠키·원본 ID를 저장소에 기록하지 않는다.

## 링크 없이 설치하는 코드 경로

공개·복제 가능한 템플릿 링크가 있으면 Notion의 `복제`가 가장 충실하다. 링크가 없거나 사용자가 직접 재구축을 선택하면 `skills/souvenir/scripts/notion_installer.py`가 `assets/template-manifest.json`을 읽어 대상 워크스페이스에 새 대시보드·네 묶음 페이지·20개 핵심 데이터베이스를 만든다.

```bash
python3 skills/souvenir/scripts/notion_installer.py validate
python3 skills/souvenir/scripts/notion_installer.py plan --pretty
NOTION_TOKEN="secret_..." python3 skills/souvenir/scripts/notion_installer.py install \
  --parent-page "<대상 상위 페이지 URL 또는 ID>"
```

`NOTION_TOKEN`은 로컬 환경 변수로만 주고 채팅·GitHub·매니페스트에 넣지 않는다. 설치 결과의 페이지·데이터베이스 ID는 `.souvenir-install.json`에 기록하며 이 파일은 공유하지 않는다. API 재구축은 구조·입력 속성·컬러 안내를 재생성하지만 네이티브 복제처럼 모든 뷰 배치·관계·수식·커버의 픽셀 단위 보존을 보장하지 않는다. 설치 후 Souvenir가 대상 워크스페이스의 관계·수식·상세 뷰를 연결하고 `template_source=code_rebuild`로 남긴다.

## 빠른 설치 순서

1. 설치 기록 제목만 먼저 검색한다. 완료 기록이 있으면 전체 워크스페이스·참조 원본·모든 DB를 다시 읽지 않고 저장된 매핑을 사용한다.
2. 새 설치는 `대시보드·네 묶음 껍데기 → 관계·핵심 DB → 보조 DB·상세 뷰 → 표시·필터 검수` 네 단계로 나누고 각 단계 종료 시 설치 기록을 갱신한다.
3. 생성 직후 같은 페이지를 반복 조회하거나 모든 DB 행을 예열하지 않는다. 최종 검수는 생성·변경된 대상과 설치 기록만 확인한다.
4. 설치가 중단되면 완료로 표시하지 않고 마지막 단계와 매핑을 남긴다. 다음 실행은 그 단계부터 재개한다.

## 대상 워크스페이스에 만드는 구조

### 페이지

1. `🧳 Souvenir · 여행 대시보드`
2. `🗺️ 계획·장소`
3. `🎫 이동·예약`
4. `💴 예산·동행`
5. `🎒 준비·자료`
6. `Souvenir · 설치 기록` — 설치 버전, 설치 시각, 상태(`진행 중`·`완료`·`중단`), 단계, 템플릿 출처(`native_duplicate`·`manual_duplicate`·`blueprint_rebuild`·`code_rebuild`·`minimal_fallback`), 생성된 페이지·데이터베이스 매핑을 기록하는 내부 페이지

대시보드 순서는 다음을 유지한다.

`진행도 히어로 → 이번 여행 한눈에(D-Day·숙소·지갑) → 오늘·다음 일정 → 여행 바로가기`

커버 이미지가 있으면 `assets/souvenir-cover.png`를 대상 워크스페이스에 업로드해 사용한다. 업로드가 불가능하면 이미지 없이 카드·콜아웃 구조를 유지한다.

### 데이터베이스 레지스트리

아래 이름은 의미 키다. 실제 생성 후 URL/ID는 `Souvenir · 설치 기록`에 매핑한다.

| 의미 키 | 데이터베이스 | 기본 화면 | 핵심 연결 |
|---|---|---|---|
| trip | `✈️ Souvenir · 여행` | 여행 요약·진행 카드 | 일정, 예약, 준비할 일, 준비물, 숙소, 지갑 |
| itinerary | `🗓️ Souvenir · 일정` | 입력 표, 일차별 보드, 달력, 시간표 | 여행, 장소, 예약, 장거리 이동, 현지 이동 |

각 데이터베이스의 세부 속성·선택지·수식은 이 파일에 다시 복제하지 않고 [SKILL.md](../SKILL.md)의 도메인 규칙과 [간편 입력 규칙](input-design.md)을 따른다. 관계를 먼저 만들고, 관계를 읽는 롤업·수식을 나중에 만든다.

## 화면 디자인 계약

### 홈

- 진행도는 전체 폭 한 줄 카드로 둔다. 차트가 아니라 수식 막대를 사용한다.
- D-Day·숙소·지갑은 동일한 원본 행을 읽는 요약 카드로 둔다.
- 오늘·다음 일정은 요약 바로 아래에 둔다.
- 네 묶음 바로가기는 다음 색과 아이콘을 고정한다.
  - `🗺️ 계획·장소` — blue
  - `🎫 이동·예약` — green
  - `💴 예산·동행` — brown
  - `🎒 준비·자료` — orange
- 기술 속성·중간 계산·보조 DB는 기본 화면에서 숨긴다.

### 묶음 상세 화면

- 상단에 해당 묶음 색상의 짧은 콜아웃을 하나 둔다.
- 첫 번째 핵심 데이터베이스 하나만 바로 노출한다.
- 나머지 데이터베이스·수식·설명·검사 화면은 `h3` 토글 안에 둔다.
- 넓은 표보다 카드·갤러리·보드·1열 구성을 우선한다.
- 카드에는 커버, 상태, 핵심 수치만 노출하고 내부 계산 속성은 숨긴다.

## 설치 후 검증

설치가 끝나면 다음을 읽어서 확인한다.

1. 대시보드와 네 묶음 페이지가 대상 워크스페이스에 생성됐는가
2. 대시보드의 진행 카드·D-Day·숙소·지갑 연결이 같은 `trip` 행을 가리키는가
3. 오늘·다음 일정과 모든 상세 뷰가 대상 여행 필터를 사용하는가
4. `expense`의 실제 사용 금액이 연결된 `wallet` 잔액에서 차감되는가
5. 원본 워크스페이스의 URL·ID가 설치 결과에 남아 있지 않은가
6. 설치 기록에 `완료`와 생성된 매핑이 저장됐는가

검증되지 않은 자동 동기화·최신 환율·날씨·예약 상태는 완료로 표시하지 않는다.

# 오류와 예외 처리

Souvenir는 오류가 나면 성공으로 가장하지 않고, **어느 단계에서 멈췄는지·저장 여부가 확실한지·사용자가 무엇을 해야 하는지**를 짧게 보여준다. 모든 사용자 메시지의 마지막 줄은 `다음 할 일: ...`로 끝낸다.

## 오류 분류

| 상황 | 처리 | 사용자에게 안내할 다음 행동 |
|---|---|---|
| 입력 누락·형식 오류 | 저장하지 않고 해당 질문에서 멈춤 | 입력을 고쳐 다시 보내기 |
| Notion 연결·권한 오류 | 현재 파트 쓰기 중단 | 연결·권한을 확인한 뒤 다시 시도 |
| 네트워크·요청 제한 | 읽기만 제한 횟수까지 재시도, 쓰기는 저장 여부가 불명확하면 재전송하지 않음 | 잠시 후 다시 확인 |
| 충돌·다른 작업 진행 중 | 변경안을 덮어쓰지 않고 중단 | 최신 내용을 다시 읽고 변경안 갱신 |
| 저장 후 확인 읽기 실패 | `확인 필요`/`pending_operation`을 남김 | Notion에서 결과를 확인하기 전 재전송하지 않음 |
| 템플릿 복제·구조 검증 실패 | `blocked`로 멈춤 | 복제 권한·링크를 확인하거나 수동 복제 |
| 외부 지도·검색 실패 | 후보를 저장하지 않고 `확인 필요` 유지 | 링크·검색을 다시 확인하거나 직접 입력 |

## 저장 안전 규칙

- 입력 오류는 해당 파트의 변경안만 폐기하고 다른 파트·사용자 메모는 보존한다.
- 저장 여부가 확실하지 않은 쓰기는 자동 재전송하지 않는다. 매핑의 `pending_operation` 또는 `pending_operations`를 먼저 확인한다.
- 같은 작업 키가 이미 존재하면 새 행을 만들지 않고 재사용한다. 여러 행이 발견되면 임의로 고르지 않고 충돌로 멈춘다.
- 충돌이 감지되면 최신 값을 다시 읽어 변경 전후를 보여준 뒤 사용자의 재승인을 받는다.
- 오류가 난 단계 이후의 단계는 실행하지 않는다. 여행·일정·예산 데이터는 템플릿 검증이 끝나기 전에는 만들지 않는다.

## 로컬 실행기 오류 계약

`run_souvenir.py`, `template_gate.py`, `notion_installer.py`는 호스트가 처리할 수 있도록 오류 코드·재시도 가능 여부·단계·다음 행동을 포함한 동일한 형태를 사용한다.

```json
{
  "ok": false,
  "error_code": "CONFLICT",
  "retryable": true,
  "stage": "part-save",
  "message": "최신 페이지가 먼저 변경되었습니다.",
  "next_action": "최신 페이지를 다시 읽고 변경안을 갱신한 뒤 다시 반영하세요."
}
```

이 코드는 로컬 호스트용이며, 사용자 대화에는 내부 ID·토큰·스택 트레이스를 노출하지 않는다. 채팅에서는 다음처럼 간결하게 렌더링한다.

```text
현재: 저장 검증 중단
최신 페이지가 먼저 변경되어 기존 변경안을 저장하지 않았어요.
다음 할 일: 최신 내용을 다시 읽고 변경안을 갱신할까요? [다시 확인] [취소]
```

`UNCERTAIN_WRITE`는 재시도 가능으로 표시하지 않는다. 먼저 Notion의 실제 페이지와 작업 기록을 확인한 뒤 사용자가 재개를 선택해야 한다.

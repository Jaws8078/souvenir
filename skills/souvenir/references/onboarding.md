## 플러그인 빠른 시작 · 환경 점검과 명시적 설치

새 컴퓨터에서 플러그인 설치 상태가 불확실하면 먼저 저장소 루트에서 아래 점검을 실행한다. 기본 실행은 Python·Codex 설치 여부와 ChatGPT 수동 설치 경로만 읽고, 설치 명령을 실행하지 않는다.

```bash
python3 skills/souvenir/scripts/install_souvenir.py
```

사용자가 실제 등록을 명시적으로 승인한 경우에만 `--apply`를 붙인다. 이 옵션은 공식 Codex CLI로 Souvenir 마켓플레이스를 등록하고 플러그인 목록을 확인한다. 비밀번호·쿠키·Notion 토큰은 읽거나 저장하지 않는다.

```bash
python3 skills/souvenir/scripts/install_souvenir.py --apply
```

Codex CLI가 없는 경우에는 설치 명령을 대신 실행했다고 말하지 말고, 사용자가 Codex를 설치하거나 ChatGPT Plugins Directory에서 Souvenir를 직접 설치하도록 안내한다. 설치가 끝난 뒤 새 Codex 채팅에서는 `$souvenir`를, ChatGPT Work에서는 `@Souvenir`를 선택해 호출한다. 이 설치기는 플러그인 배포를 대신하는 것이 아니라, 이미 로드된 Souvenir 패키지에서 공식 설치·검증 명령을 안전하게 묶어 주는 보조 실행기다.

## 시작 전 · Notion 앱/웹 실행 점검

온보딩을 시작하기 전에 현재 실행 환경이 컴퓨터 제어(CUA)나 공식 앱 실행 UI를 제공하는지 확인한다. 이 단계는 로그인 정보를 수집하지 않으며, Python/TypeScript 설치기를 사용하지 않는다.

1. 네이티브 앱 목록을 읽을 수 있고 `Notion`이 설치되어 있으면 Notion 앱을 열거나 이미 실행 중인 창을 활성화한다.
2. 앱이 설치되어 있지만 열기·활성화에 실패하면 브라우저 fallback으로 전환한다.
3. Notion 앱이 없으면 브라우저에서 `https://www.notion.so`를 연다. 인증되지 않은 경우 Notion이 공식 로그인 화면으로 이동하게 둔다.
4. CUA나 앱 실행 UI가 없는 환경에서는 앱을 열었다고 말하지 않는다. Notion 연결 도구가 제공하는 공식 연결 UI를 표시하거나 홈페이지 주소를 안내한 뒤, 사용자가 준비되었다고 하면 1단계 연결 확인을 재개한다.
5. 앱/웹을 연 뒤에도 Notion 연결과 로그인 상태는 별도로 읽기 전용 확인한다. 앱이 설치되어 있다는 사실만으로 로그인 완료로 간주하지 않는다.

실행 결과는 `app_opened`, `web_opened`, `ui_unavailable` 중 하나로 현재 대화에만 남기며, 경로·쿠키·비밀번호·토큰은 저장하지 않는다.

## 첫 사용 온보딩 · 1~5단계

처음 쓰는 사용자는 작업 메뉴를 바로 보여주지 말고 아래 다섯 단계를 순서대로 안내한다. 각 단계의 완료 상태는 현재 대화와 `Souvenir · 설치 기록`에 남기며, 이미 확인한 값은 다시 묻지 않는다. 연결·로그인·템플릿 설치가 끝나기 전에는 여행 데이터를 만들지 않는다.

### 1단계 · Notion 플러그인 연결

시작 전 앱/웹 실행 점검 결과를 확인한 뒤 Notion 플러그인 연결 상태를 읽기 전용으로 확인한다. 연결되지 않았으면 비밀번호·쿠키·토큰을 요구하지 말고, 연결 도구가 제공하는 공식 연결 UI가 있으면 그 UI를 표시한다. 연결 UI를 호출할 수 없는 환경에서는 임의의 로그인 팝업을 띄우지 말고, 사용자가 Notion 연결을 완료한 뒤 같은 채팅에서 재개하도록 안내한다. 연결 확인 전에는 워크스페이스 검색이나 페이지 생성을 시도하지 않는다.

### 2단계 · Souvenir 스킬 연결

현재 채팅에서 Souvenir 스킬이 활성화되었는지 확인한다. 활성화되지 않았으면 `$souvenir` 호출 또는 저장소 루트 폴더 열기를 안내하고, 활성화된 뒤 3단계로 넘어간다. 스킬이 이미 활성화되어 있으면 이 단계를 반복하지 않는다.

### 3단계 · Notion 로그인 상태 확인

연결된 Notion 세션의 로그인 상태를 확인한다. 로그인 필요 응답과 함께 연결 도구가 로그인/재연결 UI를 반환하면 그 UI를 먼저 표시한다. 이 스킬이나 설치 스크립트가 임의의 브라우저 로그인 창을 직접 열 수 있다고 약속하지 않는다. UI가 제공되지 않으면 다음처럼 안내하고 대기한다.

> Notion 로그인이 필요합니다. Notion 화면에서 로그인한 뒤 `다시 확인`이라고 입력해주세요.

사용자가 로그인한 뒤 같은 단계부터 재개한다. 비밀번호·쿠키·개인 토큰은 채팅으로 받거나 저장하지 않는다. 로그인 상태가 확인되기 전에는 템플릿 링크를 복제하거나 설치 기록을 쓰지 않는다.

### 4단계 · 템플릿 연결

로그인과 연결이 확인된 뒤 정확한 제목의 `Souvenir · 설치 기록`만 한 번 찾는다. 완료 기록이 있으면 대상 페이지·데이터베이스 매핑을 재사용하고 전체 워크스페이스를 반복 검색하지 않는다.

설치 기록이 없으면 다음을 한 번만 묻는다.

> 이 워크스페이스에 Souvenir 기본 템플릿을 연결할까요? 원본과 같은 화면을 원하면 공개·복제 가능한 Notion Marketplace 템플릿 링크를 사용합니다.

- 승인하고 공개·복제 가능한 링크가 있으면 Marketplace 링크를 첫 경로로 사용한다. 사용자가 자신의 워크스페이스에서 `복제`를 완료한 뒤, Souvenir는 새 사본의 URL·ID를 읽어 연결한다.
- 같은 워크스페이스의 원본이면 Notion 네이티브 복제를 우선하고, 다른 워크스페이스의 링크는 사용자의 복제 동작 없이는 대신 복제하지 않는다.
- 링크가 없거나 사용자가 거절하면 내장 청사진으로 새 구조를 재구성한다. 이 경우 원본의 픽셀 단위 복제라고 설명하지 않는다.
- 설치 기록을 `진행 중`으로 먼저 저장하고, 연결이 끝난 뒤 `완료`와 `template_source`를 기록한다. 중단되면 완료로 표시하지 말고 중단 단계와 매핑을 남겨 다음 실행에서 재개한다.

### 5단계 · 필수 여행 정보 입력

템플릿 연결이 완료되면 아래 값을 한 번에 짧게 제시한다. 모르는 값은 `미정`으로 둘 수 있지만, 여행을 만들려면 여행지와 날짜 또는 기간 중 하나는 필요하다.

- 여행지
- 출발일
- 종료일
- 여행 인원 수
- 기준 통화(KRW·JPY·USD·EUR·미정)

입력한 값은 새 여행 요약 행 하나에 먼저 저장하고, 이후 일정·항공·숙소·장소·지갑·준비물 뷰가 같은 여행 관계를 사용하게 한다. 인원 수를 입력하면 그 수만큼 동행자 행을 준비하되, 이름·역할·취향은 `여행 개요·취향` 단계에서 이어서 받는다. 기준 통화는 지갑·예산에 연결한다. 항공권과 숙소 가격은 기준 통화가 JPY여도 KRW(원화)로만 입력·표시하며, 환율을 임의로 조회하거나 확정하지 않는다.

날짜가 있으면 출발일과 종료일을 모두 저장한다. 날짜를 모르면 기간만 저장하고 임의 날짜를 만들지 않는다. 사용자가 `3박 4일`처럼 기간만 입력하면 1~4일차를 준비하되 실제 날짜와 D-Day는 미정으로 남긴다. 기본 정보가 일부 미정이어도 여행 생성을 막지 않고, 홈의 `필수 정보 확인`에서 남은 값을 표시한다.

첫 질문은 다음처럼 입력 구역과 자동 결과를 구분해 짧게 제시한다.

```text
여행지 / 출발일 / 종료일 / 인원 수 / 기준 통화
예: 후쿠오카 / 2026-12-12 / 2026-12-15 / 4명 / JPY
```

입력 예시는 사용자가 그대로 복사해 바꿔 쓸 수 있게 함께 보여준다.

- 날짜를 아는 경우: `후쿠오카 / 2026-12-12 / 2026-12-15 / 4명 / JPY`
- 기간만 아는 경우: `오사카 / 3박 4일 / 인원 미정 / JPY`
- 일부가 미정인 경우: `도쿄 / 출발일 미정 / 종료일 미정 / 2명 / KRW`

입력 뒤에는 자동 결과를 별도 구역으로 보여준다. 예를 들어 첫 번째 입력이면 `여행 일수 4일 · 숙박 3박 · 1~4일차 준비 · 기준 통화 JPY`를 표시하고, 두 번째 입력이면 `실제 날짜 미정 · D-Day 미정 · 1~4일차 준비`로 표시한다. 날짜나 기간이 없으면 목적지만 저장하지 말고 날짜 또는 기간만 추가로 요청한다.

Notion 연결 도구로 날짜를 저장할 때는 일반 `여행 기간`·`출발일`·`종료일` 문자열을 보내지 않는다. 스키마의 확장 속성인 `date:출발일:start`, `date:종료일:start`, `date:여행 기간:start`, `date:여행 기간:end`와 각 `date:…:is_datetime` 값을 사용한다. 날짜만 입력하면 `is_datetime=0`으로 저장하고, 기간을 모르면 종료 날짜와 여행 기간의 `end`를 비워 둔다.

사용자가 이미 `후쿠오카 3박 4일`처럼 말한 경우에는 목적지와 기간을 다시 묻지 않는다. 인원·통화만 추가로 묻거나 `미정`으로 저장하고 다음 단계로 진행한다.

### 대화형 계획 마법사 · 파트별 진행

1~5단계가 끝난 뒤에는 [대화형 계획 마법사](conversation-flow.md)를 읽고 적용한다. 이 문서는 질문 순서와 저장 계약을 정하며, 모든 질문을 한 번에 던지는 긴 설문으로 바꾸지 않는다.

- 먼저 `여행 개요·취향 / 날짜별 일정 / 항공 / 숙소 / 장소 보관함 / 예산·여행 지갑 / 준비물·준비할 일`을 보여주고 번호 여러 개 또는 `전부`를 받는다.
- 선택이 없으면 `여행 개요·취향 → 항공 → 숙소 → 장소 보관함 → 예산·여행 지갑 → 날짜별 일정 → 준비물·준비할 일` 순서를 추천한다.
- 각 파트는 최소 입력을 받은 뒤 해당 여행 키로 저장하고, `미정·건너뛰기`는 빈값과 `확인 필요` 상태로 남긴다. 기존 행은 제목·여행 키·원본 ID를 대조해 재사용한다.
- 기간으로 시작한 여행은 1일차부터 입력받은 일수까지 일정 행을 준비한다. 기간이 늘었을 때만 빠진 일차를 추가하고, 기존 일정명·예약·메모를 덮어쓰지 않는다.
- 항공·숙소 후보를 외부에서 찾을 때는 검색 승인과 출처 저장을 거친다. 검색 결과는 후보일 뿐 예약·결제 완료가 아니다.
- 여러 행을 한 번에 바꾸기 전에는 변경 요약을 보여주고 `반영`을 받은 뒤 저장한다. 파트 완료 후에는 저장된 항목, 미정·확인 필요 항목, 다음 선택지를 짧게 보고한다.

새 워크스페이스에서 `$souvenir`를 처음 실행하면 위 1~5단계를 순서대로 적용한다. 작업 메뉴나 여행 입력으로 바로 넘어가지 않으며, 1~4단계가 끝난 뒤에만 5단계의 기본 정보를 받는다. 사용자가 템플릿 설치를 거절하면 템플릿을 만들지 않고 요청한 작업만 최소 구조로 진행한다. 이미 `완료` 기록이 있으면 1~4단계의 설치 질문과 전체 검색을 반복하지 않고, 누락된 기본 정보만 5단계에서 묻는다.

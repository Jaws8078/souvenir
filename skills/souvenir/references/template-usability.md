# 템플릿 사용성과 인원 규칙

현재 디폴트 디자인인 비공개 Notion 작업 원본을 만들거나 복제할 때, 사용할 화면을 바꿀 때, 동행자 수가 달라질 때 적용한다. 다른 워크스페이스에서는 [내장 기본 템플릿 청사진](template-blueprint.md)으로 로컬 구조를 만든 뒤 이 규칙을 적용한다. 사용자가 다른 템플릿을 지정하면 그 구조를 우선한다.

## 네 묶음만 선택

| 묶음 | 포함 내용 | 디자인 |
|---|---|---|
| 계획·장소 | 개요·취향, 일정, 장소, 날씨와 일정 카드 안의 플랜 B/C | 파랑·지도 |
| 이동·예약 | 항공/현지 이동, 패스·렌터카, 숙소, 예약 | 초록·숙소 |
| 예산·동행 | 지갑·지출·차트, 계획 예산, 인원·역할·정산 | 브라운·금액 |
| 준비·자료 | 할 일, 준비물, 담당자별 진행률, 자료 | 주황·가방 |

세부 기능마다 질문하지 않고 네 묶음을 한 번에 제시한다. 이미 선택했으면 다시 묻지 않는다. 목적지·기간만으로 시작하라는 요청에는 기본 네 묶음으로 시작하고 나중에 끌 수 있게 한다. 선호를 알면 필요한 묶음만 켠다.

`Souvenir · 여행 화면`의 한 행은 여행별 묶음 페이지다. 여행·묶음·순서·사용을 기록한다. 홈 갤러리는 **해당 여행 AND 사용=true**로 필터링한다. 접힌 선택 표는 해당 여행의 모든 묶음과 사용 체크를 보여준다. 사용을 끄면 메뉴만 숨기며 페이지·예약·지출·메모는 보존한다.

새 여행에서는 묶음 페이지도 새 행으로 만든다. 새 여행으로 연결하고 내부의 모든 탭·차트 필터와 홈 이동 링크를 바꾼다. 원본 행·사용 체크·뷰 필터를 수정하지 않는다. 메뉴만 복사하여 원래 여행의 묶음 페이지로 연결하면 안 된다. 관계 기반 필터는 새 여행 관계와 기존 취소/제외 조건을 함께 유지한다. 여행 요약 단일 행 뷰는 제목 대신 `여행 키`(하이픈을 제거한 `id()`)로 새 여행 ID를 필터링한다. 제목 변경으로 화면이 비면 안 된다.

## 화면과 입력

속성 표시와 질문 개수에는 [간편 입력 규칙](input-design.md)을 적용한다. 사진·색상·카드로 화면을 풍성하게 구성하되 기본 작성 화면은 짧게 유지한다. 자동 계산은 입력 항목과 분리하고 보조 속성은 숨긴다.

- 홈은 페이지 최상단의 진행도 히어로 뒤에 `이번 여행 한눈에` 요약 영역을 두고, 그 다음 `오늘과 다음 일정`, `여행 바로가기`를 이어간다. D-Day·숙소·여행 지갑 카드는 34/33/33 비율의 3열을 기본으로 하되 모바일에서는 1열로 쌓이며 각각 파랑·초록·브라운 콜아웃을 쓴다. 각 카드 아래에는 바로가기 메뉴와 동일한 해당 여행의 계획·장소 / 이동·예약 / 예산·동행 페이지를 네이티브 멘션으로 연결한다. 요약과 상세 관리가 같은 원본 행을 사용하도록 유지한다. 네 묶음의 세부 입력·보조 DB·수식은 요약 아래 바로가기 화면에서 토글로 접고, 진행 막대는 요약 카드와 별개로 페이지 최상단에 둔다. 새 여행 복제 시 세 카드의 여행 필터와 관리 화면 연결도 함께 갱신한다. 숙소·예산 묶음을 끄더라도 요약 카드는 유지하며 미정 상태를 임의의 예약·금액으로 채우지 않는다.
- 홈의 진행도·메뉴와 상세 화면은 1열을 기본으로 한다. 최상단 진행 막대는 컬럼·갤러리 카드 안에 넣지 않고 페이지 전체 폭으로 둔다. 큰 상세 DB 표도 컬럼 안에 넣지 않는다.
- 각 묶음에는 고유 아이콘·컬러 콜아웃·목차를 두고 첫 DB만 핵심 화면으로 노출한다. 나머지 DB·수식·설명은 같은 색 계열의 `h3` 토글과 상세 화면 안으로 접는다. 계획·장소는 지도 파랑, 이동·예약은 숙소 초록, 예산·동행은 금액 브라운, 준비·자료는 가방 주황을 사용한다.
- 일정 달력·타임라인·일차별 보드, 장소/숙소 갤러리, 예약/준비 상태 보드, 지출 차트를 유지한다. 모바일 목록은 이름과 핵심 속성 2~3개만 보여주고 카드를 열어 자세히 입력한다. 기존 상세 탭은 보존한다.
- 공통 배너 원본은 저장소의 `assets/souvenir-cover.png`다. 같은 템플릿의 커버·아이콘·색상 규칙을 맞추되 실제 여행/숙소 사진은 보존한다. 추상 배너를 실제 목적지 사진이라고 설명하지 않는다.
- 예시는 별도 `작성 예시` 페이지에서 묶음별로 접어 보여주고 사용자가 원할 때만 가져온다. 가상 예약·금액·취향·날씨를 사용자 정보로 복사하지 않는다. 예전 안내와 보기는 `사용 가이드 · 이전 보기`에 보관한다.
- 빈칸은 **미정**, 근거·입력을 다시 확인해야 하면 **확인 필요**, 실제 실행·확인이 끝나면 **완료**다. 미정 값을 0·없음·1명으로 확정하지 않는다.

## 최상단 가로 진행도

홈 최상단 진행 바는 **차트가 아닌 여행 DB의 수식 + 한 행짜리 연결 표**로 만든다. 무료 차트 한도 오류가 확인되었으므로 진행도에 네이티브 차트를 다시 사용하지 않는다. `진행도 비율`을 내부 계산값으로 두고, `진행도 퍼센트`·`진행도 상태`·`진행도 카드`를 자동 결과로 만든다. `진행도 카드`는 한 셀 안에 퍼센트·28칸 막대·완료 건수를 자연스러운 순서로 보여주며, 채운 칸은 파스텔 블루의 두꺼운 블록, 남은 칸은 은은한 회색 블록으로 표시한다. 막대는 `전체 진행 완료 ÷ 전체 진행 대상`을 직접 읽어 수동 조정 결과도 바로 반영한다. `진행도 상태`는 상세 보기에서만 보여 메인 한 줄이 문구로 끊기지 않게 한다. 여행 이름과 진행도 카드만 남긴 한 줄 표를 페이지 전체 폭으로 배치하고 줄바꿈을 끈다. 화면 크기에 맞춰 선이 자동 늘어나는 그래프라고 설명하지 않는다. 대상이 없으면 `집계 전`·`등록한 항목 없음`과 빈 회색 막대를 표시한다. 기존 개별 진행률·계산 설명은 바로 아래 토글에 보존한다. 자동 진행은 네 묶음의 실제 완료 집계를 기본으로 하되, 여행 카드의 `진행도 수동 조정`에서 묶음별 `직접 완료`·`자동 제외` 체크박스를 제공한다. `직접 완료`는 자동 기준 전에도 해당 묶음을 완료로 반영하고, `자동 제외`는 자동으로 완료된 묶음을 검토 보류로 되돌린다. 둘 다 켜져 있으면 직접 완료를 우선한다. 자동 수식과 수동 입력을 같은 체크박스에 섞지 않는다. 새 여행 복제 시 진행 카드와 상세 뷰의 여행 키를 새 여행으로 필터링한다. 퍼센트는 수동 입력하지 않는다. 기존 차트용 DB·완료/남음 보조 행과 차트 보기는 데이터 보관함에 보존했으며 활성 홈에서는 사용하지 않는다. 실제 계산값·화면을 읽지 못했다면 검증을 주장하지 않는다.

전체는 사용 중인 묶음의 **완료 건수 합계 ÷ 대상 건수 합계**이며 항목별 비중은 같다. 일정은 계획 완료·진행 중·완료, 예약은 기존 예약 확정 집계, 할 일·준비물은 기존 완료 집계를 사용한다. 일정의 취소·건너뜀, 할 일·준비물의 제외, 예약의 취소·환불 상태는 기존 집계 기준에 따라 뺀다. `사용 화면`의 계획·장소/이동·예약/준비·자료 사용 여부를 각각 롤업하여 끈 묶음은 전체와 세부 집계에서 사용 안 함으로 표시한다. 예산 지출률·여행 날짜 경과·검토 후 정산액은 진행도로 섞지 않는다.

등록된 항목이 0개면 전체는 `집계할 항목 없음`, 세부는 `등록 전`으로 표시하며 100%로 가정하지 않는다. 숫자 진행률의 0은 이 빈 상태와 함께 해석한다. 일정에 연결한 예약·할 일은 각각 별도 관리 항목으로 집계된다. 100%는 등록한 관리 항목의 상태 기준이며 미등록 사항·최신 정보·입국 요건 검증까지 완료됐다는 뜻이 아니다. 원래 상태를 바꾸거나 가상 완료를 넣어 퍼센트를 높이지 않는다. 계산 설명은 접힌 토글로 둔다.

## 인원 설정

여행의 `인원 기준=직접 입력`이면 양의 정수 `여행자 수`, `명단 기준`이면 연결한 동행자의 `참여 수` 합계를 `적용 인원`으로 사용한다. 동행자의 참여·기존 빈 상태는 1, 보류·불참은 0이다. 기준이 비어 있으면 유효한 직접 입력을 우선하고 없으면 명단을 사용한다. 직접 입력과 명단이 다르면 `인원 안내`에서 확인하게 한다. 0명은 인원 미정이며 임의로 1명으로 계산하지 않는다.

사용자가 인원을 알려주면 해당 여행의 기존 명단을 읽고 한 사람당 한 행으로 맞춘다. 이름이 미정이면 `동행자 1`처럼 수정 가능한 자리만 만들고 실제 이름·역할·요청은 추정하지 않는다. 이미 있는 사람은 재사용한다. 인원이 줄어도 과거 사람·담당·거래를 삭제하지 않고 보류/불참과 담당 재배정을 검토한다.

개인 준비물은 필요한 사람별 행, 공용 준비물은 대표 담당과 공용 수량으로 관리한다. 인원 변경으로 구매·챙긴 수량·준비 완료 상태를 임의로 복제하지 않는다. 혼자면 정산·공동 결정은 접고 여럿이면 명단·담당자/분담 보기를 활용한다. 수식은 인원에 반응하지만 사람별 행 생성·담당 재배정·화면 조정은 스킬이 요청을 반영할 때 처리한다. 인원 변경만으로 이러한 행이 자동 생성된다고 설명하지 않는다.

## 예산과 실제 기록

계획 예산의 `인원 기준`은 다음 중 하나다.

| 기준 | 적용 인원 |
|---|---|
| 여행 전체 | 연결한 여행의 적용 인원 |
| 선택한 동행자 | 대상 여행자의 참여 수 합계 |
| 직접 입력 | 양의 정수 계산 인원 |
| 기존 빈 기준 | 유효한 계산 인원 우선, 없으면 여행 인원 |

여행과 지갑은 각각 정확히 하나 연결한다. 선택한 동행자가 같은 여행인지 대조한다. **범위=1인**인 카테고리 한도만 금액×적용 인원이며 **일행 전체**는 금액 그대로다. 인원이나 금액이 미정이면 예산 현황에서 확인 필요로 표시하고 0원 확정 예산으로 안내하지 않는다. 예상액·확정액은 해당 행에 기록된 값이며 인원 변경만으로 자동 배수 처리하지 않는다.

지갑 준비 금액은 해당 지갑의 실제 총액이며 인원 배수를 곱하지 않는다. `1인 예산 참고`는 전체 지갑을 여행 인원으로 나눈 참고값이고 실제 부담액이 아니다. 1인 지갑이면 입력한 준비 금액 그대로 표시한다. 지갑 간 통화를 섞어 합산하지 않는다.

인원 변경은 실제 결제·환불, 예약 인원/총액, 기존 분담을 자동 변경하지 않는다. 예약 인원·객실 구성·개인 준비물·담당자를 조정해야 하는지 보여주고 관련된 항목만 반영한다. 과거 분담은 거래 당시 인원·금액을 보존한다. 재분담은 원거래·참여자·합의를 검토한 뒤 갱신하며 사람별 정산은 SKILL.md의 검토 스냅샷 규칙을 유지한다.

## 확인 범위

사용자는 워크스페이스의 네이티브 차트를 모두 삭제하도록 요청했다. 기본 템플릿 생성·복제에서 네이티브 차트를 새로 만들지 않는다. 예산·지출은 기존 표·수식 요약으로 제공한다. 2026-11-11 점검에서 접근 가능한 최상위 11개 페이지와 하위 항목 663개에서 차트 보기 3개를 발견했다. 진행도 차트 전용 연결 블록과 카테고리 지출 차트가 있는 연결 블록을 삭제했고, 지출의 표 5개는 동일 데이터 소스에 재생성해 보존했다. 원본 예산 DB의 `분류별 예산` 차트 탭은 도구의 보기 삭제 기능 부재와 앱 입력 오류로 남아 있다. 이 탭을 없애려고 원본 예산 DB나 행을 삭제하지 않는다. 검사 범위는 페이지/DB 하위 블록이며 모든 DB 행 안의 페이지까지 전수 확인했다고 말하지 않는다.

저장 응답·하위 DB 보존·뷰의 여행 필터·갤러리의 사용 조건·수식 컴파일을 확인한다. 실제 렌더링이나 계산 결과를 읽지 못했으면 검증했다고 말하지 않는다. 조회 한도 오류는 반복하지 않고 개별 페이지·스키마 확인으로 할 수 있는 작업을 진행하며 남은 검수를 밝힌다. Python·TypeScript는 추가하지 않는다.

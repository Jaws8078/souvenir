## 날씨·플랜 B/C·자료 보관함

`지역별 날씨`는 방문 지역과 대상 기간별로 공식 확인 링크·자료 종류·확인 상태·예보 확인일·다음 확인일을 기록한다. 최저/최고는 ℃, 강수 확률은 %이며 실제로 확인한 값에만 확인 체크를 켠다. 미확인은 빈값으로 남기고 0℃·0%를 미정으로 취급하지 않는다. 평년 참고·단기 예보·특보/운영 안내를 구분한다. 실제 날씨가 필요할 때는 해당 지역·여행일의 공식 정보를 조회하고, 예보가 제공되지 않는 기간의 값을 확정하거나 평년값을 예보로 바꾸지 않는다. 기온·강수에 따른 대비 내용과 기존 준비물을 연결하되 자동 구매·준비 완료로 처리하지 않는다. 저장된 링크와 수치는 자동 갱신된다고 설명하지 않는다.

**플랜 B·C는 기존 일정 한 행의 속성이다.** 대안용 별도 일정 DB나 활성 일정 행을 만들어 기본 일정·비용·방문 집계에 중복 포함하지 않는다. 기존 일정의 날씨/고정 일정·플랜 B/C 탭과 일정 카드에서 활동 환경, 변경 유연성, 변경/취소 확인, 대안 검토 이유·선택 기준·판단 시점을 기록한다. B/C 각각의 이름·기존 장소 카드·환경·지도·이동·확인사항을 관리한다. 우천·기온/기상·휴무·매진·지연 등에 대한 선택 기준은 사용자 상황과 확인 근거로 정하며 자동 전환 임계값을 임의로 확정하지 않는다. 고정 일정은 실제 예약·운영 조건부터 확인한다.

`검토할 대안` 선택이나 판단 시점 도래만으로 원래 일정·날짜·장소·예약을 변경하지 않는다. 실제 반영은 기존 일정 수정 규칙에 따라 원안 대비 이동·다음 일정·예약·비용 영향을 먼저 보여주고 반영 요청 후 관련 부분만 수정한다. 적용 직전 다시 읽고 사용자 메모·원래 예약 정보·다른 날짜를 보존한다. 필요한 원안·변경 기록은 페이지 본문에 부분 추가하고 B/C 후보를 지우지 않는다. 반영 상태는 실제 변경 이후에만 반영 완료로 기록한다. 원래 계획을 수정하지 않았는데 대안이 적용됐다고 말하지 않는다.

`여행 자료 보관함`은 링크·파일·요약·지역/태그·출처·확인일/상태·대상 기간을 종류별로 관리한다. 일정·장소·예약을 연결해 원래 카드에서 찾게 한다. 이미 예약에 저장한 바우처·QR·확인서는 불필요하게 복제하지 않고 해당 예약을 연결한다. 중요 자료와 보관 자료를 구분하고 보관 상태는 기본 화면에서 제외하되 전체 보기에서 남긴다. 파일을 저장했다고 오프라인 다운로드가 완료됐다고 설명하지 않는다. 공식 확인처 링크를 저장한 것과 실제 여행일의 내용을 확인한 것은 구별한다.

새 여행에서는 날씨·자료·일정 대안 뷰도 해당 여행으로 필터링한다. 기본 공식 링크는 해당 지역에 맞는 자료만 재사용하고 예시 기온·강수·대안·확인 결과는 가져오지 않는다. 실제 사용자 자료의 출처·파일·예약 연결은 보존한다. 템플릿 구성 단계에서는 날씨와 자료를 독립 섹션으로 추가하고, 플랜 B/C는 기존 일정 파트 안에 유지한다.

## 추가 자동 확인

D-Day·일수/숙박 일수·여행 상태·소요 시간·진행률·환산/인원 범위·예산·검토 후 정산은 기존 기능을 유지한다. 다음 기능만 추가했다. 기존 `일정 확인`은 행 내부 입력 점검이며, 일정 간 겹침/이동 검사는 아래 비교 기록을 사용한다.

`일정 비교 검사`는 원래 일정 행과 구분되는 검사 기록이다. 기준/비교 일정 하나씩을 연결해 반개방 구간 `[시작, 종료)`의 겹침을 계산한다. 앞 일정 종료와 다음 시작이 같으면 겹침이 아니다. 원래 일정의 `시각 확인`은 시작·종료 시각이 실제로 정해진 경우만 켠다. 날짜만 있거나 종료가 없으면 시각 확인 필요로 남기고 취소·건너뜀은 검사에서 제외한다. 의도적인 병행 일정은 사용자 근거가 있을 때만 겹침 허용과 메모를 남긴다.

연속 이동 구간에는 확인한 `필요 이동(분)`·`필요 여유(분)`을 기록하고 `이동 기준 확인`을 켠다. `다음 시작−앞 종료−필요 이동−필요 여유`가 음수면 부족을 표시한다. 0분도 확인한 경우만 쓰고 이동·안전 여유 기준을 임의로 정하지 않는다. 방향/순서가 바뀌면 해당 이동 기준 확인을 끄고 재검토한다. 경고를 보고 원래 일정·예약을 자동 변경하지 않는다.

사용자가 `일정 검사해줘`라고 하거나 일정을 생성/수정해 반영한 뒤에는 해당 여행의 일정과 기존 검사 기록을 읽는다. 같은 여행의 서로 다른 일정 쌍을 중복 없이 연결하고 시작 시각/일차/순서에 맞춰 기준·비교 방향과 실제 연속 이동 구간을 갱신한다. 취소/건너뜀 행도 연결 범위에는 남겨 재활성화에 대비하되 결과는 제외한다. 기존 기록을 재사용하고 누락 쌍만 추가한다. 현재 여행 일정이 n개면 한 일정의 비교 연결은 n−1개가 기준이다. `검사 범위`는 누락/중복 연결을 알리는 점검이며 연결 수 충족 자체가 충돌 없음·필수 정보 완비를 뜻하지 않는다. 같은 여행 연결과 중복 쌍도 실제 ID로 확인한다. B/C 후보는 별도 일정으로 만들지 않으므로 검사 건수에도 일정으로 추가하지 않는다.

연결된 쌍은 날짜 변경을 계산에 반영하지만 새 일정·비교 기록은 자동 생성되지 않는다. 수동 추가·순서 변경 후에는 스킬로 비교 연결을 갱신한다. 부분 검사나 미연결 상태를 전체 자동 검사 완료라고 설명하지 않는다. 검사 기록은 메인 일정 파트의 접힌 시간/이동 비교 결과에서 확인한다.

예약의 `기한 알림` 탭은 예약 오픈·결제·무료 취소/변경 취소를 달력 날짜 기준으로 오늘·임박·경과 표시한다. 임박 기본값은 3일이며 당일·1일·7일로 선택할 수 있다. 완료/취소 상태에 따라 해당 경고를 종료한다. 기존 날짜·예약 조건은 보존하고 정확한 시각·시간대와 무료 취소 가능 여부는 원본 조건을 확인한다. 페이지 내 수식/확인 목록이며 푸시 알림·자동 예약/결제/취소를 설정했다고 말하지 않는다.

여행의 `필수 정보 확인`은 목적지와 날짜 또는 기간을 생성 기준으로 검사한다. 첫 사용 온보딩에서는 인원·기준 통화도 입력을 요청하지만, 사용자가 미정이라고 답하면 새 여행 생성을 멈추지 않고 홈에 남은 입력으로 표시한다. 여권/입국 확인을 완료로 표시했으나 공식 링크·확인일이 없으면 `확인 근거 점검`에서 표시한다. 이 표시는 실제 입국 요건의 정확성을 검증한 결과가 아니다.

장소·자료의 `정보 점검`은 출처·확인일 누락과 재확인 시점을 표시한다. 재확인 주기는 양수로 설정하며 빈값/0은 기본 30일이다. 직접 정한 다시 확인일이나 주기 중 먼저 도래하는 조건을 표시하고, 음수/미래 확인일은 입력 확인 대상으로 둔다. 자료의 보관 상태와 사용자 지정 재확인 필요 상태를 존중한다. 내부 작성 메모에 외부 링크를 강제하지 않고, 공식 안내/날씨 등 사실 확인 자료에 필요한 근거를 점검한다. 설정 주기 내라는 표시가 최신성·정확성을 보증하지 않으며 날씨는 기존 다음 확인일 기능을 유지한다.

새 여행에서는 새 확인 탭과 비교 결과 뷰도 해당 여행으로 필터링한다. 검사용 시각·원래 기한·기존 확인일을 임의로 채우지 않는다. 테스트는 가상 예시에서 수행하고 변경한 원래 일정·예약·자료 값은 복원한다. 자동 설치기를 사용하더라도 확인되지 않은 수식 결과를 완료로 표시하지 않는다.

## 기본 템플릿 · 현재 디폴트

화면 구성·필드 표시·사용자 질문에는 [간편 입력과 자동 결과 규칙](input-design.md)을 우선 적용한다. 아래 상세 기능은 데이터·계산 규칙이며 모든 속성을 사용자에게 한꺼번에 입력시키라는 뜻이 아니다. 기본 입력은 대체로 3~5개 열로 줄이고, 수식/롤업은 자동 결과 구역에만 표시하며 내부 계산 속성은 숨긴다. 사진·카드·색상은 유지하고 선택 입력은 필요할 때만 받는다.

### 템플릿 원본 우선 원칙

Souvenir의 디자인 원본은 저장소 코드가 아니라 **개인 데이터가 제거된 Notion 링크 배포본**이다. 페이지 구조·콜아웃·컬럼·DB 속성·뷰·수식·커버를 바꿀 때는 먼저 Notion 원본을 정리하고, 그 변경에 맞춰 이 스킬의 이동 규칙·입력 설명·검증 규칙을 수정한다. `assets/template-manifest.json`과 `notion_installer.py`는 공개 링크를 사용할 수 없는 환경을 위한 비식별 fallback 스냅샷이며, 디자인을 결정하는 권위 있는 원본으로 취급하지 않는다.

현재 작업공간의 비공개 Notion 페이지는 디폴트 디자인의 **참조 원본**이다. 다른 워크스페이스에서 원본 URL이나 ID를 몰래 복제하지 않는다. 같은 워크스페이스 안에서 접근 가능한 페이지라면 Notion 네이티브 복제를 우선해 콜아웃·컬럼·데이터베이스 뷰·관계·수식·커버를 보존한다. 다른 워크스페이스의 페이지를 현재 Notion 연결 도구가 직접 복제할 수는 없으므로, 공개·복제 가능한 템플릿 링크가 있으면 사용자가 Notion에서 `복제`를 한 뒤 Souvenir가 대상 사본을 찾아 연결한다. 대상 사본을 만들 수 없거나 링크가 없으면 [내장 기본 템플릿 청사진](template-blueprint.md)으로 재구성하고, 이를 원본과 동일한 픽셀 단위 복제라고 설명하지 않는다. 메인은 **진행도 히어로 → 여행 중 확인 존 → 계획 존** 순서로 두고, 계획 존 아래에 **계획·장소 / 이동·예약 / 예산·동행 / 준비·자료** 네 묶음을 둔다. 여행 중 확인 존은 오늘·다음 일정·숙소·예약·지갑 잔액만 먼저 보여주고, 계획 존은 입력·수정용 속성을 보여준다. 카드·연결 뷰·수식·관계를 일반 표로 바꾸지 않는다. 비공개 참조 원본에 접근할 수 없어도 내장 청사진으로 설치를 계속하고, 청사진을 적용할 수 없는 경우에만 아래 기본 섹션으로 대체하며 그 사실을 알린다.

### 계획 존과 여행 중 확인 존

- **계획 존 · 작성·수정**: 출발 전 일정·장소·교통·예약·숙소·예산·준비물을 입력하고 수정한다. 네 묶음 상세 페이지와 보조 DB는 이 존 아래에 둔다.
- **여행 중 확인 존**: 여행 중 오늘/다음 일정, 확정 예약, 체크인·체크아웃, 지도 링크, 지갑 잔액, 중요 자료를 한 열의 요약 카드로 확인한다. 기본 화면에서는 입력·내부 계산 속성을 숨기고, 필요한 경우에만 계획 존으로 이동한다.
- 여행 카드의 `여행 상태`를 `계획 중`·`여행 중`·`완료`로 관리하고, 여행 중에는 `계획 수정 잠금`을 켜 확인 존을 기본 진입점으로 둔다.
- 확인 존은 Notion 연결 DB의 표시용 화면이다. Notion 권한상 모든 연결 DB를 강제로 읽기 전용으로 만들 수 있다고 약속하지 않는다. 여행을 시작하면 확인 존 페이지를 잠그고, Souvenir는 `계획 수정`이라는 명시적 요청 없이 계획 존의 행·예약·예산을 수정하지 않는다.
- 여행 상태가 `여행 중` 또는 `완료`이면 새 정보는 먼저 확인 메모로 남긴다. 예약·일정·금액을 실제로 바꾸는 작업은 영향 요약과 사용자 반영 요청을 거친다.

### 첫 실행 · 워크스페이스 로컬 설치

Notion 연결이 확인되고 설치를 승인했으며 사용자가 별도 템플릿을 지정하지 않았다면, 새 워크스페이스에서 먼저 정확한 제목으로 `Souvenir · 설치 기록`만 찾는다. 완료 기록이 있으면 그 기록의 페이지·데이터베이스 매핑을 재사용하고, 전체 워크스페이스 검색이나 원본 페이지 재읽기를 하지 않는다. 없거나 중단된 기록이면 [내장 기본 템플릿 청사진](template-blueprint.md)의 누락 단계부터 설치한다. 설치 기록에는 대상 워크스페이스에서 새로 만든 URL·ID와 `template_source`(`native_duplicate`, `manual_duplicate`, `blueprint_rebuild`, `code_rebuild`, `minimal_fallback`)를 저장한다. 원본 대시보드 URL·비공개 ID·사용자 데이터·가상 예시 행을 대상 워크스페이스로 가져오지 않는다.

설치는 멱등적으로 수행한다. 페이지나 데이터베이스가 이미 있으면 이름만 보고 새로 중복 생성하지 말고 설치 기록의 매핑과 필요한 대상만 읽어 재사용하거나 누락 부분만 보완한다. 새 설치는 `대시보드·네 묶음 껍데기 → 관계·핵심 DB → 보조 DB·상세 뷰 → 표시·필터 검수` 순서로 진행하고 각 단계가 끝날 때 설치 기록을 갱신한다. 생성 직후 같은 객체를 다시 읽는 확인 호출과 21개 DB 전체 재검색을 반복하지 않는다. 설치 중 오류가 나면 완료로 표시하지 않고 중단 단계와 남은 매핑을 기록해 다음 호출에서 재개한다. 사용자가 템플릿 링크를 주면 같은 워크스페이스의 페이지는 네이티브 복제를 시도하고, 다른 워크스페이스의 링크는 사용자에게 `복제`를 안내한 뒤 대상 사본이 생겼을 때 연결한다. 사본을 만들 수 없을 때만 청사진 재구성으로 전환한다. Notion 쓰기 권한이 없으면 설치한 척하지 말고 필요한 구조와 권한을 안내한다.

설치·여행 생성은 같은 매핑과 상위 페이지에 대한 로컬 잠금을 잡은 뒤 진행한다. 잠금이 있으면 두 번째 프로세스는 생성하지 않고 중단한다. fallback으로 새 데이터베이스·행을 만들 때는 각 행에 `Souvenir 작업 키`를 저장하고, 생성 전에 같은 키를 조회해 기존 행을 재사용한다. 같은 키가 여러 개면 어떤 행도 임의로 선택하지 않는다. 설치 기록 아래의 `Souvenir · 작업 기록` DB에는 여행별 `반영 중` lease를 남긴다. 활성 lease가 있으면 같은 여행의 새 쓰기를 중단하고, 만료된 lease는 `확인 필요`로 기록한 뒤 재획득한다. 네이티브 Notion 플러그인처럼 로컬 잠금을 공유하지 않는 경로에서는 이 작업 기록과 여행별 단일 작성자 규칙을 먼저 확인하고, 쓰기 직전에 다시 읽어 최신 값과 충돌 여부를 확인한다. 조회 후 생성 자체는 Notion API에서 원자적이지 않으므로 여러 기기의 강한 단일 writer가 필요하면 coordinator를 사용한다.

네이티브 복제에 성공하면 원본의 블록·컬럼·커버·데이터베이스 뷰를 보존한 뒤, 대상 워크스페이스의 새 데이터베이스 관계와 설치 기록만 연결한다. 다른 워크스페이스에서 사용자가 직접 복제한 경우에는 `manual_duplicate`로 기록하고 새 사본의 실제 URL·ID를 기준으로 연결한다. 청사진 재구성에서는 원본과 다른 워크스페이스의 ID·행·필터를 가져오지 않고 구조·스타일·수식 계약을 새로 만든다. 복제/재구성 결과와 한계를 설치 완료 메시지에 한 줄로 표시한다.

### 링크 배포와 코드 재구축

공개·복제 가능한 Notion 템플릿 링크는 `SOUVENIR_TEMPLATE_URL` 같은 설정이나 README에 기본값으로 넣을 수 있다. 이 링크가 있으면 새 워크스페이스 설치의 **첫 번째 경로**로 사용하고, fallback 매니페스트로 먼저 재구축하지 않는다. 링크를 열고 복제하는 행위는 사용자의 Notion 세션에서만 수행하며, 스킬이나 스크립트가 쿠키·비밀번호·개인 토큰을 수집하거나 복제 승인을 대신하지 않는다. 원본이 비공개라면 URL만 배포하지 말고, 소유자가 별도로 공개·복제 가능한 템플릿 사본을 만들어야 한다.

링크를 사용할 수 없거나 사용자가 로컬 재구축을 선택하면 `skills/souvenir/scripts/notion_installer.py`와 `assets/template-manifest.json`을 사용한다. 매니페스트에는 원본 페이지·데이터베이스 ID와 사용자 행이 없고, 페이지 이름·색상·아이콘·입력 속성·계산 속성·뷰 의도만 들어 있다. 스크립트는 사용자가 지정한 상위 페이지와 `NOTION_TOKEN`으로 새 페이지·데이터베이스를 생성하고 대상 ID 매핑을 `.souvenir-install.json`에 저장한다. 설치 전에 반드시 `validate` 또는 `plan`을 실행하고, 토큰은 채팅에 붙여넣지 않는다.

코드 재구축은 콜아웃·페이지 계층·핵심 데이터베이스·입력 속성을 재생성하는 정책 준수형 fallback이다. Notion의 네이티브 `복제`처럼 원본의 모든 뷰 배치·관계·수식·커버를 픽셀 단위로 보존한다고 말하지 않는다. 설치 후 Souvenir가 대상 워크스페이스에서 관계·수식·상세 뷰를 이어서 구성하고, 설치 기록의 `template_source`는 `code_rebuild`로 남긴다.

템플릿 생성·복제·화면 선택·인원 변경 시 [템플릿 사용성과 인원 규칙](template-usability.md)을 읽고 적용한다. 선택은 네 묶음으로만 크게 제시하고, 목적지·기간만으로 시작하라는 요청에는 추가 필수 질문으로 만들지 않는다. 화면을 숨길 때 원래 데이터는 보존하고, 인원 변경은 계획 예산에 반영하되 실제 지출·기존 분담을 재배분하지 않는다.

같은 워크스페이스에서 새 여행을 만들 때는 설치 기록에 있는 기존 데이터베이스를 재사용한다. 템플릿의 `구분=예시` 행은 사용자 여행·예약·지출로 가져오지 않는다. 여행 요약 행을 만들고 일정·예약·준비물·숙소·지갑을 해당 여행에 연결한다. 지출은 여행 지갑에 연결한다. 복제한 페이지의 숙소·지갑·오늘·다음 일정·예약·사용 내역 뷰를 새 여행과 지갑에 맞게 필터링하고, 빠른 링크도 새 행으로 바꾼다. 원본 페이지의 뷰 필터는 바꾸지 않는다. 다른 워크스페이스에서는 먼저 내장 청사진을 설치해 그 워크스페이스의 데이터베이스·관계·뷰를 만들고, 설치 기록의 매핑만 사용한다.

대시보드의 계산 기준:

- D-Day는 `여행 기간`의 시작·종료 날짜를 기준으로 계산한다. 별도 `출발일`·`종료일`을 다시 입력시키지 않는다. 기간만 알면 `기간(일)`에 기록하고 실제 날짜는 비워 둔다. 날짜가 있으면 숙박 일수는 종료−시작, 여행 일수는 그 값+1이다.
- 숙소는 `숙소 사진`, `체크인`, `체크아웃`, IANA 형식의 `현지 시간대`를 사용한다. 체크인·아웃 안내 수식은 해당 시간대로 날짜·시간을 표시한다. 확정된 예약번호·주소·지도·사용자 메모를 보존한다.
- 준비한 예산은 `여행 지갑`의 `준비 금액`에 넣고, 실제로 제공된 경우에만 `금액 입력 완료`를 체크한다. 미정인 예산을 0원으로 확정하지 않는다. 통화가 다르면 지갑을 나누고, 사용 금액은 선택한 지갑 통화로 입력한다.
- `사용한 내역`은 한 거래당 한 행이며 기본적으로 실제 사용 금액을 기록하는 장부다. `지갑` 하나와 양수 `금액`이 있으면 숨긴 `상태`가 비어 있어도 바로 차감한다. 비어 있는 거래 유형은 지출로 계산하고, `환불`을 선택하면 복원한다. 명시적인 `예정`은 제외하며 기존 상태·거래 유형·금액을 덮어쓰지 않는다. 지갑이 없거나 여러 개이거나 금액이 0 이하이면 반영하지 않는다. `실제 반영액`을 지갑의 `누적 사용액`으로 합산하며 `남은 금액=준비 금액−누적 사용액`이다. 스킬이 예정 비용을 저장할 때는 반드시 `상태=예정`을 지정한다. 예상 비용과 실제 지출을 중복 차감하지 않는다.
- 금액 입력은 연결된 지갑의 통화 단위 숫자다. `자동 · 통화 금액`은 기존 `사용 통화` 롤업을 읽어 엔·원·달러·유로 기호와 금액을 표시하는 수식이다. 지갑 통화를 바꾸면 표시가 따라 바뀌며, 숫자 자체를 환율로 환산하지 않는다. 다른 지갑의 통화와 섞이지 않게 관계 필터를 유지한다. 숫자 속성의 공통 통화 서식을 지갑 하나에 맞춰 바꾸지 않는다. 기본 입력 다섯 열 옆에 이 읽기 전용 결과만 추가한다.
- 준비 현황은 연결된 준비물의 완료 수, 예약 현황은 취소를 제외한 예약의 확정 수로 계산한다. 오늘·다음 일정 뷰는 상대 날짜 필터를 사용하고 취소 일정을 제외한다. 수식·롤업 속성에 계산값을 직접 써 넣지 않는다.

`여행 개요와 취향`은 기존 여행 요약 행의 속성을 편집하는 네 개의 탭(방향·속도·선호·주의사항)으로 제공한다. 여행 테마·음식·이동·숙소·활동 시간대는 다중 선택, 가장 중요한 기준·여행 템포·휴식은 단일 선택, 하루 주요 일정 수는 숫자로 저장한다. 꼭 하고 싶은 일·방문지와 알레르기·피할 활동·동행자 요청만 짧은 텍스트로 기록한다. 목적지·기간·동행자와 같은 여행 행을 사용하며 새 여행 페이지에서는 이 연결 뷰도 해당 여행으로 필터링한다. 자유문장 목록을 따로 두어 속성과 중복 관리하지 않는다. 알레르기·못 먹는 음식·피하고 싶은 활동은 일정 작성의 제약으로 취급한다. 빈값은 미정이며 `없음`으로 추정하지 않는다. 취향을 채우기 위해 새 여행 작성을 멈추지 않고, 예시 여행의 선택값이나 접힌 안내는 사용자 취향으로 사용하지 않는다.

`날짜별 일정`은 기존 일정 데이터베이스의 일별 표·일차별 카드·달력·시간표·확인할 일정 뷰를 사용한다. 한 활동당 한 행이며 `여행`, `일차`, 하루 안의 `순서`를 기록한다. 날짜가 미정이면 일차와 순서만 작성하고, 시각을 알면 `날짜`의 시작·종료 범위로 저장한다. 시간대가 있으면 IANA 형식의 `현지 시간대`도 기록한다. `시간 표시`·`소요 시간`·`날짜 기준 일차`·`일정 확인`은 수식이다. 날짜나 일차 변경 시 서로 맞는지 확인하고, 여행 기간이 8일을 넘으면 기존 옵션을 보존하며 필요한 일차 옵션을 추가한다. 취소·건너뜀은 기본 뷰에서 제외하되 원래 행은 보존한다. 이 검사로 다른 행과의 시간 충돌이나 실제 이동 가능성까지 검증했다고 말하지 않는다.

`장소 보관함`은 기존 장소 데이터베이스를 재사용한다. 지역·세부 지역·종류 태그, 예산 메모·통화·결제 수단·지도·공식 링크·TIP·개인 별점·방문 체크를 저장하고, 전체·맛집/카페·관광·쇼핑/편의점·사진·일정 연결 뷰를 제공한다. 기존 숫자 `평점`은 보존하고 새 개인 별점은 `개인 평점`에 저장한다. 일정의 `장소 카드` 관계로 선택하면 장소 쪽 `방문 일정`이 연결된다. 확정된 시각·동선은 일정이, 영업시간·주소·가격·정보 근거는 장소가 관리하며 중복 기록하지 않는다. `방문 계획`은 실제 방문 체크를 우선하고, 취소·건너뜀을 제외한 일정 연결을 집계한다. 계획만 연결했다고 방문 완료로 체크하지 않는다. 독립적으로 쓰는 일정에는 기존 `장소` 텍스트도 사용할 수 있다. 가상 예시는 실제 일정·추천·방문 기록으로 가져오지 않는다.

`쇼핑`은 계획·장소 묶음의 선택 블록이다. 여행 인원 수만큼 개인 목록을 만들고 품목·구매 장소·사진·태그·상태·예상 금액·결제 수단·메모를 입력한다. 공용 목록은 사용자의 확인이 있을 때만 만든다. 구매 장소가 장소 보관함에 있으면 장소 카드와 연결하고, `구매 완료` 항목의 실제 결제만 `사용한 내역`과 여행 지갑에 연결한다. 예정 금액은 잔액에서 차감하지 않는다. 쇼핑을 끄면 행은 보존하되 메뉴·진행도 대상에서 제외한다.

`항공·장거리 교통`은 편도 한 구간당 한 행이다. 왕복·환승은 나누고 여행·연결 일정에 연결한다. 교통수단·예약 상태, 운영사·편명·공항/역·터미널, 예약번호·티켓 파일, 좌석·수하물·기내식, 요금·통화·금액 범위, 변경·취소 조건과 기한을 관리한다. **항공권 예산과 요금은 항상 KRW(원화)로 기록하고, `통화=KRW`는 고정 표시한다.** 원문이 엔화 등 다른 통화이면 확인된 환율 근거로 환산한 금액만 입력하며, 근거가 없으면 `확인 필요`로 둔다. 여정 카드·구간/시간·예약/탑승·환승/공항 이동·요금/변경 연결 뷰를 사용한다. 출발·도착 날짜 속성은 각각 현지 시간대로 시간까지 저장하고 표시용 `출발 시간대`·`도착 시간대`도 선택한다. 목록 밖의 지역은 `직접 입력`과 해당 IANA 시간대를 사용한다. 시간대 선택만으로 잘못 입력한 날짜의 시각을 보정했다고 말하지 않는다. `이동 시간`은 실제 경과 분을 계산하며 시차·날짜변경선을 반영한다. `이전 구간`은 직전 편 하나만 연결하고 환승 간격은 이전 도착→다음 출발로 계산한다. 간격만으로 입국·수하물 재수속·터미널 이동이나 최소 환승시간 충족을 보증하지 않는다. 체크인·탑승 마감은 확인된 기준만 입력하고 출발지 시간대로 표시한다. 취소·변경 기한은 예약 조건에 명시된 시간대로 저장한다.

`현지 이동`은 공항/역↔숙소·시내·도시 간·심야 귀가를 구간별로 기록한다. 출발지·도착지·이동 수단·노선·승하차/환승 안내·지도·예상 소요(분)·요금/통화/금액 범위를 관리하고 시간·요금의 확인 상태를 구분한다. 유효한 이동 일시 범위가 있으면 그 경과 시간을 우선 표시하고, 날짜가 없으면 예상 소요 시간을 표시한다. 막차는 날짜·시간·현지 시간대를 함께 저장하고 심야 대안과 대안 지도도 남긴다. `연결 장거리 구간`과 `연결 일정`으로 항공편·열차 및 일별 일정에 연결한다. 날짜·막차·운행 여부·요금·이동 시간은 추정하여 확정하지 않는다.

`교통패스·서비스·렌터카`는 이동 구간과 별도로 비교·선택·구매/예약 상태를 관리하고 현지 이동의 `교통 준비`로 연결한다. 교통카드·패스는 적용/제외 노선·유효기간·가격·수령 방법, 택시·호출은 서비스·지역·앱 링크, 렌터카는 인수/반납·면허/국제운전면허·운전자 조건·보험/보증금·차량/연료·주차/통행료·주유/충전/반납 조건을 속성으로 작성한다. 서류가 미정이면 준비 완료로 처리하지 않고 `해당 없음`은 확인한 경우만 선택한다. 서류 체크 완료는 운전 자격이나 실제 대여 가능 여부의 검증이 아니다. 교통의 예상 요금·상품 가격은 지갑에서 자동 차감하지 않고 실제 결제를 `사용한 내역`에 한 번 기록한다. 항공·장거리 교통의 공통 예약은 아래 예약 관리에 한 건만 등록하여 상세 구간과 연결한다.

숙소 상세 관리는 기존 `숙소 정보` DB를 재사용한다. 숙소 카드·후보 비교·확정 숙소·객실/체크인·비용/취소 뷰를 제공한다. 사진·주소·지도·연락처, 객실 유형·숙박 인원·객실 수·침대 구성, 시설·조식 조건·늦은 체크인·출입 방법, 접근성과 주변 시설을 속성으로 관리한다. 기존 `객실·인원` 메모는 보존한다. **1박 비용과 숙박 총액은 항상 KRW(원화)로 기록하고, `통화=KRW`는 고정 표시한다.** 원문 금액이 다른 통화라면 확인된 환율 근거가 있을 때만 KRW로 환산하며, 세금 포함 여부와 환산 근거가 없으면 `확인 필요`로 둔다. `숙박 총액`은 전체 숙박 기준이며 확인한 뒤 `총액 확인`을 체크한다. 세금 포함/별도, 보증금, 현장 결제액을 구분하고 세금·보증금을 총액에 자동으로 더하거나 실제 지출로 추정하지 않는다. 시설 태그는 포함 요금이나 이용 가능 시간을 보증하지 않으므로 조건을 확인한다.

`예약 관리`는 기존 예약·체크리스트 DB를 확장한 공통 예약 창구다. 한 예약당 한 행으로 항공·숙소·식당·체험·티켓 등을 종류로 구분하고 숙소·교통·일정·장소 관계를 연결한다. 예약 현황 보드·이용 달력·결제/잔금·마감 관리·후속 작업·바우처/연결 뷰를 사용한다. 이용 일시·IANA 현지 시간대·인원·예약자·예약번호와 확인서/QR/링크를 기록한다. 오픈일·결제 기한·무료 취소·변경/취소 마감·후속 기한은 구별하고 각 날짜 속성에 예약처 기준 시간대를 설정한다. 기존 `기한`과 `취소·환불` 상태는 보존하며 후자를 환불 완료로 추정하지 않는다. 취소·환불 대기·환불 완료는 진행/확정 집계에서 제외한다.

예약의 이용 날짜만 알면 날짜만 입력하고 `이용 시각 확인`은 체크하지 않는다. 시각을 확인했을 때만 시간·시간대와 함께 체크하여 자정을 임의로 확정하지 않는다. 예약의 `금액`은 총액이고 `결제액`은 해당 예약 통화로 실제 결제한 누계다. `금액 확인`과 `결제액 확인`을 모두 체크한 경우에만 잔금을 표시한다. 미정 금액을 0원으로 확정하지 않고, 확인된 미결제 0원만 입력한다. 총액보다 큰 결제액이나 음수는 입력 확인 대상으로 표시한다. 취소·환불 예약은 일반 잔금 대신 내역 확인을 표시하고 환불액을 따로 관리한다. 예약 입력만으로 지갑을 차감하지 않는다. 담당자는 PEOPLE 속성에서 고르고 워크스페이스 외 동행자는 담당자 메모에 기록한다. 후속 작업을 완료하면 완료 체크로 작업 뷰에서 제외한다.

숙소의 `예약 관리`와 교통의 `통합 예약`이 연결되면 `예약 현황`은 연결 예약의 상태를 우선 표시한다. 연결하지 않은 기존 행은 원래 예약 상태를 표시한다. 연결 후 상태·결제·후속 작업은 공통 예약에서 수정하고, 기존 예약번호·티켓·메모를 자동 삭제하거나 덮어쓰지 않는다. 같은 예약을 두 번 생성하지 않는다. 숙박 일정·운항 정보는 원래 상세 카드가 관리하며, 일정 변경 시 예약 관리의 이용 일시와 연결 일정에 미치는 영향도 함께 검토한다. 관계만 연결했다고 날짜·예약번호·결제액까지 자동 동기화된다고 설명하지 않는다.

새 여행에서 숙소·예약·세 교통 DB를 재사용하고 모든 연결 뷰를 새 여행으로 필터링한다. 접힌 예시와 `구분=예시` 행은 실제 여행으로 가져오지 않는다. 사용자 맞춤 구성 선택지는 향후 큰 묶음으로 제공하되 템플릿 구성 작업 도중 임의의 선택 메뉴를 추가하지 않는다. 현재는 구성 요소를 독립된 섹션으로 만들고, 전체 구성이 끝난 뒤 메인 요약·분야별 하위 페이지로 배치한다.

### 항공 화면 전환 규칙

원본 DB 이름이 `항공·장거리 교통`이어도 새 계획 마법사와 fallback 매니페스트의 사용자 화면은 `항공`으로 표시한다. 열차·버스·선박 후보를 별도 파트로 추가하지 않고, 기존 데이터와 속성은 삭제하지 않는다. 예약 전에는 선호 시간대·예산·후보 상태를 사용하고, 예약 후에는 편명·공항·예약번호·확인 링크를 채운다.

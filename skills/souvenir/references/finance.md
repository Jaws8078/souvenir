## 예산·지출과 동행자 정산

기존 `여행 지갑`, `예산`, `사용한 내역` DB를 재사용한다. 준비 금액은 통화별 지갑, 카테고리 한도와 예상/확정액은 예산, 실제 결제/환불은 거래 한 건당 한 행으로 관리한다. 예산의 `금액`은 카테고리 한도이며 `범위=1인`이면 `적용 인원`을 곱한다. 실제 거래를 같은 지갑의 `카테고리 예산` 하나에 연결한다. 카테고리 한도를 준비 금액에 더하거나 예상/확정액을 실제 지출로 중복 차감하지 않는다. 기존 `사용 금액`·`잔액` 등 이전 속성은 보존하되 새 연결 뷰에서는 검증한 `실제 지출`·`예산 현황`을 사용한다. 예비비는 준비 금액 안의 유보액이며 지출이 아니다.

거래 금액은 지갑 통화의 실제 결제 건 전체 금액이다. 여러 명이 나눠 결제했으면 결제 건별로 나누고 전체 청구액을 반복 입력하지 않는다. 결제자·수단·일자, 선결제/현장/잔금 단계, 관련 예약·영수증을 기록한다. 완료한 환불은 별도 양수 거래로 원거래에 연결하며, 실제 반환액과 별도로 지불한 수수료를 중복 기록하지 않는다. 예정 거래는 실제 잔액과 정산에서 제외한다.

여행의 `기준 통화`와 `정산 단위`를 먼저 정한다. 기본 템플릿은 KRW·1원 단위이며 금액은 미정으로 둔다. 각 거래의 `환산 통화`·`계산 단위`는 이 설정에 맞춘다. 적용 환율은 원래 통화 **1단위당** 기준 통화 금액이다. 100엔 고시 값은 100으로 나눠 입력하고 같은 통화는 1이다. 실제로 확인한 환율·적용일·근거를 남기고 `환율 확인`을 켠다. 환산액은 단위에 맞춰 반올림한다. 환율을 자동 조회하거나 미확인 값을 최신 환율로 확정하지 않는다. 지갑 원래 통화 잔액은 환산과 별개다. 카테고리 지출 차트는 설정한 기준 통화의 환산 완료 지출을 보여주며 환불 전 금액이다. 기준 통화 변경·새 여행 생성 시 차트의 환산 통화 필터도 바꾼다. 여행 요약 뷰는 제목 대신 `여행 키`를 새 여행 ID로 필터링한다.

`동행자`는 여행당 한 사람 한 행으로 역할·요청·준비/예약 담당을 관리한다. 기존 워크스페이스 PEOPLE 담당자는 유지하고 여행자 담당 관계도 사용할 수 있다. `공동 결정`에는 선택지·의견·결정 사항·담당자·기한을 기록한다. 예시의 역할·합의를 실제 사용자에게 적용하지 않는다.

`지출별 분담`은 거래당 부담자 한 명에 한 행이다. 같은 사람을 중복 입력하지 않는다. 정산할 실제 거래에만 `정산 포함`을 켜고 공용/개인, 결제·환불자 한 명, 분담 방식을 정한다. 개인 비용은 대상 한 명으로 한다. 분담의 `계산 기준액`은 해당 거래의 **부호 있는 기준 통화 실제액**이다. 완료된 환불은 음수다. 계산 인원·방식·통화·단위와 기준액 확인을 함께 기록한다. 균등은 인원으로 나누고, 비율은 합계 100%, 개별 금액은 기준 통화의 양수 부담액을 입력해 확인한다. 개별 환불액의 부호는 기준액을 따른다. 단위 반올림 차이는 지정한 한 행의 `반올림 보정`에 남긴다. `원거래 대조`·`분담 점검`을 확인하고 원거래가 바뀌면 분담 기준을 갱신한다. 자동으로 모든 중복·다른 여행 연결까지 검증했다고 말하지 않는다.

**사람별 정산은 검토한 합계의 스냅샷이다.** 복잡한 연결 집계가 테스트에서 0으로 조회되어 자동 집계를 확정값으로 사용하지 않는다. 미검증 자동 집계 속성은 숨긴 채 보존했다. 원거래나 송금만 바꿔도 사람별 합계가 자동 갱신된다고 설명하지 않는다.

사용자가 `정산 다시 검토해줘`라고 하면:

1. 해당 여행·통화의 실제 거래, 분담, 송금 기록을 읽는다. 관련 동행자의 `정산 기준 확인`을 먼저 끈다. 다른 여행·통화가 섞였거나 환율·담당자·분담 기준이 불명확하면 확인할 항목을 표시하고 확인 체크를 켜지 않는다.
2. 분담 기준을 원거래와 대조한다. 중복 부담자, 비율 100%, 개별/균등 분담 합계와 반올림을 확인한다. 미완료 거래·예정 송금은 제외한다. 환불은 실제 수령자 결제액과 해당 사람들의 부담액에서 차감한다.
3. 사람별 `확인 결제액`·`확인 부담액`·`확인 송금액`·`확인 수령액`을 기준 통화로 합산해 기록한다. `확인 통화`·`정산 검토일`을 남기고 검증한 경우에만 기준 확인을 켠다. 수식·롤업 결과 속성에 계산값을 직접 쓰지 않는다.
4. `정산 차액=결제액−부담액+송금액−수령액`으로 양수는 받을 돈, 음수는 보낼 돈, 검토 후 0은 정산 완료다. 받을 돈과 보낼 돈 총합이 일치하는지 확인한다. 이후 원거래·환율·분담·송금 변경을 반영할 때는 관련 기준 확인을 끄고 다시 검토한다.

`정산 송금`은 보낸/받은 사람·기준 통화 금액·상태·날짜·증빙을 기록한다. 기록만으로 실제 송금을 실행하거나 여행 지갑을 차감하지 않는다. 송금 완료 기록 후 사람별 검토 합계를 갱신한다. 계산 예시는 실제 환율·결제·송금·사용자 합의와 구분한다. 새 여행에서는 예산·거래·동행자·분담·송금·공동 결정 뷰도 해당 여행으로 필터링하고 예시는 가져오지 않는다. 자동 설치기에서는 계산 수식을 확정값으로 쓰지 않고, 대상 워크스페이스에서 연결·검수 후 활성화한다.

# Souvenir 여행 도우미

연결된 Notion 플러그인으로 템플릿과 여행 페이지를 읽고 저장한다. 다른 워크스페이스에서는 공개 템플릿의 사용자 승인 복제를 우선하고, 링크를 쓸 수 없을 때만 저장소에 포함된 코드 재구축 매니페스트를 사용한다.

## 작업 선택

요청에서 작업이 명확하면 바로 시작한다. `$souvenir`만 호출하거나 작업이 모호하면 다음 메뉴를 보여준다. 번호나 작업 이름으로 답할 수 있다고 안내한다.

1. 여행 플래너 만들기
2. 새 여행 계획
3. 기존 일정 수정

이미 알려준 정보는 다시 묻지 않는다. 사용자가 저장 위치를 지정하면 해당 위치를 사용한다. 별도 위치 없이 저장을 요청하면 비공개 초안을 사용한다. Notion 연결이나 쓰기 권한이 없으면 작성한 초안을 채팅에 보여주고 저장에 필요한 조건을 알려준다.

Notion 도구를 사용할 때는 해당 도구의 Markdown 규격을 먼저 읽는다. 비공개 초안은 페이지 생성의 `creation_mode: "draft"`로 저장하며 부모 위치를 함께 지정하지 않는다. 페이지 제목은 속성에 넣고 본문에는 중복하지 않는다. 저장 응답의 오류·경고를 확인한 뒤 성공한 페이지 링크를 안내한다.

새 워크스페이스에서 `$souvenir`를 처음 실행하면 작업 메뉴보다 **연결 확인 → 템플릿 설치 확인**을 먼저 처리한다. 연결 확인은 읽기 전용으로 한 번만 수행하며, Notion이 연결되지 않았으면 채팅에 비밀번호를 요구하지 말고 사용자가 Notion 연결을 완료한 뒤 다시 이어갈 수 있게 멈춘다. 연결이 확인된 뒤에만 `Souvenir · 설치 기록`을 찾고, 설치 기록이 없을 때 다음과 같이 한 번만 묻는다.

> 이 워크스페이스에 Souvenir 기본 템플릿을 설치할까요? 원본과 같은 화면을 원하면 공개·복제 가능한 Notion 템플릿 링크를 함께 주세요.

사용자가 설치를 거절하면 템플릿을 만들지 않고 요청한 작업만 최소 구조로 진행한다. 설치를 승인하면 설치 기록을 먼저 `진행 중`으로 저장하고, 설치가 끝난 뒤 1~3번 작업을 이어간다. 이미 `완료` 기록이 있으면 재확인만 하고 설치 질문과 전체 검색을 반복하지 않는다.

## 기본 템플릿 · 현재 디폴트

화면 구성·필드 표시·사용자 질문에는 [간편 입력과 자동 결과 규칙](references/input-design.md)을 우선 적용한다. 아래 상세 기능은 데이터·계산 규칙이며 모든 속성을 사용자에게 한꺼번에 입력시키라는 뜻이 아니다. 기본 입력은 대체로 3~5개 열로 줄이고, 수식/롤업은 자동 결과 구역에만 표시하며 내부 계산 속성은 숨긴다. 사진·카드·색상은 유지하고 선택 입력은 필요할 때만 받는다.

현재 작업공간에서 확인한 [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19?pvs=204)는 디폴트 디자인의 **참조 원본**이다. 다른 워크스페이스에서 이 URL이나 이 워크스페이스의 ID를 몰래 복제하지 않는다. 같은 워크스페이스 안에서 접근 가능한 페이지라면 Notion 네이티브 복제를 우선해 콜아웃·컬럼·데이터베이스 뷰·관계·수식·커버를 보존한다. 다른 워크스페이스의 페이지를 현재 Notion 연결 도구가 직접 복제할 수는 없으므로, 공개·복제 가능한 템플릿 링크가 있으면 사용자가 Notion에서 `복제`를 한 뒤 Souvenir가 대상 사본을 찾아 연결한다. 대상 사본을 만들 수 없거나 링크가 없으면 [내장 기본 템플릿 청사진](references/template-blueprint.md)으로 재구성하고, 이를 원본과 동일한 픽셀 단위 복제라고 설명하지 않는다. 메인은 **진행도 히어로 → 여행 중 확인 존 → 계획 존** 순서로 두고, 계획 존 아래에 **계획·장소 / 이동·예약 / 예산·동행 / 준비·자료** 네 묶음을 둔다. 여행 중 확인 존은 오늘·다음 일정·숙소·예약·지갑 잔액만 먼저 보여주고, 계획 존은 입력·수정용 속성을 보여준다. 카드·연결 뷰·수식·관계를 일반 표로 바꾸지 않는다. 사용자의 [여행 계획 도우미(제작 중)](https://app.notion.com/p/3cc1036c4e4280508eb9c50b9532885c?pvs=204)을 참고한 것이다. 참조 원본에 접근할 수 없어도 내장 청사진으로 설치를 계속하고, 청사진을 적용할 수 없는 경우에만 아래 기본 섹션으로 대체하며 그 사실을 알린다.

### 계획 존과 여행 중 확인 존

- **계획 존 · 작성·수정**: 출발 전 일정·장소·교통·예약·숙소·예산·준비물을 입력하고 수정한다. 네 묶음 상세 페이지와 보조 DB는 이 존 아래에 둔다.
- **여행 중 확인 존**: 여행 중 오늘/다음 일정, 확정 예약, 체크인·체크아웃, 지도 링크, 지갑 잔액, 중요 자료를 한 열의 요약 카드로 확인한다. 기본 화면에서는 입력·내부 계산 속성을 숨기고, 필요한 경우에만 계획 존으로 이동한다.
- 여행 카드의 `여행 상태`를 `계획 중`·`여행 중`·`완료`로 관리하고, 여행 중에는 `계획 수정 잠금`을 켜 확인 존을 기본 진입점으로 둔다.
- 확인 존은 Notion 연결 DB의 표시용 화면이다. Notion 권한상 모든 연결 DB를 강제로 읽기 전용으로 만들 수 있다고 약속하지 않는다. 여행을 시작하면 확인 존 페이지를 잠그고, Souvenir는 `계획 수정`이라는 명시적 요청 없이 계획 존의 행·예약·예산을 수정하지 않는다.
- 여행 상태가 `여행 중` 또는 `완료`이면 새 정보는 먼저 확인 메모로 남긴다. 예약·일정·금액을 실제로 바꾸는 작업은 영향 요약과 사용자 반영 요청을 거친다.

### 첫 실행 · 워크스페이스 로컬 설치

Notion 연결이 확인되고 설치를 승인했으며 사용자가 별도 템플릿을 지정하지 않았다면, 새 워크스페이스에서 먼저 정확한 제목으로 `Souvenir · 설치 기록`만 찾는다. 완료 기록이 있으면 그 기록의 페이지·데이터베이스 매핑을 재사용하고, 전체 워크스페이스 검색이나 원본 페이지 재읽기를 하지 않는다. 없거나 중단된 기록이면 [내장 기본 템플릿 청사진](references/template-blueprint.md)의 누락 단계부터 설치한다. 설치 기록에는 대상 워크스페이스에서 새로 만든 URL·ID와 `template_source`(`native_duplicate`, `manual_duplicate`, `blueprint_rebuild`, `code_rebuild`, `minimal_fallback`)를 저장한다. 원본 대시보드 URL·비공개 ID·사용자 데이터·가상 예시 행을 대상 워크스페이스로 가져오지 않는다.

설치는 멱등적으로 수행한다. 페이지나 데이터베이스가 이미 있으면 이름만 보고 새로 중복 생성하지 말고 설치 기록의 매핑과 필요한 대상만 읽어 재사용하거나 누락 부분만 보완한다. 새 설치는 `대시보드·네 묶음 껍데기 → 관계·핵심 DB → 보조 DB·상세 뷰 → 표시·필터 검수` 순서로 진행하고 각 단계가 끝날 때 설치 기록을 갱신한다. 생성 직후 같은 객체를 다시 읽는 확인 호출과 20개 DB 전체 재검색을 반복하지 않는다. 설치 중 오류가 나면 완료로 표시하지 않고 중단 단계와 남은 매핑을 기록해 다음 호출에서 재개한다. 사용자가 템플릿 링크를 주면 같은 워크스페이스의 페이지는 네이티브 복제를 시도하고, 다른 워크스페이스의 링크는 사용자에게 `복제`를 안내한 뒤 대상 사본이 생겼을 때 연결한다. 사본을 만들 수 없을 때만 청사진 재구성으로 전환한다. Notion 쓰기 권한이 없으면 설치한 척하지 말고 필요한 구조와 권한을 안내한다.

네이티브 복제에 성공하면 원본의 블록·컬럼·커버·데이터베이스 뷰를 보존한 뒤, 대상 워크스페이스의 새 데이터베이스 관계와 설치 기록만 연결한다. 다른 워크스페이스에서 사용자가 직접 복제한 경우에는 `manual_duplicate`로 기록하고 새 사본의 실제 URL·ID를 기준으로 연결한다. 청사진 재구성에서는 원본과 다른 워크스페이스의 ID·행·필터를 가져오지 않고 구조·스타일·수식 계약을 새로 만든다. 복제/재구성 결과와 한계를 설치 완료 메시지에 한 줄로 표시한다.

### 링크 배포와 코드 재구축

공개·복제 가능한 Notion 템플릿 링크는 `SOUVENIR_TEMPLATE_URL` 같은 설정이나 README에 기본값으로 넣을 수 있다. 링크를 열고 복제하는 행위는 사용자의 Notion 세션에서만 수행하며, 스킬이나 스크립트가 쿠키·비밀번호·개인 토큰을 수집하거나 복제 승인을 대신하지 않는다. 원본이 비공개라면 URL만 배포하지 말고, 소유자가 별도로 공개·복제 가능한 템플릿 사본을 만들어야 한다.

링크를 사용할 수 없거나 사용자가 로컬 재구축을 선택하면 `skills/souvenir/scripts/notion_installer.py`와 `assets/template-manifest.json`을 사용한다. 매니페스트에는 원본 페이지·데이터베이스 ID와 사용자 행이 없고, 페이지 이름·색상·아이콘·입력 속성·계산 속성·뷰 의도만 들어 있다. 스크립트는 사용자가 지정한 상위 페이지와 `NOTION_TOKEN`으로 새 페이지·데이터베이스를 생성하고 대상 ID 매핑을 `.souvenir-install.json`에 저장한다. 설치 전에 반드시 `validate` 또는 `plan`을 실행하고, 토큰은 채팅에 붙여넣지 않는다.

코드 재구축은 콜아웃·페이지 계층·핵심 데이터베이스·입력 속성을 재생성하는 정책 준수형 fallback이다. Notion의 네이티브 `복제`처럼 원본의 모든 뷰 배치·관계·수식·커버를 픽셀 단위로 보존한다고 말하지 않는다. 설치 후 Souvenir가 대상 워크스페이스에서 관계·수식·상세 뷰를 이어서 구성하고, 설치 기록의 `template_source`는 `code_rebuild`로 남긴다.

템플릿 생성·복제·화면 선택·인원 변경 시 [템플릿 사용성과 인원 규칙](references/template-usability.md)을 읽고 적용한다. 선택은 네 묶음으로만 크게 제시하고, 목적지·기간만으로 시작하라는 요청에는 추가 필수 질문으로 만들지 않는다. 화면을 숨길 때 원래 데이터는 보존하고, 인원 변경은 계획 예산에 반영하되 실제 지출·기존 분담을 재배분하지 않는다.

같은 워크스페이스에서 새 여행을 만들 때는 설치 기록에 있는 기존 데이터베이스를 재사용한다. 템플릿의 `구분=예시` 행은 사용자 여행·예약·지출로 가져오지 않는다. 여행 요약 행을 만들고 일정·예약·준비물·숙소·지갑을 해당 여행에 연결한다. 지출은 여행 지갑에 연결한다. 복제한 페이지의 숙소·지갑·오늘·다음 일정·예약·사용 내역 뷰를 새 여행과 지갑에 맞게 필터링하고, 빠른 링크도 새 행으로 바꾼다. 원본 페이지의 뷰 필터는 바꾸지 않는다. 다른 워크스페이스에서는 먼저 내장 청사진을 설치해 그 워크스페이스의 데이터베이스·관계·뷰를 만들고, 설치 기록의 매핑만 사용한다.

대시보드의 계산 기준:

- D-Day는 `여행 기간`의 시작·종료 날짜를 기준으로 계산한다. 별도 `출발일`·`종료일`을 다시 입력시키지 않는다. 기간만 알면 `기간(일)`에 기록하고 실제 날짜는 비워 둔다. 날짜가 있으면 숙박 일수는 종료−시작, 여행 일수는 그 값+1이다.
- 숙소는 `숙소 사진`, `체크인`, `체크아웃`, IANA 형식의 `현지 시간대`를 사용한다. 체크인·아웃 안내 수식은 해당 시간대로 날짜·시간을 표시한다. 확정된 예약번호·주소·지도·사용자 메모를 보존한다.
- 준비한 예산은 `여행 지갑`의 `준비 금액`에 넣고, 실제로 제공된 경우에만 `금액 입력 완료`를 체크한다. 미정인 예산을 0원으로 확정하지 않는다. 통화가 다르면 지갑을 나누고, 사용 금액은 선택한 지갑 통화로 입력한다.
- `사용한 내역`은 한 거래당 한 행이며 기본적으로 실제 사용 금액을 기록하는 장부다. `지갑` 하나와 양수 `금액`이 있으면 숨긴 `상태`가 비어 있어도 바로 차감한다. 비어 있는 거래 유형은 지출로 계산하고, `환불`을 선택하면 복원한다. 명시적인 `예정`은 제외하며 기존 상태·거래 유형·금액을 덮어쓰지 않는다. 지갑이 없거나 여러 개이거나 금액이 0 이하이면 반영하지 않는다. `실제 반영액`을 지갑의 `누적 사용액`으로 합산하며 `남은 금액=준비 금액−누적 사용액`이다. 스킬이 예정 비용을 저장할 때는 반드시 `상태=예정`을 지정한다. 예상 비용과 실제 지출을 중복 차감하지 않는다.
- 금액 입력은 연결된 지갑의 통화 단위 숫자다. `자동 · 통화 금액`은 기존 `사용 통화` 롤업을 읽어 엔·원·달러·유로 기호와 금액을 표시하는 수식이다. 지갑 통화를 바꾸면 표시가 따라 바뀌며, 숫자 자체를 환율로 환산하지 않는다. 다른 지갑의 통화와 섞이지 않게 관계 필터를 유지한다. 숫자 속성의 공통 통화 서식을 지갑 하나에 맞춰 바꾸지 않는다. 기본 입력 다섯 열 옆에 이 읽기 전용 결과만 추가한다.
- 준비 현황은 연결된 준비물의 완료 수, 예약 현황은 취소를 제외한 예약의 확정 수로 계산한다. 오늘·다음 일정 뷰는 상대 날짜 필터를 사용하고 취소 일정을 제외한다. 수식·롤업 속성에 계산값을 직접 써 넣지 않는다.

`여행 개요와 취향`은 기존 여행 요약 행의 속성을 편집하는 네 개의 탭(방향·속도·선호·주의사항)으로 제공한다. 여행 테마·음식·이동·숙소·활동 시간대는 다중 선택, 가장 중요한 기준·여행 템포·휴식은 단일 선택, 하루 주요 일정 수는 숫자로 저장한다. 꼭 하고 싶은 일·방문지와 알레르기·피할 활동·동행자 요청만 짧은 텍스트로 기록한다. 목적지·기간·동행자와 같은 여행 행을 사용하며 새 여행 페이지에서는 이 연결 뷰도 해당 여행으로 필터링한다. 자유문장 목록을 따로 두어 속성과 중복 관리하지 않는다. 알레르기·못 먹는 음식·피하고 싶은 활동은 일정 작성의 제약으로 취급한다. 빈값은 미정이며 `없음`으로 추정하지 않는다. 취향을 채우기 위해 새 여행 작성을 멈추지 않고, 예시 여행의 선택값이나 접힌 안내는 사용자 취향으로 사용하지 않는다.

`날짜별 일정`은 기존 일정 데이터베이스의 일별 표·일차별 카드·달력·시간표·확인할 일정 뷰를 사용한다. 한 활동당 한 행이며 `여행`, `일차`, 하루 안의 `순서`를 기록한다. 날짜가 미정이면 일차와 순서만 작성하고, 시각을 알면 `날짜`의 시작·종료 범위로 저장한다. 시간대가 있으면 IANA 형식의 `현지 시간대`도 기록한다. `시간 표시`·`소요 시간`·`날짜 기준 일차`·`일정 확인`은 수식이다. 날짜나 일차 변경 시 서로 맞는지 확인하고, 여행 기간이 8일을 넘으면 기존 옵션을 보존하며 필요한 일차 옵션을 추가한다. 취소·건너뜀은 기본 뷰에서 제외하되 원래 행은 보존한다. 이 검사로 다른 행과의 시간 충돌이나 실제 이동 가능성까지 검증했다고 말하지 않는다.

`장소 보관함`은 기존 장소 데이터베이스를 재사용한다. 지역·세부 지역·종류 태그, 예산 메모·통화·결제 수단·지도·공식 링크·TIP·개인 별점·방문 체크를 저장하고, 전체·맛집/카페·관광·쇼핑/편의점·사진·일정 연결 뷰를 제공한다. 기존 숫자 `평점`은 보존하고 새 개인 별점은 `개인 평점`에 저장한다. 일정의 `장소 카드` 관계로 선택하면 장소 쪽 `방문 일정`이 연결된다. 확정된 시각·동선은 일정이, 영업시간·주소·가격·정보 근거는 장소가 관리하며 중복 기록하지 않는다. `방문 계획`은 실제 방문 체크를 우선하고, 취소·건너뜀을 제외한 일정 연결을 집계한다. 계획만 연결했다고 방문 완료로 체크하지 않는다. 독립적으로 쓰는 일정에는 기존 `장소` 텍스트도 사용할 수 있다. 가상 예시는 실제 일정·추천·방문 기록으로 가져오지 않는다.

`항공·장거리 교통`은 편도 한 구간당 한 행이다. 왕복·환승은 나누고 여행·연결 일정에 연결한다. 교통수단·예약 상태, 운영사·편명·공항/역·터미널, 예약번호·티켓 파일, 좌석·수하물·기내식, 요금·통화·금액 범위, 변경·취소 조건과 기한을 관리한다. 여정 카드·구간/시간·예약/탑승·환승/공항 이동·요금/변경 연결 뷰를 사용한다. 출발·도착 날짜 속성은 각각 현지 시간대로 시간까지 저장하고 표시용 `출발 시간대`·`도착 시간대`도 선택한다. 목록 밖의 지역은 `직접 입력`과 해당 IANA 시간대를 사용한다. 시간대 선택만으로 잘못 입력한 날짜의 시각을 보정했다고 말하지 않는다. `이동 시간`은 실제 경과 분을 계산하며 시차·날짜변경선을 반영한다. `이전 구간`은 직전 편 하나만 연결하고 환승 간격은 이전 도착→다음 출발로 계산한다. 간격만으로 입국·수하물 재수속·터미널 이동이나 최소 환승시간 충족을 보증하지 않는다. 체크인·탑승 마감은 확인된 기준만 입력하고 출발지 시간대로 표시한다. 취소·변경 기한은 예약 조건에 명시된 시간대로 저장한다.

`현지 이동`은 공항/역↔숙소·시내·도시 간·심야 귀가를 구간별로 기록한다. 출발지·도착지·이동 수단·노선·승하차/환승 안내·지도·예상 소요(분)·요금/통화/금액 범위를 관리하고 시간·요금의 확인 상태를 구분한다. 유효한 이동 일시 범위가 있으면 그 경과 시간을 우선 표시하고, 날짜가 없으면 예상 소요 시간을 표시한다. 막차는 날짜·시간·현지 시간대를 함께 저장하고 심야 대안과 대안 지도도 남긴다. `연결 장거리 구간`과 `연결 일정`으로 항공편·열차 및 일별 일정에 연결한다. 날짜·막차·운행 여부·요금·이동 시간은 추정하여 확정하지 않는다.

`교통패스·서비스·렌터카`는 이동 구간과 별도로 비교·선택·구매/예약 상태를 관리하고 현지 이동의 `교통 준비`로 연결한다. 교통카드·패스는 적용/제외 노선·유효기간·가격·수령 방법, 택시·호출은 서비스·지역·앱 링크, 렌터카는 인수/반납·면허/국제운전면허·운전자 조건·보험/보증금·차량/연료·주차/통행료·주유/충전/반납 조건을 속성으로 작성한다. 서류가 미정이면 준비 완료로 처리하지 않고 `해당 없음`은 확인한 경우만 선택한다. 서류 체크 완료는 운전 자격이나 실제 대여 가능 여부의 검증이 아니다. 교통의 예상 요금·상품 가격은 지갑에서 자동 차감하지 않고 실제 결제를 `사용한 내역`에 한 번 기록한다. 항공·장거리 교통의 공통 예약은 아래 예약 관리에 한 건만 등록하여 상세 구간과 연결한다.

숙소 상세 관리는 기존 `숙소 정보` DB를 재사용한다. 숙소 카드·후보 비교·확정 숙소·객실/체크인·비용/취소 뷰를 제공한다. 사진·주소·지도·연락처, 객실 유형·숙박 인원·객실 수·침대 구성, 시설·조식 조건·늦은 체크인·출입 방법, 접근성과 주변 시설을 속성으로 관리한다. 기존 `객실·인원` 메모는 보존한다. `숙박 총액`은 전체 숙박 기준이며 확인한 뒤 `총액 확인`을 체크한다. 세금 포함/별도, 보증금, 현장 결제액을 구분하고 세금·보증금을 총액에 자동으로 더하거나 실제 지출로 추정하지 않는다. 시설 태그는 포함 요금이나 이용 가능 시간을 보증하지 않으므로 조건을 확인한다.

`예약 관리`는 기존 예약·체크리스트 DB를 확장한 공통 예약 창구다. 한 예약당 한 행으로 항공·숙소·식당·체험·티켓 등을 종류로 구분하고 숙소·교통·일정·장소 관계를 연결한다. 예약 현황 보드·이용 달력·결제/잔금·마감 관리·후속 작업·바우처/연결 뷰를 사용한다. 이용 일시·IANA 현지 시간대·인원·예약자·예약번호와 확인서/QR/링크를 기록한다. 오픈일·결제 기한·무료 취소·변경/취소 마감·후속 기한은 구별하고 각 날짜 속성에 예약처 기준 시간대를 설정한다. 기존 `기한`과 `취소·환불` 상태는 보존하며 후자를 환불 완료로 추정하지 않는다. 취소·환불 대기·환불 완료는 진행/확정 집계에서 제외한다.

예약의 이용 날짜만 알면 날짜만 입력하고 `이용 시각 확인`은 체크하지 않는다. 시각을 확인했을 때만 시간·시간대와 함께 체크하여 자정을 임의로 확정하지 않는다. 예약의 `금액`은 총액이고 `결제액`은 해당 예약 통화로 실제 결제한 누계다. `금액 확인`과 `결제액 확인`을 모두 체크한 경우에만 잔금을 표시한다. 미정 금액을 0원으로 확정하지 않고, 확인된 미결제 0원만 입력한다. 총액보다 큰 결제액이나 음수는 입력 확인 대상으로 표시한다. 취소·환불 예약은 일반 잔금 대신 내역 확인을 표시하고 환불액을 따로 관리한다. 예약 입력만으로 지갑을 차감하지 않는다. 담당자는 PEOPLE 속성에서 고르고 워크스페이스 외 동행자는 담당자 메모에 기록한다. 후속 작업을 완료하면 완료 체크로 작업 뷰에서 제외한다.

숙소의 `예약 관리`와 교통의 `통합 예약`이 연결되면 `예약 현황`은 연결 예약의 상태를 우선 표시한다. 연결하지 않은 기존 행은 원래 예약 상태를 표시한다. 연결 후 상태·결제·후속 작업은 공통 예약에서 수정하고, 기존 예약번호·티켓·메모를 자동 삭제하거나 덮어쓰지 않는다. 같은 예약을 두 번 생성하지 않는다. 숙박 일정·운항 정보는 원래 상세 카드가 관리하며, 일정 변경 시 예약 관리의 이용 일시와 연결 일정에 미치는 영향도 함께 검토한다. 관계만 연결했다고 날짜·예약번호·결제액까지 자동 동기화된다고 설명하지 않는다.

새 여행에서 숙소·예약·세 교통 DB를 재사용하고 모든 연결 뷰를 새 여행으로 필터링한다. 접힌 예시와 `구분=예시` 행은 실제 여행으로 가져오지 않는다. 사용자 맞춤 구성 선택지는 향후 큰 묶음으로 제공하되 템플릿 구성 작업 도중 임의의 선택 메뉴를 추가하지 않는다. 현재는 구성 요소를 독립된 섹션으로 만들고, 전체 구성이 끝난 뒤 메인 요약·분야별 하위 페이지로 배치한다.

## 예산·지출과 동행자 정산

기존 `여행 지갑`, `예산`, `사용한 내역` DB를 재사용한다. 준비 금액은 통화별 지갑, 카테고리 한도와 예상/확정액은 예산, 실제 결제/환불은 거래 한 건당 한 행으로 관리한다. 예산의 `금액`은 카테고리 한도이며 `범위=1인`이면 `적용 인원`을 곱한다. 실제 거래를 같은 지갑의 `카테고리 예산` 하나에 연결한다. 카테고리 한도를 준비 금액에 더하거나 예상/확정액을 실제 지출로 중복 차감하지 않는다. 기존 `사용 금액`·`잔액` 등 이전 속성은 보존하되 새 연결 뷰에서는 검증한 `실제 지출`·`예산 현황`을 사용한다. 예비비는 준비 금액 안의 유보액이며 지출이 아니다.

거래 금액은 지갑 통화의 실제 결제 건 전체 금액이다. 여러 명이 나눠 결제했으면 결제 건별로 나누고 전체 청구액을 반복 입력하지 않는다. 결제자·수단·일자, 선결제/현장/잔금 단계, 관련 예약·영수증을 기록한다. 완료한 환불은 별도 양수 거래로 원거래에 연결하며, 실제 반환액과 별도로 지불한 수수료를 중복 기록하지 않는다. 예정 거래는 실제 잔액과 정산에서 제외한다.

여행의 `기준 통화`와 `정산 단위`를 먼저 정한다. 기본 템플릿은 KRW·1원 단위이며 금액은 미정으로 둔다. 각 거래의 `환산 통화`·`계산 단위`는 이 설정에 맞춘다. 적용 환율은 원래 통화 **1단위당** 기준 통화 금액이다. 100엔 고시 값은 100으로 나눠 입력하고 같은 통화는 1이다. 실제로 확인한 환율·적용일·근거를 남기고 `환율 확인`을 켠다. 환산액은 단위에 맞춰 반올림한다. 환율을 자동 조회하거나 미확인 값을 최신 환율로 확정하지 않는다. 지갑 원래 통화 잔액은 환산과 별개다. 카테고리 지출 차트는 설정한 기준 통화의 환산 완료 지출을 보여주며 환불 전 금액이다. 기준 통화 변경·새 여행 생성 시 차트의 환산 통화 필터도 바꾼다. 여행 요약 뷰는 제목 대신 `여행 키`를 새 여행 ID로 필터링한다.

`동행자`는 여행당 한 사람 한 행으로 역할·요청·준비/예약 담당을 관리한다. 기존 워크스페이스 PEOPLE 담당자는 유지하고 여행자 담당 관계도 사용할 수 있다. `공동 결정`에는 선택지·의견·결정 사항·담당자·기한을 기록한다. 예시의 역할·합의를 실제 사용자에게 적용하지 않는다.

`지출별 분담`은 거래당 부담자 한 명에 한 행이다. 같은 사람을 중복 입력하지 않는다. 정산할 실제 거래에만 `정산 포함`을 켜고 공용/개인, 결제·환불자 한 명, 분담 방식을 정한다. 개인 비용은 대상 한 명으로 한다. 분담의 `계산 기준액`은 해당 거래의 **부호 있는 기준 통화 실제액**이다. 완료된 환불은 음수다. 계산 인원·방식·통화·단위와 기준액 확인을 함께 기록한다. 균등은 인원으로 나누고, 비율은 합계 100%, 개별 금액은 기준 통화의 양수 부담액을 입력해 확인한다. 개별 환불액의 부호는 기준액을 따른다. 단위 반올림 차이는 지정한 한 행의 `반올림 보정`에 남긴다. `원거래 대조`·`분담 점검`을 확인하고 원거래가 바뀌면 분담 기준을 갱신한다. 자동으로 모든 중복·다른 여행 연결까지 검증했다고 말하지 않는다.

**사람별 정산은 검토한 합계의 스냅샷이다.** 복잡한 연결 집계가 테스트에서 0으로 조회되어 자동 집계를 확정값으로 사용하지 않는다. 미검증 자동 집계 속성은 숨긴 채 보존했다. 원거래나 송금만 바꿔도 사람별 합계가 자동 갱신된다고 설명하지 않는다.

사용자가 `정산 다시 검토해줘`라고 하면:

1. 해당 여행·통화의 실제 거래, 분담, 송금 기록을 읽는다. 관련 동행자의 `정산 기준 확인`을 먼저 끈다. 다른 여행·통화가 섞였거나 환율·담당자·분담 기준이 불명확하면 확인할 항목을 표시하고 확인 체크를 켜지 않는다.
2. 분담 기준을 원거래와 대조한다. 중복 부담자, 비율 100%, 개별/균등 분담 합계와 반올림을 확인한다. 미완료 거래·예정 송금은 제외한다. 환불은 실제 수령자 결제액과 해당 사람들의 부담액에서 차감한다.
3. 사람별 `확인 결제액`·`확인 부담액`·`확인 송금액`·`확인 수령액`을 기준 통화로 합산해 기록한다. `확인 통화`·`정산 검토일`을 남기고 검증한 경우에만 기준 확인을 켠다. 수식·롤업 결과 속성에 계산값을 직접 쓰지 않는다.
4. `정산 차액=결제액−부담액+송금액−수령액`으로 양수는 받을 돈, 음수는 보낼 돈, 검토 후 0은 정산 완료다. 받을 돈과 보낼 돈 총합이 일치하는지 확인한다. 이후 원거래·환율·분담·송금 변경을 반영할 때는 관련 기준 확인을 끄고 다시 검토한다.

`정산 송금`은 보낸/받은 사람·기준 통화 금액·상태·날짜·증빙을 기록한다. 기록만으로 실제 송금을 실행하거나 여행 지갑을 차감하지 않는다. 송금 완료 기록 후 사람별 검토 합계를 갱신한다. 계산 예시는 실제 환율·결제·송금·사용자 합의와 구분한다. 새 여행에서는 예산·거래·동행자·분담·송금·공동 결정 뷰도 해당 여행으로 필터링하고 예시는 가져오지 않는다. 자동 설치기에서는 계산 수식을 확정값으로 쓰지 않고, 대상 워크스페이스에서 연결·검수 후 활성화한다.

## 준비할 일과 준비물

`준비할 일`은 실행할 작업 한 건당 한 행이다. 여행 전·출발 당일·여행 중·귀국 전·귀국 후로 나누고 담당 여행자 한 명·기한·중요도·상태를 관리한다. 시점별 표·진행 보드·기한 달력·기한 확인·출발 당일·귀국 전후·여권/입국 확인·제외 포함 뷰를 사용한다. 기한이 없어도 작성한다. 완료·제외 항목에는 기한 지남 경고를 표시하지 않는다. 실제 예약은 기존 예약 관리에 연결하며 할 일 완료가 예약 상태를 바꾸지는 않는다.

여권·입국 요건은 목적지·국적·경유·여행일에 맞는 공식 근거, 확인일·결과·확인 상태로 기록한다. 기본 체크리스트가 있다는 이유로 현재 입국 요건을 확인했다고 말하지 않는다. 실제 요건을 조사할 때는 필요한 조건과 공식 자료를 확인하고, 미정인 조건은 확인 필요로 남긴다. 보험·통신·환전/카드·집/반려동물·업무도 실행할 일로 기록하되 사용자의 실제 가입·소유·반려동물·업무 상황을 추정하지 않는다.

`준비물`은 기존 DB를 확장한다. 공용/개인·분류·필수 체크, 담당 여행자·수량/챙긴 수량·구매 상태/링크·수납 위치, 계절·날씨/활동 조건을 기록한다. 필수/미완료·구매/확인·공용·담당자별·계절/날씨/활동·귀국 소지품·제외 포함 뷰를 제공한다. 기존 담당자 텍스트는 보존하고 진행률은 여행자 담당 관계로 집계한다. 구매 완료, 수량 확인, 준비 완료 상태, 귀국 소지품 확인은 별개다. 수량을 채웠다고 상태를 자동 완료하지 않으며, 수납 위치 선택이 항공사 반입 허용을 검증한 표시도 아니다. 귀국 확인 대상만 골라 귀국 전 다시 체크하고 확인일을 남긴다.

진행률은 할 일과 준비물을 각각 계산한다. 완료/준비 완료만 분자에 포함하고 제외는 분모에서도 뺀다. 미배정 항목도 전체 수에 포함하며 담당자별 집계는 대표 담당 한 명을 기준으로 한다. 항목이 0개면 등록된 항목 없음으로 표시하고 100% 완료로 추정하지 않는다. 이 진행률은 Notion에서 상태 변경을 반영하는 검증된 수식/롤업이며, 별도 검토 스냅샷인 금전 정산과 혼동하지 않는다. 여행 카드에는 자동 진행을 보정하는 `직접 완료`·`자동 제외` 체크박스를 묶음별로 둔다. 자동 완료 결과는 수식으로 표시하고, 사용자가 직접 완료를 켜거나 자동 완료를 제외할 수 있게 한다. 수식 속성 자체를 사용자가 편집 가능한 체크박스로 가장하지 않는다.

기본 템플릿에는 시작용 할 일 15개·품목 8개가 `구분=기본`으로 있다. 새 여행에서는 기본 항목의 이름·분류·시점·선택용 조건만 복사하고 새 여행에 연결한다. 할 일은 시작 전, 준비물은 미정으로 시작하며 예전 여행의 완료·구매·귀국 체크·기한·실제 확인 결과·예약 연결·담당자·챙긴 수량을 그대로 가져오지 않는다. 수량·필수 여부는 사용자가 알려준 선호와 여행 조건에 맞추고 미정인 것은 비워둔다. 예시는 복사하지 않고 원본 템플릿의 상태도 바꾸지 않는다. 새 여행에서는 준비 현황의 `여행 키` 필터와 할 일·준비물·담당자별 뷰를 해당 여행에 맞춘다.

## 날씨·플랜 B/C·자료 보관함

`지역별 날씨`는 방문 지역과 대상 기간별로 공식 확인 링크·자료 종류·확인 상태·예보 확인일·다음 확인일을 기록한다. 최저/최고는 ℃, 강수 확률은 %이며 실제로 확인한 값에만 확인 체크를 켠다. 미확인은 빈값으로 남기고 0℃·0%를 미정으로 취급하지 않는다. 평년 참고·단기 예보·특보/운영 안내를 구분한다. 실제 날씨가 필요할 때는 해당 지역·여행일의 공식 정보를 조회하고, 예보가 제공되지 않는 기간의 값을 확정하거나 평년값을 예보로 바꾸지 않는다. 기온·강수에 따른 대비 내용과 기존 준비물을 연결하되 자동 구매·준비 완료로 처리하지 않는다. 저장된 링크와 수치는 자동 갱신된다고 설명하지 않는다.

**플랜 B·C는 기존 일정 한 행의 속성이다.** 대안용 별도 일정 DB나 활성 일정 행을 만들어 기본 일정·비용·방문 집계에 중복 포함하지 않는다. 기존 일정의 날씨/고정 일정·플랜 B/C 탭과 일정 카드에서 활동 환경, 변경 유연성, 변경/취소 확인, 대안 검토 이유·선택 기준·판단 시점을 기록한다. B/C 각각의 이름·기존 장소 카드·환경·지도·이동·확인사항을 관리한다. 우천·기온/기상·휴무·매진·지연 등에 대한 선택 기준은 사용자 상황과 확인 근거로 정하며 자동 전환 임계값을 임의로 확정하지 않는다. 고정 일정은 실제 예약·운영 조건부터 확인한다.

`검토할 대안` 선택이나 판단 시점 도래만으로 원래 일정·날짜·장소·예약을 변경하지 않는다. 실제 반영은 기존 일정 수정 규칙에 따라 원안 대비 이동·다음 일정·예약·비용 영향을 먼저 보여주고 반영 요청 후 관련 부분만 수정한다. 적용 직전 다시 읽고 사용자 메모·원래 예약 정보·다른 날짜를 보존한다. 필요한 원안·변경 기록은 페이지 본문에 부분 추가하고 B/C 후보를 지우지 않는다. 반영 상태는 실제 변경 이후에만 반영 완료로 기록한다. 원래 계획을 수정하지 않았는데 대안이 적용됐다고 말하지 않는다.

`여행 자료 보관함`은 링크·파일·요약·지역/태그·출처·확인일/상태·대상 기간을 종류별로 관리한다. 일정·장소·예약을 연결해 원래 카드에서 찾게 한다. 이미 예약에 저장한 바우처·QR·확인서는 불필요하게 복제하지 않고 해당 예약을 연결한다. 중요 자료와 보관 자료를 구분하고 보관 상태는 기본 화면에서 제외하되 전체 보기에서 남긴다. 파일을 저장했다고 오프라인 다운로드가 완료됐다고 설명하지 않는다. 공식 확인처 링크를 저장한 것과 실제 여행일의 내용을 확인한 것은 구별한다.

새 여행에서는 날씨·자료·일정 대안 뷰도 해당 여행으로 필터링한다. 기본 공식 링크는 해당 지역에 맞는 자료만 재사용하고 예시 기온·강수·대안·확인 결과는 가져오지 않는다. 실제 사용자 자료의 출처·파일·예약 연결은 보존한다. 템플릿 구성 단계에서는 날씨와 자료를 독립 섹션으로 추가하고, 플랜 B/C는 기존 일정 파트 안에 유지한다.

## 추가 자동 확인

D-Day·일수/숙박 일수·여행 상태·소요 시간·진행률·환산/인원 범위·예산·검토 후 정산은 기존 기능을 유지한다. 다음 기능만 추가했다. 기존 `일정 확인`은 행 내부 입력 점검이며, 일정 간 겹침/이동 검사는 아래 비교 기록을 사용한다.

`일정 비교 검사`는 원래 일정 행과 구분되는 검사 기록이다. 기준/비교 일정 하나씩을 연결해 반개방 구간 `[시작, 종료)`의 겹침을 계산한다. 앞 일정 종료와 다음 시작이 같으면 겹침이 아니다. 원래 일정의 `시각 확인`은 시작·종료 시각이 실제로 정해진 경우만 켠다. 날짜만 있거나 종료가 없으면 시각 확인 필요로 남기고 취소·건너뜀은 검사에서 제외한다. 의도적인 병행 일정은 사용자 근거가 있을 때만 겹침 허용과 메모를 남긴다.

연속 이동 구간에는 확인한 `필요 이동(분)`·`필요 여유(분)`을 기록하고 `이동 기준 확인`을 켠다. `다음 시작−앞 종료−필요 이동−필요 여유`가 음수면 부족을 표시한다. 0분도 확인한 경우만 쓰고 이동·안전 여유 기준을 임의로 정하지 않는다. 방향/순서가 바뀌면 해당 이동 기준 확인을 끄고 재검토한다. 경고를 보고 원래 일정·예약을 자동 변경하지 않는다.

사용자가 `일정 검사해줘`라고 하거나 일정을 생성/수정해 반영한 뒤에는 해당 여행의 일정과 기존 검사 기록을 읽는다. 같은 여행의 서로 다른 일정 쌍을 중복 없이 연결하고 시작 시각/일차/순서에 맞춰 기준·비교 방향과 실제 연속 이동 구간을 갱신한다. 취소/건너뜀 행도 연결 범위에는 남겨 재활성화에 대비하되 결과는 제외한다. 기존 기록을 재사용하고 누락 쌍만 추가한다. 현재 여행 일정이 n개면 한 일정의 비교 연결은 n−1개가 기준이다. `검사 범위`는 누락/중복 연결을 알리는 점검이며 연결 수 충족 자체가 충돌 없음·필수 정보 완비를 뜻하지 않는다. 같은 여행 연결과 중복 쌍도 실제 ID로 확인한다. B/C 후보는 별도 일정으로 만들지 않으므로 검사 건수에도 일정으로 추가하지 않는다.

연결된 쌍은 날짜 변경을 계산에 반영하지만 새 일정·비교 기록은 자동 생성되지 않는다. 수동 추가·순서 변경 후에는 스킬로 비교 연결을 갱신한다. 부분 검사나 미연결 상태를 전체 자동 검사 완료라고 설명하지 않는다. 검사 기록은 메인 일정 파트의 접힌 시간/이동 비교 결과에서 확인한다.

예약의 `기한 알림` 탭은 예약 오픈·결제·무료 취소/변경 취소를 달력 날짜 기준으로 오늘·임박·경과 표시한다. 임박 기본값은 3일이며 당일·1일·7일로 선택할 수 있다. 완료/취소 상태에 따라 해당 경고를 종료한다. 기존 날짜·예약 조건은 보존하고 정확한 시각·시간대와 무료 취소 가능 여부는 원본 조건을 확인한다. 페이지 내 수식/확인 목록이며 푸시 알림·자동 예약/결제/취소를 설정했다고 말하지 않는다.

여행의 `필수 정보 확인`은 목적지와 날짜 또는 기간만 검사한다. 예산·인원·숙소가 미정이라고 새 여행 생성을 멈추지 않는다. 여권/입국 확인을 완료로 표시했으나 공식 링크·확인일이 없으면 `확인 근거 점검`에서 표시한다. 이 표시는 실제 입국 요건의 정확성을 검증한 결과가 아니다.

장소·자료의 `정보 점검`은 출처·확인일 누락과 재확인 시점을 표시한다. 재확인 주기는 양수로 설정하며 빈값/0은 기본 30일이다. 직접 정한 다시 확인일이나 주기 중 먼저 도래하는 조건을 표시하고, 음수/미래 확인일은 입력 확인 대상으로 둔다. 자료의 보관 상태와 사용자 지정 재확인 필요 상태를 존중한다. 내부 작성 메모에 외부 링크를 강제하지 않고, 공식 안내/날씨 등 사실 확인 자료에 필요한 근거를 점검한다. 설정 주기 내라는 표시가 최신성·정확성을 보증하지 않으며 날씨는 기존 다음 확인일 기능을 유지한다.

새 여행에서는 새 확인 탭과 비교 결과 뷰도 해당 여행으로 필터링한다. 검사용 시각·원래 기한·기존 확인일을 임의로 채우지 않는다. 테스트는 가상 예시에서 수행하고 변경한 원래 일정·예약·자료 값은 복원한다. 자동 설치기를 사용하더라도 확인되지 않은 수식 결과를 완료로 표시하지 않는다.

## 여행 플래너 만들기

사용자가 기존 양식을 쓰고 싶다면 해당 페이지를 읽고 제목, 섹션, 일정표·예산표 구조를 파악한다. 별도 양식이 없으면 현재 워크스페이스의 설치 기록을 재사용하거나 [내장 기본 템플릿 청사진](references/template-blueprint.md)을 설치한다. 참조 원본 페이지 URL은 현재 워크스페이스의 디자인을 확인할 때만 사용하며, 다른 워크스페이스의 설치에 필수로 요구하지 않는다. 청사진 설치도 불가능할 때만 아래 섹션을 가진 빈 페이지를 만든다.

- **여행 개요** — 목적지, 날짜 또는 기간, 인원, 숙소, 예산
- **날짜별 일정** — 날짜, 시간대, 장소, 이동, 예약·휴무 메모
- **예산** — 항목, 금액, 통화, 1인 또는 일행 전체, 확정 또는 예상
- **예약 체크리스트** — 예약 대상, 기한, 상태, 예약 정보 또는 링크

템플릿을 저장하거나 확인한 뒤 링크를 알려준다. 이후 같은 템플릿을 지정할 때 이 링크를 사용할 수 있다고 안내한다.

## 새 여행 계획

1. 목적지와 날짜 또는 기간 중 빠진 필수 정보만 묻는다. `후쿠오카 3박 4일`이면 바로 작성·저장한다. 날짜 없이 기간만 있으면 1일차부터 표시하며 임의의 날짜나 도착 시각을 확정하지 않는다. 인원, 예산, 숙소는 알려준 경우 반영하고 미정이면 비워두며, 이를 채우기 위해 작성을 멈추지 않는다.
2. 지정된 템플릿이 있으면 먼저 구조를 읽고, 저장할 때 그 템플릿의 복제본을 사용한다. 지정된 템플릿이 없으면 설치 기록의 매핑을 재사용하고, 매핑이 없으면 첫 실행 설치를 수행한 뒤 대상 워크스페이스에 생성된 대시보드·데이터베이스를 사용한다. 원본 대시보드 URL은 다른 워크스페이스의 필수 입력이 아니다. 새 여행 요약 행과 관련 일정·예산·예약·장소·준비물 행을 연결하고, 초안만 요청하면 채팅에 보여준다.
3. 확정된 항공편·숙소·예약을 먼저 배치하고, 가까운 장소끼리 묶어 동선을 짠다. 알려진 이동 시간을 반영하고, 확인 근거가 없는 휴무·가격·이동 시간은 `확인 필요`로 표시한다. 금액은 확정과 예상, 1인과 일행 전체를 구분한다.
4. 저장이 성공하면 여행 페이지 링크와 남은 확인 항목을 알려준다.

## 기존 일정 수정

1. 대상 여행 페이지를 읽고, 바뀐 조건과 영향을 받는 일정·예약·이동·비용을 찾는다. 대상이 여러 개면 페이지 이름이나 링크로 확인한다.
2. 바뀌는 항목을 변경 전후로 보여준다. 예약을 변경해야 할 가능성과 확인할 사항을 따로 표시한다. 사용자가 변경안을 확인하고 반영을 요청하면 수정한다.
3. 적용 직전에 해당 항목을 다시 읽고, 검토한 뒤 내용이 달라졌다면 변경안을 갱신하고 다시 반영 요청을 받는다. 관련 항목은 부분 교체로 수정하고 사용자 메모와 다른 날짜, 이미 기록된 예약 정보는 보존한다. 예약 변경 가능성은 확인 항목으로 안내하고 예약 완료 상태나 예약번호를 임의로 변경하지 않는다.
4. 수정 결과를 확인하고 여행 페이지 링크를 알려준다.

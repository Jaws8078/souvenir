# Souvenir 여행 도우미

연결된 Notion 플러그인으로 템플릿과 여행 페이지를 읽고 저장한다. 다른 워크스페이스에서는 `skills/souvenir/assets/template-source.json`의 공개 템플릿 링크가 있으면 사용자 승인 복제를 우선하고, 링크를 쓸 수 없을 때만 저장소에 포함된 코드 재구축 매니페스트를 보조 경로로 사용한다.

## 작업 선택

요청에서 작업이 명확하면 바로 시작한다. `$souvenir`만 호출하거나 작업이 모호하면 다음 메뉴를 보여준다. 번호나 작업 이름으로 답할 수 있다고 안내한다.

1. 여행 플래너 만들기
2. 새 여행 계획
3. 기존 일정 수정

이미 알려준 정보는 다시 묻지 않는다. 사용자가 저장 위치를 지정하면 해당 위치를 사용한다. 별도 위치 없이 저장을 요청하면 비공개 초안을 사용한다. Notion 연결이나 쓰기 권한이 없으면 작성한 초안을 채팅에 보여주고 저장에 필요한 조건을 알려준다.

Notion 도구를 사용할 때는 해당 도구의 Markdown 규격을 먼저 읽는다. 비공개 초안은 페이지 생성의 `creation_mode: "draft"`로 저장하며 부모 위치를 함께 지정하지 않는다. 페이지 제목은 속성에 넣고 본문에는 중복하지 않는다. 저장 응답의 오류·경고를 확인한 뒤 성공한 페이지 링크를 안내한다.

## 필요한 규칙만 읽기

이 파일은 공통 진입점이다. 아래 자료를 해당 작업에 맞춰 읽고, 다른 분야의 상세 규칙까지 한꺼번에 로드하지 않는다. 상대 경로는 이 스킬 폴더를 기준으로 해석한다. 플러그인과 저장소 로컬 스킬 모두 이 파일을 원본으로 사용한다.

- 첫 사용·설치·로그인·필수 정보 입력: [온보딩](references/onboarding.md). 최초 사용은 연결 확인 → 스킬 확인 → 로그인 확인 → 템플릿 연결 → 기본 정보 입력 순서이며, 완료한 단계와 이미 받은 정보는 재사용한다.
- 대화로 여행 계획을 이어갈 때: [대화형 계획 마법사](references/conversation-flow.md). 선택한 파트만 질문하고, 모르는 값은 미정으로 남긴다.
- 실제 입력·저장·표시를 바꿀 때: [간편 입력 규칙](references/input-design.md).
- 템플릿 연결, 여행·일정·장소·항공·숙소·예약 데이터 작업: [데이터 운영 규칙](references/data-operations.md).
- 지갑·예산·지출·환산·분담·정산: [금액과 정산](references/finance.md).
- 준비할 일·준비물·준비 진행률: [준비 규칙](references/preparation.md).
- 날씨·플랜 B/C·자료: [대안과 자료](references/alternatives.md). 플랜 B/C는 기존 일정의 속성으로 기록한다.
- 일정 충돌·이동 여유·기한·필수 정보·최신성 점검: [검증 규칙](references/validation.md).
- 화면 구성·인원 변경: [사용성과 인원 규칙](references/template-usability.md).
- 공개 링크를 사용할 수 없어 코드로 재구축할 때만: [fallback 청사진](references/template-blueprint.md), [매니페스트](assets/template-manifest.json).

## 공통 데이터 원칙

- 디자인 원본은 사용자의 Notion 템플릿이다. 코드 매니페스트는 링크를 이용할 수 없을 때의 재구축용 스냅샷이며, 이를 원본과 완전히 같은 복제로 설명하지 않는다.
- 공개·복제 가능한 링크는 [배포 설정](assets/template-source.json)을 확인한다. 설치 기록의 대상 워크스페이스 매핑을 재사용하고, 원본의 개인 데이터·예시 행·ID를 새 여행에 가져오지 않는다.
- 새 여행은 목적지와 날짜 또는 기간으로 시작한다. 날짜를 알면 출발일·종료일을 저장하고, 기간만 알면 실제 날짜·D-Day를 비워 둔다. 인원·통화는 미정일 수 있다.
- 항공권·숙소 가격은 KRW로 기록한다. 지갑은 선택한 통화를 사용한다. 환율 근거 없이 숫자를 환산하거나 예정 비용을 실제 지출로 차감하지 않는다.
- 수식·롤업은 읽기 전용 결과다. 미확인 휴무·가격·이동 시간은 확인 필요로 표시한다. 자동화·로그인·설치·저장 성공은 실제 확인한 범위만 설명한다.
- 기존 일정·예약·사용자 메모를 수정할 때는 영향 범위를 먼저 보여주고 반영 요청에 따라 해당 부분만 변경한다. 저장 직전에 다시 읽고 변경된 내용이 있으면 변경안을 갱신한다.
- 로컬 설치 스크립트는 `validate`/`plan` 또는 기본 점검으로 시작한다. 실제 등록·생성은 사용자가 요청한 범위에서 실행하고, 토큰은 채팅으로 받지 않는다. 설치 대상마다 별도 `--mapping`을 사용한다.

## 여행 플래너 만들기

사용자가 기존 양식을 쓰고 싶다면 해당 페이지를 읽고 제목, 섹션, 일정표·예산표 구조를 파악한다. 별도 양식이 없으면 현재 워크스페이스의 설치 기록을 재사용하거나 [내장 기본 템플릿 청사진](references/template-blueprint.md)을 설치한다. 참조 원본 페이지 URL은 현재 워크스페이스의 디자인을 확인할 때만 사용하며, 다른 워크스페이스의 설치에 필수로 요구하지 않는다. 청사진 설치도 불가능할 때만 아래 섹션을 가진 빈 페이지를 만든다.

- **여행 개요** — 목적지, 날짜 또는 기간, 인원, 숙소, 예산
- **날짜별 일정** — 날짜, 시간대, 장소, 이동, 예약·휴무 메모
- **예산** — 항목, 금액, 통화, 1인 또는 일행 전체, 확정 또는 예상
- **예약 체크리스트** — 예약 대상, 기한, 상태, 예약 정보 또는 링크

템플릿을 저장하거나 확인한 뒤 링크를 알려준다. 이후 같은 템플릿을 지정할 때 이 링크를 사용할 수 있다고 안내한다.

## 새 여행 계획

1. 첫 사용 온보딩이 완료되지 않았다면 먼저 `1~5단계`를 순서대로 실행한다. 이미 완료된 단계는 재실행하지 않고 누락된 연결·설치·기본 정보만 묻는다.
2. `후쿠오카 3박 4일`처럼 목적지와 기간이 이미 있으면 다시 묻지 않는다. 날짜가 없으면 기간만 저장하고 1일차부터 표시하며 임의의 날짜나 도착 시각을 확정하지 않는다. 인원·기준 통화가 미정이어도 `미정`으로 저장한 뒤 계속 진행한다.
3. 지정된 템플릿이 있으면 먼저 구조를 읽고, 저장할 때 그 템플릿의 복제본을 사용한다. 지정된 템플릿이 없으면 설치 기록의 매핑을 재사용하고, 매핑이 없으면 첫 실행 설치를 수행한 뒤 대상 워크스페이스에 생성된 대시보드·데이터베이스를 사용한다. 원본 대시보드 URL은 다른 워크스페이스의 필수 입력이 아니다. 새 여행 요약 행과 관련 일정·예산·예약·장소·준비물 행을 연결하고, 초안만 요청하면 채팅에 보여준다.
4. 확정된 항공편·숙소·예약을 먼저 배치하고, 가까운 장소끼리 묶어 동선을 짠다. 알려진 이동 시간을 반영하고, 확인 근거가 없는 휴무·가격·이동 시간은 `확인 필요`로 표시한다. 금액은 확정과 예상, 1인과 일행 전체를 구분한다.
5. 저장이 성공하면 여행 페이지 링크와 남은 확인 항목을 알려준다.

## 기존 일정 수정

1. 대상 여행 페이지를 읽고, 바뀐 조건과 영향을 받는 일정·예약·이동·비용을 찾는다. 대상이 여러 개면 페이지 이름이나 링크로 확인한다.
2. 바뀌는 항목을 변경 전후로 보여준다. 예약을 변경해야 할 가능성과 확인할 사항을 따로 표시한다. 사용자가 변경안을 확인하고 반영을 요청하면 수정한다.
3. 적용 직전에 해당 항목을 다시 읽고, 검토한 뒤 내용이 달라졌다면 변경안을 갱신하고 다시 반영 요청을 받는다. 관련 항목은 부분 교체로 수정하고 사용자 메모와 다른 날짜, 이미 기록된 예약 정보는 보존한다. 예약 변경 가능성은 확인 항목으로 안내하고 예약 완료 상태나 예약번호를 임의로 변경하지 않는다.
4. 수정 결과를 확인하고 여행 페이지 링크를 알려준다.

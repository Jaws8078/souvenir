# 입력은 짧게, 결과는 한눈에

사용자는 풍성한 디자인을 원하지만 입력 항목은 최소화하고, 입력과 자동 계산을 명확히 구분하기를 요청했다. 아래 규칙은 기존 상세 기능 설명보다 화면 표시와 질문 개수에 우선한다.

## 공통 원칙

- 사진·커버·아이콘·분야별 색상·갤러리·보드를 유지한다. 내용을 모두 같은 긴 표로 바꾸지 않는다. 네이티브 차트는 새로 만들지 않는다.
- 기본 표는 제목 포함 대체로 3~5개 열이다. 입력 화면은 `✍️`, 자동 결과는 `🟢`, 선택 기능은 `선택 입력`으로 표시한다.
- 상세 카드는 `✍️ 직접 입력 · 여기만 작성하세요` → `🟢 자동 결과 · 입력하지 않아요` → `📎 선택 입력 · 필요할 때만`으로 구분한다. 선택 입력은 값이 있을 때만 표시한다.
- 수식·롤업을 입력 구역에 섞지 않는다. 합계 보조값·검사 연결·중간 환산·검토 스냅샷 등의 내부 속성은 `hide`로 숨긴다. 속성을 생략하면 Notion이 자동 표시할 수 있으므로 모든 나머지 속성의 숨김을 명시한다.
- 숨김은 삭제가 아니다. 속성·기록·수식·관계는 보존하고 상세 입력은 기존 전용 탭에서 필요할 때만 열게 한다. 요청하지 않은 정보를 채우기 위해 사용자를 멈추지 않는다.
- 아래는 기본 화면에 보일 항목이며 모든 항목이 필수라는 뜻이 아니다. 여행 시작의 필수 조건은 목적지와 날짜 또는 기간뿐이다. 날짜가 있으면 기간(일)을 별도로 요구하지 않는다.
- 사용 내역은 실제 사용 장부이며 금액 입력 즉시 잔액에 반영한다. 숨긴 상태가 비어 있다고 0원으로 처리하지 않는다. 예정 거래는 명시적인 `상태=예정`으로 제외한다. 기존 상태를 덮어쓰지 않으며, 지갑 연결 없는 행은 차감하지 않는다. 필터에 의한 새 행 자동 연결은 실제 생성으로 확인하기 전까지 보장하지 않는다.

## 사용 내역과 지갑

**사용자 지정:** 직접 입력은 `사용처`, `거래 유형`, `결제 단계`, `결제 수단`, `금액` 다섯 열이다. 최신 요청에 따라 금액 바로 옆에 읽기 전용 `자동 · 통화 금액`만 추가한다. 지갑·상태·날짜·분류·환율·증빙·정산·기타 수식 결과는 모두 숨긴다. 기존 값·관계와 지갑 안의 지출 표는 보존한다. 스킬이 거래를 기록할 때는 숨긴 지갑·여행 연결을 정확히 설정한다. 사용 내역은 실제 거래가 기본이고, 예정 거래는 명시적으로 예정 상태로 저장한다. 기존 상태를 바꾸어 차감 문제를 우회하지 않는다.

지갑 상세 카드 본문에는 원본 사용 내역 데이터 소스의 인라인 연결 표를 둔다. `지갑` 관계가 해당 지갑 하나를 포함하도록 필터링하고 위 다섯 입력 열 뒤에 자동 통화 금액을 표시한다. 새 지갑을 만들 때도 이 표를 함께 만들고 복제 시 원본 지갑 필터를 새 지갑으로 바꾼다. 열 너비는 사용처 180px, 유형·수단·금액 각 110px, 단계 115px, 자동 결과 165px를 기준으로 한다. 다른 여행·지갑의 거래를 섞지 않으며 기존 메모와 거래는 보존한다.

페이지 레이아웃의 `{type: "views", relation: "사용 내역"}` 모듈은 원본 기본 뷰와 표시 설정이 별개다. 원본 뷰만 고치고 지갑 내부 표에도 적용됐다고 보고하지 않는다. 자동 관계 표를 대체할 때는 먼저 모든 기존 지갑에 위 연결 표가 실제로 저장됐는지 확인한 뒤 모듈만 제거한다. 사용 내역 관계 속성·거래·계산은 삭제하지 않는다. 표가 사라지지 않았는지와 각 표의 다섯 열·지갑 필터를 검수한다.

1. `✍️ 지갑 설정`: 지갑 이름·통화·준비 금액·금액 입력 완료만 보인다. 실제 준비 총액을 확인한 뒤 체크한다.
2. `✍️ 간편 기록`과 지갑 내부 `사용 내역`: 사용처·거래 유형·결제 단계·결제 수단·금액, 총 다섯 입력 칸이다. 금액은 양수로 기록한다. 숨긴 상태가 비어 있어도 지출을 차감하며 결제 단계는 선결제·현장 결제·잔금 결제의 구분이다.
3. 날짜·분류·영수증·환율·환불·정산 등의 나머지 속성은 사용 내역 표와 상세 카드에서 숨긴다. 스킬이 추가 정보를 기록할 때는 실제로 제공된 값만 저장한다. 공용 비용 분담을 쓰지 않으면 분담 정보를 요구하지 않는다.
4. 통화는 지갑에서 읽고, 금액 옆의 `자동 · 통화 금액`에서 `¥1,320 · 엔`처럼 표시한다. 이 칸은 입력할 수식이 아니라 자동 결과다. 지갑 사용액·잔액·사용률은 지갑의 자동 결과 구역에서 읽는다. 환율 환산과 통화 단위 표시는 다르며 실제 환율·분담 계산 규칙은 SKILL.md를 따른다.
5. 홈의 지갑 요약은 해당 여행의 이름 있는 지갑만 보여준다. 빈 이름의 초안은 삭제하지 않는다. 새 지갑 작성은 지갑 설정에서 한다.

## 상세 카드의 기본 배치

제목 속성은 공통으로 직접 입력하며 아래 목록에서 생략했다. 사진이 있는 여행·장소·숙소는 기존 사진을 유지한다.

| 카드 | 기본 직접 입력 | 자동 결과 |
|---|---|---|
| 여행 | 목적지 · 여행 기간 · 기간(일) | 여행 기간 표시 · 출발까지 · 인원 안내 · 필수 정보 확인 |
| 사용 내역 | 거래 유형 · 결제 단계 · 결제 수단 · 금액 | 자동 · 통화 금액 |
| 여행 지갑 | 통화 · 준비 금액 · 금액 입력 완료 | 남은 금액 표시 · 사용 금액 표시 · 예산 사용률 |
| 일정 | 일차 · 날짜 · 장소 카드 · 활동 상태 | 시간 표시 · 일정 확인 |
| 장소 | 종류 · 지역 · 지도 | 방문 계획 · 정보 점검 |
| 예약 | 예약 종류 · 이용 일시 · 상태 | 이용 시각 안내 · 잔금 안내 · 후속 상태 |
| 준비물 | 상태 · 수량 · 여행자 담당 · 대상 | 챙기기 안내 |
| 계획 예산 | 지갑 · 분류 · 금액 · 금액 확인 · 범위 | 예산 현황 · 인원 계산 안내 |
| 숙소 | 주소 · 체크인 · 체크아웃 · 예약 상태 | 숙박 기간 · 예약 현황 |
| 항공·장거리 | 교통수단 · 출발지 · 도착지 · 출발 일시 · 도착 일시 | 노선 표시 · 이동 시간 · 예약 현황 |
| 현지 이동 | 출발지 · 도착지 · 이동 수단 · 이동 상태 | 소요 시간 표시 · 막차 안내 |
| 패스·렌터카 | 종류 · 상태 · 이용 지역 · 구매·예약 링크 | 렌터카 서류 확인 |
| 동행자 | 참여 상태 · 역할 | 정산 현황 · 할 일 진행률 · 준비물 진행률 |
| 분담 | 거래 · 부담자 · 계산 방식 · 계산 기준액 · 기준액 확인 | 부담액 안내 · 원거래 대조 · 분담 진단 |
| 정산 송금 | 보낸 사람 · 받은 사람 · 금액 · 상태 | 송금 확인 |
| 공동 결정 | 선택지·의견 · 담당자 · 기한 · 상태 | 없음 |
| 할 일 | 상태 · 기한 · 담당 여행자 | 기한 안내 · 담당 확인 |
| 날씨 | 대상 기간 · 날씨 링크 · 정보 상태 | 기온 안내 · 강수 안내 · 다음 확인 안내 |
| 자료 | 자료 링크 · 첨부 · 종류 | 정보 점검 |
| 일정 검사 | 기준 일정 · 비교 일정 | 시간 겹침 · 이동 여유 |

특수 항목의 인원·환율·현지 시간대·시각 확인·취소 조건 등은 필요해진 시점에 기존 전용 탭에서 받는다. 숨겼다는 이유로 검증을 생략하거나 미정 값을 확정하지 않는다. 가벼운 입력과 정확한 계산을 함께 유지한다.

## 검수

저장된 레이아웃과 표시 열을 다시 읽고, 기본 입력에 수식/롤업이 없는지, 누락된 보조 속성이 자동 노출되지 않는지, 기존 여행·취소·제외 필터가 남았는지 확인한다. 금액·예약·일정의 기존 값과 계산식은 UI 정리만을 위해 바꾸지 않는다. 실제 앱/모바일 화면을 확인하지 못하면 시각 검수를 완료했다고 말하지 않는다.

## Souvenir가 하는 일

- 목적지와 날짜·기간만으로 여행 페이지를 시작합니다.
- 여행 개요, 일정, 항공, 숙소, 장소, 쇼핑, 예산, 준비물을 대화로 채웁니다.
- 여행 중에는 오늘·다음 일정, 예약, 숙소, 지갑 잔액을 확인 화면에서 빠르게 봅니다.
- 기존 메모·예약·다른 날짜는 보존하고, 요청한 항목만 변경합니다.
- 자동 계산 결과와 직접 입력 항목을 분리해 Notion 화면을 단순하게 유지합니다.
- Google Maps 일반·공유 링크를 읽어 장소명을 채우고, 만료된 링크는 잘못 저장하지 않고 `확인 필요`로 멈춥니다.
- 쇼핑 품목명만 받아도 목적지 기준으로 후보를 조사하고, 가격·수량·구매 장소·출처를 확인받은 뒤 사람별 목록에 저장합니다.
- 장소를 여러 개 한 번에 받아도 목적지와 맞는지 확인하고, 이상하거나 근거가 없는 장소는 사용자 확인 전까지 저장하지 않습니다.
- 백지에서 장소를 찾을 때는 추천순 후보를 최대 10곳씩 보여주고, 더 필요하다고 답했을 때만 다음 10곳을 이어서 보여줍니다. 10곳보다 적으면 찾은 수만 표시합니다.
- 로컬 실행기에 Google Places API 키를 직접 연결한 경우에도 같은 흐름으로 검색할 수 있습니다. 키는 환경변수로만 읽고 Notion이나 후보 데이터에 저장하지 않습니다.
- Google 검색 결과는 후보 화면에서만 보여주며, API 결과를 그대로 복사·재배포하지 않습니다. 저장할 때는 사용자가 정한 표시명과 `place_id`·Google Maps 링크만 사용하고 `Google Maps` 출처 고지를 유지합니다. [Google Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies)에 맞지 않는 사진·리뷰 저장은 하지 않습니다.
- 장소 검색 후보는 별도 Notion 후보 DB를 만들지 않고 임시 검토 카드로만 유지합니다. 승인한 장소만 `장소 보관함`의 `확인 완료 갤러리`에 들어가며, 구형 복제본에는 `장소 ID`·`정보 상태`·`검색 제공자`·`확인일` 내부 속성을 누락된 것만 추가합니다.
- 항공·숙소·장소·쇼핑에 첨부한 사진이나 이미지 URL을 해당 DB의 `사진` 파일 속성과 `사진 URL`에 함께 저장해 카드·갤러리에서 바로 보여줍니다. 기존 사진은 교체 요청 전까지 보존합니다.
- 기존 복제본이 `장소 사진`·`숙소 사진`처럼 예전 열 이름을 사용해도 자동으로 감지해 같은 사진 열에 저장하며, 항공처럼 사진 열이 없던 복제본에는 업그레이드 시 필요한 파일 속성만 추가합니다.

## 빠른 시작

> **현재 배포 상태**
> 최신 Notion 디자인은 공개·복제 가능한 **단일 링크 배포본**에 반영되어 있습니다. Souvenir는 이 템플릿의 원본 또는 사용자가 복제한 사본만 사용하며, 사본 확인 전에는 여행 계획을 만들지 않습니다.

### Codex CLI

```bash
codex plugin marketplace add Jaws8078/souvenir --ref main
codex plugin add souvenir@souvenir-marketplace
```

새 채팅에서 다음 중 하나를 입력합니다.

```text
$souvenir
Souvenir로 후쿠오카 3박 4일 여행 계획을 시작해줘.
```

### ChatGPT 데스크톱

1. Plugins Directory를 엽니다.
2. `Add Marketplace` 또는 `Add from repository`를 선택합니다.
3. `https://github.com/Jaws8078/souvenir`를 입력합니다.
4. Souvenir를 설치하고 새 Work 채팅에서 `@Souvenir`를 선택합니다.

### 첫 실행 흐름

Souvenir는 Notion 연결을 먼저 확인합니다. 연결이 없으면 공식 연결 UI에서 승인한 뒤 같은 대화에서 재개합니다. 연결이 확인되면 계정과 현재 워크스페이스 이름을 먼저 보여주고, 사용자가 진행을 확인한 뒤에만 템플릿과 여행 데이터를 엽니다.

1. Notion 연결·로그인 확인
2. 연결된 계정·워크스페이스 확인
3. 현재 워크스페이스에 제공 템플릿이 있는지 검사
4. 없으면 한 번 허락을 받고 복제 시도
   - 먼저 로컬 Notion 앱 설치·실행 가능 여부를 확인
   - 로컬 앱이 있으면 앱 안에서 로그인·Duplicate·워크스페이스 선택을 진행하고 웹은 열지 않음
   - 로컬 앱이 없거나 사용할 수 없을 때만 CUA 브라우저 또는 수동 링크 경로로 전환
5. 복제본 URL·ID·필수 섹션 재검사
6. 여행지·출발일·종료일(또는 기간)·인원·기준 통화 입력
7. 필요한 계획 파트 선택
8. 변경안을 확인한 뒤 Notion에 반영

처음에는 `$souvenir`만 입력해도 되고, 메뉴에서 `1. 여행 플래너 만들기`, `2. 새 여행 계획`, `3. 기존 일정 수정`을 선택할 수 있습니다.

### 대화 방식

Souvenir는 긴 설문 대신 **현재 단계 → 최소 질문 → 한 개의 자연스러운 예시 → 다음 할 일** 순서로 안내합니다. 파트 시작 때 꼭 필요한 입력과 저장할 표만 보여주고, 사진·메모·상태 같은 선택 필드는 원할 때만 펼칩니다. 이미 받은 정보는 다시 묻지 않으며 `미정`·`건너뛰기`도 허용합니다. 모든 메시지는 마지막에 `다음 할 일:`을 표시하므로 사용자는 답변이나 선택지만 보내면 됩니다.

## 핵심 기능

| 영역 | 제공 기능 |
| --- | --- |
| 🗺️ 계획·장소 | 날짜별 일정, 장소 보관함, 날씨·플랜 B/C, 선택형 쇼핑 목록 |
| 🎟️ 이동·예약 | 항공 후보, 현지 이동, 숙소 후보·확정 숙소, 예약 상태 |
| 💴 예산·동행 | 여행 지갑, 실제 지출, 잔액·사용률, 인원별 분담·정산 |
| 🎒 준비·자료 | 준비할 일, 준비물, 담당자·기한, 예약 확인서·중요 자료 |

입력 속성과 자동 결과를 분리합니다. 사용자는 필요한 기본 항목만 작성하고, 잔액·기간·진행률·확인 결과는 수식과 계산으로 표시됩니다. 항공권과 숙소 가격은 원화(KRW)로 관리하며, 확인 근거 없는 환율·날씨·운영 정보는 `확인 필요`로 남깁니다.

### 반영 중에도 현재 작업을 보여줌

`반영`을 누른 뒤에는 Souvenir가 아무 설명 없이 기다리게 하지 않습니다. 현재 파트와 함께 `입력·관계 확인 → 대상 DB·기존 행 확인 → 변경안 반영 → 저장 결과 재조회` 순서로 짧게 진행 상황을 알려줍니다. 오래 걸리는 경우에는 중복 메시지 대신 같은 단계의 지연 상태를 한 번만 갱신하고, 오류가 나면 완료로 표시하지 않고 중단 단계와 필요한 조치를 안내합니다. 진행 메시지의 끝에도 다음 단계가 표시됩니다.

오류·충돌·저장 여부 불명확 상태는 자동으로 덮어쓰거나 재전송하지 않습니다. 입력 오류, Notion 권한·네트워크 오류, 동시 수정 충돌, 템플릿 복제 실패를 구분해 중단하고 `다시 확인`·`입력 수정`·`취소` 중 다음 행동을 제시합니다. 저장 여부가 불확실하면 실제 Notion 결과를 확인한 뒤에만 재개합니다. 자세한 규칙은 [오류와 예외 처리](skills/souvenir/references/error-handling.md)에 정리되어 있습니다.

반영이 끝난 뒤에는 전체 여행 페이지를 반복해서 보여주지 않습니다. 실제로 수정된 일정·항공·숙소·장소·쇼핑·지갑·준비물의 **파트 블록 페이지 링크**만 우선 제공합니다. 데이터베이스 자체 링크는 보여주지 않으며, 전체 여행 링크는 새 여행을 만들었을 때나 사용자가 요청한 경우에만 덧붙입니다.

저장한 모든 파트는 같은 여행 키와 관계로 **여행 중 확인 존**에 연결합니다. 여행 요약·오늘/다음 일정, 항공·현지 이동, 숙소·예약, 장소·날씨/플랜 B/C, 사람별 쇼핑, 지갑·예산·사용 내역·정산, 동행자·취향, 준비할 일·준비물·자료가 각 확인 카드에 표시되어야 저장 완료로 처리합니다. 확인 존에 보이지 않는 항목은 완료로 안내하지 않고 해당 파트만 다시 연결·검증합니다.

### 입력은 표별로 나눠 저장

각 파트를 시작할 때 Souvenir가 그 파트의 **최소 입력 항목과 저장할 표**를 먼저 보여줍니다. 전체 저장 필드는 상세 입력에서 확인할 수 있고, 답변은 한 번에 한 항목씩 받아도 됩니다. 모르는 값은 `미정`으로 둘 수 있습니다. 사람별 취향은 `여행자 · 역할 · 먹고 싶은 음식 · 선호 이동 · 숙소 취향 · 주의사항 · 추가 요청`을 각각 동행자 표의 독립 열에 저장하며, `의견·요청` 한 칸으로 합치지 않습니다. 일정·항공·숙소·장소·쇼핑·예산·준비물도 같은 방식으로 입력 필드와 DB 속성을 일대일로 연결합니다. 저장 전에는 변경 요약을 보여주고 `반영`을 받은 뒤 실제 행을 다시 확인합니다.

질문은 기본 입력만 먼저 받습니다. 여행은 목적지·기간·인원·통화, 장소는 장소·지역·종류·지도 링크, 쇼핑은 품목·담당자·구매 장소·수량·예상 금액처럼 시작에 필요한 값만 묻고, 사진·메모·상태·검증 정보는 필요할 때만 펼칩니다. 비어 있는 값은 `미정`으로 두며 자동 결과 속성은 입력받지 않습니다.

로컬 실행기를 지원하는 환경에서는 사용자가 코드를 입력하지 않아도 스킬이 이 계약을 읽습니다. 개발자가 필드 목록만 확인하려면 다음처럼 실행할 수 있습니다.

```bash
python3 skills/souvenir/scripts/run_souvenir.py fields --part "여행 개요·취향" --pretty
```

레거시 입력에 `의견·요청`만 남아 있으면 의미를 추측해 나누지 않고, 역할·음식·이동·숙소·주의사항·추가 요청을 다시 확인합니다.

fallback 설치 경로에서도 같은 계약을 사용합니다. 일정·항공·숙소·장소·예산·준비물은 승인된 정규화 행을 각 DB에 저장하고, 기존 여행의 일차·준비 항목은 중복 생성하지 않고 갱신합니다. 복제 템플릿의 실제 스키마를 다시 읽어 `여행` 관계와 `구분=사용 중` 표시를 함께 반영하므로, 저장된 행이 예전 샘플 필터에 가려지지 않습니다. 사용자는 명령이나 JSON을 직접 입력할 필요가 없고, 호스트가 저장 전 요약과 `반영` 확인을 받은 뒤 실행합니다.

### 지갑은 다섯 칸만 입력

사용 내역의 기본 입력은 `사용처 · 거래 유형 · 결제 단계 · 결제 수단 · 금액`입니다. 사용 금액은 연결된 지갑에서 자동 차감되고, `사용액 · 남은 금액 · 사용률`은 읽기 전용 결과로 표시됩니다. 예정 비용은 실제 지출과 분리합니다.

### 쇼핑은 이름만으로 임의 저장하지 않음

쇼핑은 `품목명 · 예상 총액 · 수량 · 구매 장소`가 기본 입력입니다. 품목명만 입력하면 Souvenir가 목적지와 함께 웹·이미지·제공 링크를 조사해 후보와 출처를 먼저 보여줍니다. 사용자가 승인한 후보만 `사용자 확인 완료`로 사람별 쇼핑 DB에 저장하고, 저장 후 현재 여행의 실제 행을 다시 확인합니다. 가격·수량·구매 장소가 확인되지 않은 후보는 저장하지 않습니다.

## 여러 사람이 동시에 사용할 때

같은 여행을 여러 세션에서 동시에 수정해도 다음 보호 장치가 작동합니다.

- 여행별 잠금과 작업 lease로 한 번에 하나의 쓰기만 진행
- 작업 키로 중복 생성 방지
- 저장 직전 버전 충돌 확인으로 다른 사람의 최신 수정 보존
- 충돌한 항목만 다시 확인하고, 메모·예약·다른 날짜는 유지

```text
현재 이 여행에 다른 반영 작업이 진행 중입니다.
기존 작업이 끝난 뒤 다시 시도해주세요.
```

혼자 사용하는 경우에는 이 보호 기능이 거의 보이지 않습니다. 여러 컴퓨터에서 같은 여행을 함께 편집하는 환경은 선택형 coordinator로 작업 순서를 조정할 수 있습니다. 자세한 설계는 [동시성 대응 메모](docs/concurrency-roadmap.md)에서 확인할 수 있습니다.

## 템플릿 사용

### 권장: Notion 링크 배포본 복제

Souvenir의 디자인 원본은 Notion 템플릿입니다. [Souvenir 링크 배포본](https://rift-volcano-c77.notion.site/Souvenir-4171036c4e4280928564d129600f6472?source=copy_link)을 열고 Notion에서 **복제**하면 원본의 커버·레이아웃·DB 뷰를 가장 충실하게 사용할 수 있습니다. 현재 배포본은 개인 여행·예약·지출 데이터와 이전 `새 여행` 연결을 제거한 빈 시작 상태입니다.

사용자는 링크를 연 뒤 **복제**만 하면 됩니다. 별도 마켓 등록은 필요하지 않습니다. 링크 소유자는 `공유 → 웹에 게시 → 복제 허용`을 켜고, 비공개 작업 원본·예약·지갑·개인 메모는 공개하지 않습니다. 배포 링크는 [`template-source.json`](skills/souvenir/assets/template-source.json)에 관리합니다.

`@souvenir`를 호출하면 이 링크가 자동으로 기준 템플릿으로 고정됩니다. 현재 워크스페이스에서 기준 템플릿 사본이 발견되면 그대로 재사용합니다. 사본이 없으면 먼저 한 번 허락을 받고 **로컬 Notion 앱 설치·실행 가능 여부를 먼저 확인합니다.** 로컬 앱이 있으면 웹 브라우저를 열지 않고 앱 안에서 로그인·`Duplicate`·워크스페이스 선택을 진행합니다. 로컬 앱이 없거나 사용할 수 없다고 확인된 경우에만 CUA 브라우저가 링크를 열어 `Duplicate`와 워크스페이스 선택을 진행하거나, CUA가 없으면 사용자가 링크에서 직접 `Duplicate`를 누릅니다. 어느 경로든 복제 후 URL·페이지 ID·필수 섹션을 다시 확인한 뒤에만 여행 데이터를 저장합니다. 일반 실행에서는 다른 템플릿이나 코드 청사진으로 대체하지 않습니다.

복제 capability와 현재 게이트 상태는 호스트용 로컬 실행기로도 확인할 수 있습니다. 사용자가 명령을 입력할 필요는 없으며, Codex·ChatGPT 호스트가 다음 결과를 읽어 브라우저·Notion 도구를 호출합니다.

```bash
python3 skills/souvenir/scripts/run_souvenir.py template-gate plan \
  --capability browser_automation --pretty

# 로컬 Notion 앱 설치 여부만 읽기 전용으로 점검
python3 skills/souvenir/scripts/run_souvenir.py template-gate plan \
  --local-status --pretty
```

첫 번째 명령은 브라우저를 직접 열지 않습니다. 기본 상태에서는 `check_local_notion`을 먼저 반환하고, 로컬 점검 결과가 `installed`일 때 `duplicate_local_app`만 반환합니다. 로컬 앱이 `unavailable` 또는 `unusable`로 확인된 경우에만 `duplicate_browser` 또는 `wait_for_manual_duplicate`로 내려갑니다. 실제 클릭·로그인·MFA는 호스트와 사용자가 처리합니다.

### 템플릿 업데이트 순서

템플릿을 바꿀 때는 다음 순서를 지킵니다.

1. 비공개 Notion 원본을 수정합니다.
2. 개인 데이터와 테스트 행을 제거한 링크 배포본에 같은 변경을 반영합니다.
3. 같은 링크를 유지한 채 README와 스킬 규칙이 새 입력·뷰를 설명하는지 확인합니다.

이미 복제한 사용자의 사본은 원본 링크가 자동으로 갱신되지 않습니다. 새 사용자는 같은 링크에서 최신본을 복제하고, 기존 사본은 필요한 변경만 직접 반영합니다.

### 개발자 전용: 링크 없이 코드로 재구축

일반 사용 흐름에는 포함되지 않습니다. 링크 템플릿과 별도로 코드 재구축을 점검해야 하는 개발자만 사용합니다.

```bash
python3 skills/souvenir/scripts/notion_installer.py validate
python3 skills/souvenir/scripts/notion_installer.py plan --pretty
export NOTION_TOKEN="secret_..."
python3 skills/souvenir/scripts/notion_installer.py install \
  --parent-page "<대상 상위 페이지 URL 또는 ID>"
```

이 경로는 비식별 매니페스트로 구조를 새로 만들며, Notion 네이티브 복제처럼 원본의 모든 폭·뷰·관계·수식을 픽셀 단위로 보존한다고 약속하지 않습니다. 토큰은 채팅·GitHub·매핑 파일에 넣지 않습니다.

## 업데이트와 문제 해결

Git으로 설치했다면 저장소에서 최신 버전을 받습니다.

```bash
cd souvenir
git pull
```

플러그인 코드와 Notion 템플릿은 별도로 업데이트됩니다. GitHub/마켓플레이스 업데이트는 대화 규칙과 Python 엔진을 갱신하고, 링크 배포본 업데이트는 새로 복제하는 사본에 반영됩니다. 기존 Notion 사본의 내용은 자동으로 덮어쓰지 않습니다.

- `$souvenir`가 인식되지 않으면 Codex에서 저장소 루트 폴더를 엽니다.
- Notion 페이지가 만들어지지 않으면 Notion 연결과 대상 워크스페이스 쓰기 권한을 확인합니다.
- 설치가 중단되면 매핑 파일을 지우지 말고 `$souvenir`를 다시 실행합니다. 중단 지점부터 재개합니다.
- 저장 여부가 불명확하다는 안내가 나오면 Notion에서 실제 생성 여부를 먼저 확인합니다.

## 선택 기능: Python 여행 엔진

Codex·Claude Code·Gemini처럼 로컬 실행기를 지원하는 환경에서는 사용자가 Python 명령을 입력하지 않아도 Souvenir가 필요할 때 엔진을 호출합니다. 일정 충돌·이동 여유·예산·파일 입력·오늘/다음 일정 확인을 계산하며, 기본적으로 먼저 결과를 보여주고 승인 후 Notion에 반영합니다.

로컬 실행기 상태는 다음 명령으로 확인할 수 있습니다.

```bash
python3 skills/souvenir/scripts/run_souvenir.py --status
```

ChatGPT 웹·모바일처럼 로컬 실행기가 없는 환경에서도 Notion 연결과 대화형 계획 기능은 사용할 수 있습니다.

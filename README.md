## 빠른 시작

Souvenir는 별도 앱이 아니라 **Notion 연결을 사용하는 로컬 실행형 플러그인/스킬**이에요. 처음 한 번 플러그인을 설치하고 Notion 워크스페이스를 연결하면, 이후에는 사용자가 명령어나 Python 코드를 입력하지 않고 여행을 자연어로 관리할 수 있어요.

### 1. Codex에 설치하기 (권장)

Codex CLI에서 아래 두 명령을 한 번만 실행해요.

```bash
codex plugin marketplace add Jaws8078/souvenir --ref main
codex plugin add souvenir@souvenir-marketplace
```

설치가 끝나면 새 채팅에서 아래처럼 호출해요.

```text
$souvenir
```

또는 아래처럼 바로 요청해도 돼요.

```text
Souvenir로 후쿠오카 3박 4일 여행 계획을 시작해줘.
```

플러그인은 `requires_local_executor`를 사용하므로, 로컬 실행기를 지원하는 Codex·Claude Code·Gemini에서는 일정 검사·예산 계산·여행 중 새로고침을 내부적으로 실행해요. 사용자가 `python3` 명령을 직접 입력할 필요는 없어요.

### 2. ChatGPT 데스크톱에 설치하기

1. Plugins Directory를 열어요.
2. `Add Marketplace` 또는 `Add from repository`를 선택해요.
3. `https://github.com/Jaws8078/souvenir`를 입력하고 동기화해요.
4. **Souvenir**를 설치하고 새 Work 채팅을 시작해요.
5. 입력창에서 `@`를 눌러 **Souvenir**를 선택하거나 표시되는 시작 문구를 사용해요.

ChatGPT 웹·모바일처럼 로컬 실행기를 제공하지 않는 환경에서는 Notion 플러그인과 대화형 계획 기능을 사용할 수 있지만, Python 엔진 자동 호출은 지원되지 않아요.

### 3. Notion을 한 번 연결하기

첫 `$souvenir` 호출 때 Souvenir가 짧은 읽기 요청으로 연결 상태를 자동 확인해요. 연결되어 있으면 바로 다음 단계로 넘어가고, 연결되지 않았으면 공식 Notion 연결 UI를 보여준 뒤 사용자의 승인만 기다려요.

1. Notion 연결 화면에서 로그인하고 워크스페이스 권한을 승인해요.
2. 템플릿 설치 여부를 확인해요.
3. Marketplace 템플릿을 사용한다면 Notion에서 한 번 `복제`해요.
4. Souvenir가 복제된 페이지와 데이터베이스를 연결해요.

비밀번호·쿠키·Notion 토큰을 채팅에 입력하지 않아요. Souvenir가 다른 플러그인을 사용자 모르게 설치하거나 OAuth 권한을 대신 승인하지는 않아요. 현재 호스트에 Notion 플러그인 자체가 없으면 먼저 Notion 플러그인을 연결한 뒤 같은 채팅에서 `다시 확인`이라고 하면 이어서 진행해요. 플러그인 설치와 Notion 템플릿 복제는 워크스페이스마다 한 번씩 필요해요.

### 자동 설치기를 사용하는 경우 (선택)

저장소 폴더를 이미 열었거나 Codex CLI가 있는 환경에서는 설치기가 현재 환경만 확인하고, 사용자가 선택한 경우에만 등록을 실행해요.

```bash
python3 skills/souvenir/scripts/install_souvenir.py
python3 skills/souvenir/scripts/install_souvenir.py --apply
```

설치기는 비밀번호·쿠키·Notion 토큰을 읽지 않아요. 설치 후에는 새 채팅에서 `$souvenir`를 호출하면 돼요.

### 플러그인을 설치할 수 없는 환경

저장소를 직접 열어도 같은 스킬을 사용할 수 있어요.

```bash
git clone https://github.com/Jaws8078/souvenir.git
cd souvenir
```

Codex에서 `souvenir` 폴더를 프로젝트로 열고 새 채팅에서 `$souvenir`를 호출해요. 저장소 안의 `.agents/skills/souvenir/SKILL.md`가 공통 스킬을 가리켜요.

### 플러그인 설치 후 첫 실행

플러그인을 설치하면 Souvenir가 먼저 Notion 연결 상태를 확인해요. 연결이 없으면 공식 Notion 연결 화면에서 승인하고, 로그인 상태를 확인한 뒤 템플릿 설치 단계로 넘어가요.

Notion 템플릿을 Marketplace에 등록하면 **플러그인 관리자가** [`skills/souvenir/assets/template-source.json`](skills/souvenir/assets/template-source.json)의 `template_url`에 공개·복제 가능한 링크를 넣고 버전을 올려요. 사용자가 이 파일을 직접 수정할 필요는 없어요. 업데이트된 플러그인을 설치하면 새 워크스페이스에서 이 링크가 첫 번째 설치 경로가 되고, 사용자가 Notion에서 한 번 `복제`한 사본을 Souvenir가 연결해요. 링크가 아직 배포되지 않았거나 복제를 거절하면 내장 청사진은 보조 경로로만 사용해요.

플러그인 설치와 Notion 템플릿 복제는 별개예요. 플러그인은 한 번 설치하면 새 채팅에서 재사용할 수 있지만, 각 Notion 워크스페이스의 연결·로그인·최초 복제 승인은 사용자가 한 번 진행해야 해요.

### 저장소 직접 열기 상세 단계

플러그인 설치가 표시되지 않는 환경에서는 아래 방식으로 사용해요.

#### 1. 저장소 받기

Git이 있다면 터미널에서 실행해요.

```bash
git clone https://github.com/Jaws8078/souvenir.git
cd souvenir
```

Git을 처음 쓰거나 설치할 수 없다면 GitHub의 **Code → Download ZIP**으로 받아 압축을 풀어도 돼요. 다만 ZIP 방식은 업데이트할 때 다시 내려받아야 하므로 Git clone을 권장해요.

#### 2. Codex에서 폴더 열기

Codex에서 방금 받은 `souvenir` 폴더를 프로젝트로 열어요. 저장소 안의 `.agents/skills/souvenir/SKILL.md`를 통해 스킬이 자동으로 검색돼요. 인식이 늦으면 폴더를 닫았다가 다시 열거나 새 채팅을 시작해요.

#### 3. Notion 연결하기

Codex에서 Notion 플러그인을 연결하고, 템플릿을 만들 워크스페이스에 접근 권한을 줘요. 첫 설치에는 페이지와 데이터베이스를 만들 수 있는 쓰기 권한이 필요해요.

#### 4. 첫 실행

새 채팅에서 아래처럼 입력해요.

```text
$souvenir
```

번호나 작업 이름으로 선택할 수 있어요.

| 선택 | 하는 일 |
|---|---|
| 1. 여행 플래너 만들기 | 기본 양식 또는 기존 템플릿을 사용해요. |
| 2. 새 여행 계획 | 목적지와 날짜 또는 기간만으로 시작해요. |
| 3. 기존 일정 수정 | 변경안과 영향을 먼저 보여주고 요청한 부분을 반영해요. |

예: **`$souvenir 새 여행 계획. 후쿠오카 3박 4일`**

날짜가 미정이면 1~4일차로 작성해요. 인원·예산·숙소·취향은 나중에 정해도 돼요. 저장 위치를 지정하지 않으면 비공개 초안으로 저장하고, 지정한 템플릿이 있으면 그 구조를 재사용해요.

### 파트별 계획 마법사

필수 정보가 저장되면 Souvenir가 아래 파트를 번호로 제시하고, 한 번에 하나씩 짧게 입력받아요.

1. 여행 개요·취향
2. 날짜별 일정
3. 항공
4. 숙소
5. 장소 보관함
6. 예산·여행 지갑
7. 준비물·준비할 일

추천 순서는 `여행 개요·취향 → 항공 → 숙소 → 장소 보관함 → 예산·여행 지갑 → 날짜별 일정 → 준비물·준비할 일`이에요. 각 파트에서 `미정`·`건너뛰기`를 답해도 여행은 계속 만들 수 있고, 해당 값은 `확인 필요`로 남아요. 기간이 `3박 4일`이면 일정 입력을 1~4일차로 나눠 받아요. 세부 질문 형식과 저장 규칙은 [대화형 계획 마법사](skills/souvenir/references/conversation-flow.md)에 정리돼 있어요.

항공·숙소 후보를 웹에서 찾는 경우에는 먼저 검색 동의를 받고 출처를 저장해요. 후보를 정리하는 것과 실제 예약·결제는 분리돼요. **항공권 예산·요금과 숙소 1박 비용·숙박 총액은 여행 기준 통화와 무관하게 KRW(원화)로 표시해요.** 원문이 엔화 등 다른 통화라면 확인된 환율 근거가 있을 때만 원화로 환산하고, 근거가 없으면 `확인 필요`로 남겨요. 사진·파일은 읽을 수 있는 정보만 반영하고, 확인하지 못한 필드는 비워 둬요.

### 템플릿 설치가 끝나면

처음 연결한 워크스페이스에서는 원본 페이지를 채팅에 붙여넣을 필요가 없어요. `template_url`이 배포된 버전이면 사용자가 Notion에서 템플릿을 `복제`하고, Souvenir가 새 사본의 페이지·데이터베이스를 연결해요. 아직 링크가 없는 버전에서는 내장 청사진으로 `Souvenir · 여행 대시보드`, 네 묶음 화면, 관계형 데이터베이스와 기본 뷰를 보조 생성해요. 템플릿 설치가 끝난 뒤에는 아래처럼 바로 시작하면 돼요.

```text
$souvenir 새 여행 계획. 후쿠오카 3박 4일
```

설치 기록이 있으면 기존 구조를 재사용하고, 사용자가 별도 템플릿 링크를 주면 그 템플릿을 우선해요.

### 방법 C · 링크 없이 코드로 재구축하기 (선택)

공개 템플릿 링크를 사용할 수 없거나, 각 워크스페이스에 구조를 새로 만들고 싶다면 저장소의 공식 Notion API 설치기를 사용할 수 있어요. 원본 비공개 페이지를 읽거나 복사하지 않고, 저장소에 포함된 **비식별 fallback 매니페스트**로 새 구조를 만들어요. 디자인의 기준은 코드가 아니라 Notion Marketplace 템플릿이에요.

```bash
python3 skills/souvenir/scripts/notion_installer.py validate
python3 skills/souvenir/scripts/notion_installer.py plan --pretty
export NOTION_TOKEN="secret_..."
python3 skills/souvenir/scripts/notion_installer.py install \
  --parent-page "<대상 상위 페이지 URL 또는 ID>"
```

`NOTION_TOKEN`은 Notion에서 직접 만든 공식 통합 토큰을 로컬 환경 변수로만 사용하고, 채팅·GitHub·`.souvenir-install.json`에는 넣지 않아요. 대상 상위 페이지에는 해당 통합을 연결하고 페이지/데이터베이스 생성 권한을 줘야 해요. 설치 결과는 대상 ID 매핑과 `template_source=code_rebuild`를 `.souvenir-install.json`에 남겨 중단 후 재개할 수 있어요.

### Python 여행 엔진과 로컬 자동 호출

플러그인은 로컬 실행기를 요구하도록 등록되어 있어요. Codex·Claude Code·Gemini처럼 로컬 실행이 가능한 환경에서는 사용자가 Python 명령을 직접 입력하지 않아도 Souvenir가 필요할 때 [Python 여행 엔진](skills/souvenir/references/python-engine.md)을 호출해요. 템플릿을 바꾸지 않고 일정·예산·파일 입력·여행 중 확인을 자동화할 수 있어요. `check`는 일정 겹침·이동 여유·예약 기한·오래된 장소 정보를 검사하고, `budget`은 지갑 잔액·사용률·분담 송금을 계산하며, `organize`와 `import`는 짧은 일정 문장·지도 링크·CSV·JSON·iCalendar 파일을 Notion 입력용 행으로 정리해요. `refresh`는 오늘/다음 일정·기한·숙소·지갑을 읽기 전용 JSON으로 만들어요.

첫 실행 상태 확인과 각 엔진 호출은 스킬이 내부적으로 처리해요.

```bash
python3 scripts/run_souvenir.py --status
```

이 명령은 개발자나 로컬 fallback 환경에서만 직접 사용할 수 있고, 일반 사용자는 `$souvenir`와 자연어 요청만 입력하면 돼요.

```bash
python3 skills/souvenir/scripts/trip_engine.py check --input trip.json --pretty
python3 skills/souvenir/scripts/trip_engine.py budget --input trip.json --base-currency JPY --rate JPY=0.009 --pretty
python3 skills/souvenir/scripts/trip_engine.py refresh --input trip.json --now 2026-12-12T09:00:00 --pretty
```

Notion fallback 설치 기록이 있으면 로컬 실행기가 `NOTION_TOKEN`, `--mapping`, `--trip-id`를 로컬에서만 지정해 관련 DB를 읽을 수 있어요. 검사·계산·새로고침은 기본적으로 쓰기 작업을 하지 않으며, 결과를 확인한 뒤 Souvenir가 필요한 부분만 반영해요. 로컬 실행기는 사용자의 요청 중에만 호출되며 백그라운드에서 계속 실행되지 않아요. 로컬 실행기가 없는 ChatGPT 웹·모바일 환경에서는 Python 엔진 자동 호출 없이 Notion 플러그인 흐름을 사용해요.

설치 후 API fallback에서 필수 정보와 일차 구조를 한 번에 만들려면 `scaffold`를 사용할 수 있어요. 출발일·종료일을 주면 실제 날짜가 일차에 채워지고, 기간만 주면 날짜 없이 일차만 준비돼요. 여행 인원이 있으면 동행자 행도 만들고, 기본 준비할 일 15개·준비물 8개·지갑 1개를 같은 여행 키로 연결해요.

```bash
python3 skills/souvenir/scripts/notion_installer.py scaffold \
  --mapping .souvenir-install.json \
  --destination 후쿠오카 \
  --start-date 2026-12-12 \
  --end-date 2026-12-15 \
  --travelers 4 \
  --currency JPY \
  --pretty
```

날짜 대신 `--duration-days 4`를 사용할 수도 있어요. 출발일과 기간을 함께 주면 종료일을 계산하고, 기간만 주면 실제 날짜는 비워 둬요. 같은 목적지·날짜·기간·인원·통화·여행 이름으로 다시 실행하면 저장된 결과를 재사용해요. 같은 조건으로 별도 여행을 만들려면 `--trip-name`을 다르게 지정하세요. 이 명령은 Marketplace 템플릿을 대체하지 않고, 링크를 사용할 수 없는 환경을 위한 API fallback이에요.

설치·여행 생성은 성공한 페이지·행·본문 묶음마다 기록을 저장해요. 확실히 실패한 요청은 다음 실행에서 해당 지점부터 재개하고, 통신 중단처럼 저장 여부가 불분명한 요청은 `pending_operation`을 남기고 멈춰요. 이때는 대상 Notion에서 실제 생성 여부를 확인해 매핑을 복구한 뒤 재개해야 해요. 설치 기록을 지우고 다시 실행하면 중복 생성될 수 있어요.

워크스페이스나 상위 페이지가 다르면 `--mapping .souvenir-install-other.json`처럼 별도 파일을 사용하세요. 같은 매핑으로 여러 설치 프로세스를 동시에 실행하지 마세요. 설치 중 매니페스트가 달라지면 원래 버전으로 재개하거나 새 매핑을 사용해요. 매핑 파일은 개인별 생성 ID와 여행 입력값을 담으므로 Git에 올리지 않아요.

이 경로는 대시보드·네 묶음·20개 핵심 데이터베이스·입력 속성을 재생성해요. Notion의 네이티브 `복제`처럼 원본의 모든 관계·수식·뷰 배치·커버를 픽셀 단위로 보존하는 방식은 아니므로, 설치 후 Souvenir가 대상 워크스페이스에서 상세 뷰와 계산을 이어서 구성해요. 최고 충실도가 필요하면 공개·복제 가능한 Marketplace 템플릿에서 사용자가 직접 `Add` 또는 `Duplicate`하는 방법을 우선해요.

코드 재구축 경로도 사람별 취향 필드, 항공 후보 입력, 숙소 후보 비교, 장소 출처·사진 링크, 자료 파일 링크, 기본 준비할 일 15개와 준비물 8개를 함께 만들어요. 기본 행은 특정 여행에 연결하지 않은 `원본 구분=기본` 상태라서, 새 여행을 만들 때 필요한 항목만 복사해 사용해요.

### 템플릿을 수정할 때의 순서

1. Notion의 비공개 작업 원본을 먼저 정리해요.
2. 배포용 사본과 Marketplace 템플릿을 업데이트해요.
3. 공개 템플릿 URL을 `template-source.json`에 넣고 플러그인 버전을 올려요.
4. 바뀐 화면·속성·뷰에 맞춰 `SKILL.md`의 작성/확인 규칙과 README를 수정해요.
5. 링크 없는 환경도 지원해야 할 때만 `template-manifest.json`과 Python fallback을 같은 구조로 갱신해요.

즉, **Notion 템플릿 → 스킬 규칙 → 코드 fallback** 순서가 기준이에요. 코드가 Notion 디자인을 거꾸로 결정하지 않아요.

## 업데이트하기

Git clone으로 설치했다면 저장소 폴더에서 실행해요.

```bash
cd souvenir
git pull
```

그 다음 Codex에서 새 채팅을 시작하면 최신 스킬 규칙과 내장 템플릿 청사진이 반영돼요. ZIP으로 설치했다면 최신 ZIP을 다시 받아 기존 폴더를 교체해요. Notion에 이미 만든 여행 데이터는 업데이트로 삭제하지 않아요.

### Notion 앱이 설치되어 있을 때

첫 실행에서는 먼저 컴퓨터 제어 기능이 있는지 확인해요.

- Notion 데스크톱 앱이 확인되면 앱을 열거나 이미 실행 중인 창을 활성화해요.
- 앱이 없거나 열기에 실패하면 `https://www.notion.so`를 브라우저에서 열어요.
- CUA·앱 실행 기능이 없는 환경에서는 앱을 열었다고 말하지 않고, 공식 Notion 연결 UI나 홈페이지 주소를 안내해요.
- 앱이 열려 있어도 로그인 완료로 간주하지 않고 Notion 연결 상태를 다시 확인해요.

이 분기는 `notion_installer.py`가 아니라 Souvenir 온보딩의 실행 전 점검이에요. 앱 실행이 지원되지 않는 환경에서도 기존 연결·로그인 안내와 웹 fallback은 계속 사용할 수 있어요.

## 문제가 생기면

- `$souvenir`가 인식되지 않으면 Codex에서 저장소 **루트 폴더**를 열었는지 확인해요.
- `.agents/skills/souvenir/SKILL.md` 파일이 있는지 확인해요.
- Notion 페이지가 만들어지지 않으면 Notion 연결 상태와 대상 워크스페이스의 쓰기 권한을 확인해요.
- 설치가 중단되면 다시 `$souvenir`를 실행해요. `Souvenir · 설치 기록`을 읽고 누락된 단계부터 이어가요.

## 다른 워크스페이스에서 시작해요

다른 워크스페이스에서 처음 `$souvenir`를 실행하면 아래 순서로 한 번만 진행해요.

1. **Notion 플러그인 연결** — 연결되지 않았으면 비밀번호를 채팅에 입력하지 말고 Notion 연결을 완료한 뒤 다시 실행해요.
2. **Souvenir 스킬 연결** — `$souvenir`가 활성화되지 않았다면 저장소 루트를 Codex에서 열고 스킬을 다시 호출해요.
3. **Notion 로그인 확인** — 연결된 Notion 화면에서 로그인이 필요하면 로그인 후 같은 채팅에서 재개해요. 비밀번호·쿠키·개인 토큰은 받지 않아요.
4. **템플릿 연결** — `Souvenir · 설치 기록`을 먼저 찾아요. 기록이 없을 때만 기본 템플릿 설치 여부를 한 번 확인하고, 승인하면 공개·복제 가능한 Marketplace 링크를 우선 사용해요. 사용자가 자신의 워크스페이스에서 `복제`한 뒤 새 사본을 연결해요. 링크가 없거나 거절하면 내장 청사진으로 재구성해요.
5. **필수 정보 입력** — 여행지·출발일·종료일·인원 수·기준 통화를 받아 새 여행 요약 행에 저장해요. 모르는 값은 `미정`으로 둘 수 있지만 여행지와 날짜 또는 기간은 있어야 시작할 수 있어요.

설치 기록은 연결 전에는 만들지 않고, 템플릿 설치를 시작할 때 `진행 중`, 완료 후 `완료`로 남겨요. 중간에 멈춰도 다음 실행에서 전체 워크스페이스를 다시 훑지 않고 누락 단계부터 재개해요.

### 첫 실행 입력 예시

Souvenir가 아래처럼 물으면 한 줄로 답하면 돼요.

```text
여행지 / 출발일 / 종료일 / 인원 수 / 기준 통화
예: 후쿠오카 / 2026-12-12 / 2026-12-15 / 4명 / JPY
```

다른 입력도 가능해요.

- `오사카 / 3박 4일 / 인원 미정 / JPY` → 실제 날짜와 D-Day는 미정, 1~4일차만 준비
- `도쿄 / 출발일 미정 / 종료일 미정 / 2명 / KRW` → 날짜는 나중에 입력하고 인원·통화만 먼저 저장
- 여행지와 날짜 또는 기간을 모두 모르면 → 해당 두 값만 추가로 요청하고 여행 행은 만들지 않음

### 로그인 창은 어떻게 표시되나요?

Souvenir가 임의로 비밀번호를 받거나 브라우저를 조작하지는 않아요. Notion 연결 도구가 공식 로그인·재연결 UI를 반환하면 그 UI를 표시하고, 그런 UI를 제공하지 않는 환경에서는 아래처럼 안내한 뒤 기다려요.

> Notion 로그인이 필요합니다. Notion 화면에서 로그인한 뒤 `다시 확인`이라고 입력해주세요.

즉, 로그인 창 표시 여부는 Codex·ChatGPT의 Notion 연결 화면이 결정하고, Souvenir 스킬은 로그인 필요 상태를 감지해 작업을 멈췄다가 로그인 후 같은 단계부터 재개해요.

원본과 최대한 같은 화면을 원하면 **공개·복제 가능한 Notion 템플릿 링크**를 함께 주세요. 같은 워크스페이스 안의 페이지라면 네이티브 복제를 시도하지만, 다른 워크스페이스의 페이지는 현재 Notion 연결 도구가 직접 복제할 수 없어요. 이 경우 링크를 열고 Notion에서 `복제`를 한 번 누른 뒤, 새로 생긴 대상 사본을 Souvenir가 연결해요. 대상 사본을 만들 수 없거나 링크가 없으면 [내장 템플릿 청사진](.agents/skills/souvenir/references/template-blueprint.md)으로 새 워크스페이스에 재구성해요. 이 방식은 구조와 디자인 계약을 재현하지만 원본의 픽셀 단위 복제라고 보장할 수는 없어요.

- 원본 워크스페이스의 페이지·데이터베이스 ID, 사용자 데이터, 예시 거래는 복사하지 않아요.
- `Souvenir · 설치 기록`에 대상 워크스페이스의 페이지·데이터베이스 매핑과 템플릿 출처(`native_duplicate`, `manual_duplicate`, `blueprint_rebuild` 또는 `code_rebuild`)를 저장해요.
- 이미 설치됐거나 중간에 멈춘 경우에는 기록을 우선 사용하고, 같은 객체를 반복 생성하거나 전체 DB를 다시 검색하지 않아요.
- Notion 연결과 쓰기 권한이 없으면 설치하지 않고 필요한 권한과 구조를 안내해요.

현재 디폴트 대시보드 [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19)는 디자인 확인용 참조 원본이에요. 이 비공개 참조 링크를 배포용으로 사용하지 않아요. 다른 워크스페이스에서 원본과 같은 레이아웃이 필요하면 공개 상태에서 `복제 허용`을 켠 별도 Marketplace 템플릿 링크를 `template-source.json`에 등록해야 해요.

### 링크를 내장할 수 있나요?

가능해요. 다만 내장되는 것은 **주소**이지 Notion 페이지 자체가 아니에요.

- 공개·복제 가능한 템플릿 URL은 [`template-source.json`](skills/souvenir/assets/template-source.json)에 기본값으로 넣어요.
- 사용자의 Notion 연결과 로그인은 워크스페이스마다 별도로 필요해요.
- 다른 워크스페이스에서 자동 복제하려면 현재 연결 도구의 범위를 넘어가므로, 사용자가 링크를 열어 `복제`하는 1회 동작이 필요해요.
- 복제 후 새 사본의 URL·ID를 읽어 설치 기록에 저장하면 이후에는 다시 링크를 열지 않아도 돼요.

따라서 배포 형태는 두 가지예요. **최고 충실도**가 필요하면 공개 Notion 템플릿 링크를 스킬에 내장하고 첫 실행 때 사용자에게 한 번만 `복제`를 안내해요. 링크를 공개할 수 없거나 코드로 감사 가능한 설치를 원하면 저장소의 `template-manifest.json`과 Python 설치기를 사용해요. 코드 경로는 원본 ID·데이터를 복사하지 않고 구조를 새로 만들며, 원본의 모든 컬럼 폭·DB 뷰 배치·관계·수식을 그대로 보존한다고 보장하지 않아요.

## 입력과 결과를 구분해요

| 표시 | 사용할 때 |
|---|---|
| **✍️ 입력** | 직접 작성하는 기본 항목이에요. 대부분 제목 포함 3~5개 열만 보여줘요. |
| **🟢 자동** | 잔액·기간·진행률·확인 결과예요. 직접 입력하지 않아요. |
| **선택 입력** | 날짜·영수증·환율·객실·정산 등 필요해졌을 때만 열어요. |

진행률은 자동 계산을 기본으로 하되, 카드의 **진행도 수동 조정**에서 묶음별 `직접 완료` 또는 `자동 제외`를 선택할 수 있어요. 자동 완료 표시는 계속 계산되고, 수동 조정은 해당 여행에만 반영돼요. 두 체크가 동시에 켜지면 `직접 완료`를 우선해요.

카드를 열면 **직접 입력 → 자동 결과 → 선택 입력**으로 구역이 나뉘어요. 내부 집계·중간 계산 속성은 숨겨두었고 기존 값과 기능은 보존해요. 빈칸은 **미정**, 근거·입력을 다시 봐야 하면 **확인 필요**, 실제로 마치면 **완료**예요.

## 지갑과 사용 내역은 짧게

사용 내역 표와 상세 카드의 입력은 **사용처·유형·단계·수단·금액** 다섯 칸이에요. 금액 바로 옆에는 읽기 전용 **자동 · 통화 금액**을 보여줘요. 그 밖의 입력과 계산 속성은 숨겨두었어요.

지갑 카드를 열면 **사용 내역 연결 표**에서 바로 지출을 작성할 수 있어요. 각 표는 해당 지갑의 거래만 보여주며, 예산·동행의 전체 사용 내역과 같은 원본 데이터를 사용해요. 새 지갑을 스킬로 만들 때도 이 표를 함께 구성해요.

1. **✍️ 지갑 설정**에서 지갑 이름·통화·준비 금액을 입력하고 `금액 입력 완료`를 켜요.
2. **✍️ 간편 기록**에서 아래 다섯 칸만 작성해요.

| 사용처 | 거래 유형 | 결제 단계 | 결제 수단 | 금액 |
|---|---|---|---|---|
| 점심 식사 | 지출 | 선택 | 선택 | 1,200 |

위 행은 입력 위치를 보여주는 예시예요. 날짜·분류·영수증·환율·정산 등의 보조 속성은 숨겨두었어요. 일행과 정산하지 않으면 분담 정보를 채울 필요가 없어요.

금액은 양수로 입력하면 연결된 지갑 잔액에서 바로 빠져요. 숨긴 상태가 비어 있어도 작동하며 유형을 환불로 선택하면 돌아와요. 예정 비용은 스킬에 ‘예정’이라고 알려주면 차감에서 제외해요. **사용액·남은 금액·사용률은 지갑의 자동 결과 구역**에서 확인해요.

지갑 통화가 JPY이면 금액 옆에 `¥1,320 · 엔`, USD이면 `$1,320.00 · 달러`처럼 자동 표시돼요. 입력 숫자는 해당 통화의 금액이며, 지갑 통화를 바꾸는 것만으로 환율 환산이 되지는 않아요.

## 필요한 네 묶음만 사용해요

현재 디폴트 디자인 참조: [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19)

별도 템플릿을 지정하지 않으면 Souvenir는 설치 기록의 대상 워크스페이스 로컬 구조를 사용해 새 여행을 시작해요. 설치 기록이 없으면 내장 템플릿 청사진으로 먼저 설치해요.

| 묶음 | 기본 작성 | 함께 볼 수 있는 것 |
|---|---|---|
| 🗺️ 계획·장소 | 일정 이름·일차·날짜·장소·상태 | 달력·타임라인·일차별 보드, 장소 사진, 날씨·플랜 B/C |
| 🎟️ 이동·예약 | 출발/도착·이용 날짜·예약 상태 | 숙소 갤러리, 현지 시각·숙박 기간·잔금 안내 |
| 💴 예산·동행 | 지갑 설정·간편 기록 | 예산 잔액, 인원별 계획 예산, 필요한 경우 동행자·정산 |
| 🎒 준비·자료 | 할 일·준비물 이름·상태·담당자 | 전체/담당자별 진행률, 기한 달력, 구매·귀국 확인·자료 |

목적지·기간만으로 시작하면 기본 네 묶음을 제공해요. 홈은 **진행도 히어로 → 여행 중 확인 존 → 계획 존** 순서로 고정해요. 여행 중 확인 존에서는 오늘·다음 일정, 확정 예약, 숙소, 지갑 잔액과 중요 자료를 먼저 확인하고, 계획 존에서만 세부 내용을 작성·수정해요. 새 여행에서는 연결 보기와 이동 링크를 해당 여행으로 구분해요.

네 묶음 화면은 상단 컬러 요약 안내와 핵심 DB 하나만 먼저 보여줘요. 장소·예약·지출·준비물의 보조 DB, 수식, 상세 설명은 `상세 보기` 토글 안에 넣어 화면을 단순하게 유지해요.

여행을 시작하면 **여행 중 확인 존**을 페이지 잠금 상태로 두는 것을 권장해요. 확인 존은 입력 속성과 내부 계산 속성을 숨긴 표시용 화면이고, 계획을 바꿀 때는 **계획 존 → 해당 묶음**으로 이동해요. Notion 연결 데이터베이스의 모든 행을 강제 읽기 전용으로 만들 수는 없으므로, Souvenir는 `계획 수정`이라는 명시적 요청 없이 일정·예약·예산을 변경하지 않아요.

여행 카드의 `여행 상태`를 `계획 중`·`여행 중`·`완료`로 바꾸고, 출발할 때 `계획 수정 잠금`을 켜면 확인 존 중심으로 사용할 수 있어요.

메인 최상단에는 여행별 **진행 카드**가 있어요. 한 줄 안에서 퍼센트·파스텔톤 두꺼운 막대·완료 건수를 자연스럽게 보여주며, 선택한 묶음의 등록 항목 중 완료 비율을 자동 계산해요. 취소·제외 항목은 빼고, 항목이 없으면 `집계 전 · 등록한 항목 없음`으로 표시해요. `이제 시작`·`마무리 단계` 같은 상태 문구와 세부 항목별 진행률은 접은 상세 보기에서 따로 확인해요. 자동 기준이 충분하지 않아도 `직접 완료`를 켤 수 있고, 작성은 됐지만 검토가 덜 됐다면 `자동 제외`를 켜서 해당 묶음을 진행률에서 잠시 뺄 수 있어요.

인원을 정하면 직접 입력 또는 명단 기준으로 계획 예산을 계산해요. **1인 단가 한도만 적용 인원에 따라 바뀌며**, 실제 결제·환불·기존 분담은 자동 재배분하지 않아요. 사람별 정산은 원거래를 대조한 검토 합계이며 `정산 다시 검토해줘`로 요청할 수 있어요.

## 현재 확인 범위

- 20개 DB의 상세 카드에서 입력과 자동 결과를 구분하고, 기본 화면에서 상세·보조 속성을 숨겼어요.
- 주요 입력 보기·사진 카드·보드의 표시 항목을 줄였어요. 기존 기록·속성·수식은 삭제하지 않았어요.
- 저장된 레이아웃, 입력 구역의 속성 유형, 여행·취소·제외 필터를 다시 확인했어요. 실제 앱·모바일 렌더링 검수는 남아 있어요.
- 환율·날씨·운영 정보는 자동 조회되지 않아요. 미확인 정보는 확인 필요로 남겨요.
- 무료 환경을 고려해 네이티브 차트는 새로 만들지 않아요. 이전 예산 DB의 차트 탭 1개는 삭제 도구/앱 입력 문제로 남아 있어요.
- 플러그인 매니페스트·저장소 마켓플레이스·시작 문구를 추가했어요. 실제 ChatGPT/Codex 데스크톱의 표시 위치와 클릭 후 동작은 설치 환경에서 한 번 더 확인해야 해요.

기본 스킬은 새 의존성 없이 동작하고, 코드 설치기는 Python 3.9 이상과 표준 라이브러리만 사용해요. 기존 구현·계산 검증·남은 제약은 [구현 기록](docs/implementation-notes.md)에 보존했어요. 공통 규칙은 [SKILL.md](skills/souvenir/SKILL.md) 한 곳에서 관리하고, `.agents/skills/souvenir`는 저장소 로컬 진입점으로 연결돼요. 온보딩·예산·준비·검증 등 상세 규칙은 해당 작업 때만 읽어서 매번 전체 설명을 불러오지 않아요. 입력 설계는 [간편 입력 규칙](skills/souvenir/references/input-design.md), 코드 설치 설계는 [템플릿 청사진](skills/souvenir/references/template-blueprint.md)에서 볼 수 있어요.

### 개발·검증

아래 검증은 실제 Notion 쓰기나 플러그인 설치 없이 실행돼요.

```bash
python3 -m unittest discover -s skills/souvenir/tests -v
python3 skills/souvenir/scripts/notion_installer.py validate
python3 skills/souvenir/scripts/notion_installer.py plan --pretty
python3 skills/souvenir/scripts/install_souvenir.py
```

테스트는 중단 후 재개, 중복 생성 방지, 다른 설치 대상 혼용 방지, 날짜·통화 입력, API 오류·재시도, 긴 텍스트·블록 분할, 스킬 문서 연결을 확인해요. GitHub Actions는 Linux·Windows의 Python 3.10·3.13에서 같은 검증을 실행하고, Python 3.9 최소 호환성은 로컬 회귀 테스트로 확인해요. 이 검증은 Notion의 실제 복제·화면 렌더링·수식 계산을 검증한 결과와 구분해요.

API 요청 제한 처리는 [Notion 공식 문서](https://developers.notion.com/reference/request-limits)를 따라요. 429·529는 대기 지시를 존중해 제한적으로 재시도하고, 저장 여부가 불분명한 쓰기 요청은 자동 재전송하지 않아요.

# Souvenir

![Souvenir 공통 배너](assets/souvenir-cover.png)

**여행은 한눈에, 작성은 간단하게.**

Notion 연결을 사용해 여행 플래너를 만들고 계획을 수정하는 **Codex·ChatGPT용 플러그인/스킬**이에요. 사진·카드·색상으로 보기 좋게 정리하고, 작성할 때는 필요한 항목만 보여줘요.

## 처음 설치하기

Souvenir는 별도 프로그램이 아니라 **플러그인으로 설치하거나 Codex 프로젝트에서 바로 불러 쓰는 여행 도우미**예요. Python, TypeScript, npm 설치는 필요하지 않아요.

가장 쉬운 방법은 플러그인 설치예요. 플러그인을 설치할 수 없는 환경에서는 저장소를 직접 열어도 같은 스킬을 사용할 수 있어요.

### 방법 A · 플러그인으로 설치하기 (권장)

#### Codex CLI에서 마켓플레이스 등록

Codex CLI를 사용한다면 다음 명령으로 Souvenir 마켓플레이스를 등록해요.

```bash
codex plugin marketplace add Jaws8078/souvenir --ref main
```

등록 후 Codex 데스크톱의 Plugins Directory에서 **Souvenir 여행 도우미**를 설치하고 새 채팅을 시작해요.

#### ChatGPT 데스크톱에서 설치

1. Plugins Directory를 열어요.
2. `Add Marketplace` 또는 `Add from repository`를 선택해요.
3. `https://github.com/Jaws8078/souvenir`를 입력하고 동기화해요.
4. **Souvenir**를 설치하고 새 채팅을 시작해요.
5. Notion 연결을 완료한 뒤 `$souvenir` 또는 표시되는 시작 문구를 사용해요.

플러그인은 스킬·내장 템플릿·시작 문구를 묶어 설치하지만, Notion 계정과 워크스페이스 권한은 각 사용자가 별도로 연결해야 해요.

### 방법 B · 저장소를 직접 열기

플러그인 설치가 표시되지 않는 환경에서는 아래 방식으로 사용해요.

#### 1. 저장소 받기

Git이 있다면 터미널에서 실행해요.

```bash
git clone https://github.com/Jaws8078/souvenir.git
cd souvenir
```

Git을 처음 쓰거나 설치할 수 없다면 GitHub의 **Code → Download ZIP**으로 받아 압축을 풀어도 돼요. 다만 ZIP 방식은 업데이트할 때 다시 내려받아야 하므로 Git clone을 권장해요.

#### 2. Codex에서 폴더 열기

Codex에서 방금 받은 `souvenir` 폴더를 프로젝트로 열어요. 저장소 안의 `.agents/skills/souvenir/SKILL.md`를 통해 스킬이 자동으로 검색돼요. 인식이 늦으면 폴더를 닫았다가 다시 열거나 새 채팅을 시작해요.

#### 3. Notion 연결하기

Codex에서 Notion 플러그인을 연결하고, 템플릿을 만들 워크스페이스에 접근 권한을 줘요. 첫 설치에는 페이지와 데이터베이스를 만들 수 있는 쓰기 권한이 필요해요.

#### 4. 첫 실행

새 채팅에서 아래처럼 입력해요.

```text
$souvenir
```

번호나 작업 이름으로 선택할 수 있어요.

| 선택 | 하는 일 |
|---|---|
| 1. 여행 플래너 만들기 | 기본 양식 또는 기존 템플릿을 사용해요. |
| 2. 새 여행 계획 | 목적지와 날짜 또는 기간만으로 시작해요. |
| 3. 기존 일정 수정 | 변경안과 영향을 먼저 보여주고 요청한 부분을 반영해요. |

예: **`$souvenir 새 여행 계획. 후쿠오카 3박 4일`**

날짜가 미정이면 1~4일차로 작성해요. 인원·예산·숙소·취향은 나중에 정해도 돼요. 저장 위치를 지정하지 않으면 비공개 초안으로 저장하고, 지정한 템플릿이 있으면 그 구조를 재사용해요.

### 설치가 끝나면

처음 연결한 워크스페이스에서는 원본 Notion 페이지 링크를 요구하지 않아요. Souvenir가 내장 청사진으로 `Souvenir · 여행 대시보드`, 네 묶음 화면, 관계형 데이터베이스와 기본 뷰를 해당 워크스페이스에 만들어요. 설치가 끝난 뒤에는 아래처럼 바로 시작하면 돼요.

```text
$souvenir 새 여행 계획. 후쿠오카 3박 4일
```

설치 기록이 있으면 기존 구조를 재사용하고, 사용자가 별도 템플릿 링크를 주면 그 템플릿을 우선해요.

## 업데이트하기

Git clone으로 설치했다면 저장소 폴더에서 실행해요.

```bash
cd souvenir
git pull
```

그 다음 Codex에서 새 채팅을 시작하면 최신 스킬 규칙과 내장 템플릿 청사진이 반영돼요. ZIP으로 설치했다면 최신 ZIP을 다시 받아 기존 폴더를 교체해요. Notion에 이미 만든 여행 데이터는 업데이트로 삭제하지 않아요.

## 문제가 생기면

- `$souvenir`가 인식되지 않으면 Codex에서 저장소 **루트 폴더**를 열었는지 확인해요.
- `.agents/skills/souvenir/SKILL.md` 파일이 있는지 확인해요.
- Notion 페이지가 만들어지지 않으면 Notion 연결 상태와 대상 워크스페이스의 쓰기 권한을 확인해요.
- 설치가 중단되면 다시 `$souvenir`를 실행해요. `Souvenir · 설치 기록`을 읽고 누락된 단계부터 이어가요.

## 다른 워크스페이스에서 시작해요

다른 워크스페이스에서 처음 `$souvenir`를 실행하면 아래 순서로 한 번만 진행해요.

1. Notion 연결 상태와 대상 워크스페이스 접근 권한을 먼저 확인해요. 연결되지 않았으면 채팅에 비밀번호를 입력하지 말고 Notion 연결을 완료한 뒤 다시 실행해요.
2. `Souvenir · 설치 기록`을 먼저 찾아요. 완료 기록이 있으면 기존 페이지·데이터베이스를 재사용하므로 전체 워크스페이스를 다시 훑지 않아요.
3. 설치 기록이 없을 때만 **기본 템플릿을 설치할지 한 번 확인**해요. 거절하면 템플릿을 만들지 않고 요청한 최소 작업만 진행해요.
4. 설치를 승인하면 설치 기록을 먼저 저장하고 대시보드·네 묶음·핵심 DB부터 만든 뒤, 보조 DB와 상세 뷰를 이어서 구성해요. 중간에 멈춰도 다음 실행에서 누락 단계부터 재개해요.

원본과 최대한 같은 화면을 원하면 대상 워크스페이스에서 열 수 있고 **복제 권한이 있는 Notion 템플릿 링크**를 함께 주세요. 이 경우 네이티브 페이지 복제를 먼저 시도해서 콜아웃·컬럼·커버·데이터베이스 뷰·관계·수식을 보존해요. 복제 권한이 없거나 연결 도구가 네이티브 복제를 지원하지 않는 경우에는 [내장 템플릿 청사진](.agents/skills/souvenir/references/template-blueprint.md)으로 새 워크스페이스에 재구성해요. 이 방식은 구조와 디자인 계약을 재현하지만 원본의 픽셀 단위 복제라고 보장할 수는 없어요.

- 원본 워크스페이스의 페이지·데이터베이스 ID, 사용자 데이터, 예시 거래는 복사하지 않아요.
- `Souvenir · 설치 기록`에 대상 워크스페이스의 페이지·데이터베이스 매핑과 템플릿 출처(`native_duplicate` 또는 `blueprint_rebuild`)를 저장해요.
- 이미 설치됐거나 중간에 멈춘 경우에는 기록을 우선 사용하고, 같은 객체를 반복 생성하거나 전체 DB를 다시 검색하지 않아요.
- Notion 연결과 쓰기 권한이 없으면 설치하지 않고 필요한 권한과 구조를 안내해요.

현재 디폴트 대시보드 [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19)는 디자인 확인용 참조 원본이에요. 다른 워크스페이스에 원본 링크가 없어도 청사진 설치는 가능하지만, 원본과 똑같은 레이아웃이 필요하면 복제 권한이 있는 템플릿 링크가 가장 빠르고 정확해요.

## 입력과 결과를 구분해요

| 표시 | 사용할 때 |
|---|---|
| **✍️ 입력** | 직접 작성하는 기본 항목이에요. 대부분 제목 포함 3~5개 열만 보여줘요. |
| **🟢 자동** | 잔액·기간·진행률·확인 결과예요. 직접 입력하지 않아요. |
| **선택 입력** | 날짜·영수증·환율·객실·정산 등 필요해졌을 때만 열어요. |

진행률은 자동 계산을 기본으로 하되, 카드의 **진행도 수동 조정**에서 묶음별 `직접 완료` 또는 `자동 제외`를 선택할 수 있어요. 자동 완료 표시는 계속 계산되고, 수동 조정은 해당 여행에만 반영돼요. 두 체크가 동시에 켜지면 `직접 완료`를 우선해요.

카드를 열면 **직접 입력 → 자동 결과 → 선택 입력**으로 구역이 나뉘어요. 내부 집계·중간 계산 속성은 숨겨두었고 기존 값과 기능은 보존해요. 빈칸은 **미정**, 근거·입력을 다시 봐야 하면 **확인 필요**, 실제로 마치면 **완료**예요.

## 지갑과 사용 내역은 짧게

사용 내역 표와 상세 카드의 입력은 **사용처·유형·단계·수단·금액** 다섯 칸이에요. 금액 바로 옆에는 읽기 전용 **자동 · 통화 금액**을 보여줘요. 그 밖의 입력과 계산 속성은 숨겨두었어요.

지갑 카드를 열면 **사용 내역 연결 표**에서 바로 지출을 작성할 수 있어요. 각 표는 해당 지갑의 거래만 보여주며, 예산·동행의 전체 사용 내역과 같은 원본 데이터를 사용해요. 새 지갑을 스킬로 만들 때도 이 표를 함께 구성해요.

1. **✍️ 지갑 설정**에서 지갑 이름·통화·준비 금액을 입력하고 `금액 입력 완료`를 켜요.
2. **✍️ 간편 기록**에서 아래 다섯 칸만 작성해요.

| 사용처 | 거래 유형 | 결제 단계 | 결제 수단 | 금액 |
|---|---|---|---|---|
| 점심 식사 | 지출 | 선택 | 선택 | 1,200 |

위 행은 입력 위치를 보여주는 예시예요. 날짜·분류·영수증·환율·정산 등의 보조 속성은 숨겨두었어요. 일행과 정산하지 않으면 분담 정보를 채울 필요가 없어요.

금액은 양수로 입력하면 연결된 지갑 잔액에서 바로 빠져요. 숨긴 상태가 비어 있어도 작동하며 유형을 환불로 선택하면 돌아와요. 예정 비용은 스킬에 ‘예정’이라고 알려주면 차감에서 제외해요. **사용액·남은 금액·사용률은 지갑의 자동 결과 구역**에서 확인해요.

지갑 통화가 JPY이면 금액 옆에 `¥1,320 · 엔`, USD이면 `$1,320.00 · 달러`처럼 자동 표시돼요. 입력 숫자는 해당 통화의 금액이며, 지갑 통화를 바꾸는 것만으로 환율 환산이 되지는 않아요.

## 필요한 네 묶음만 사용해요

현재 디폴트 디자인 참조: [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19)

별도 템플릿을 지정하지 않으면 Souvenir는 설치 기록의 대상 워크스페이스 로컬 구조를 사용해 새 여행을 시작해요. 설치 기록이 없으면 내장 템플릿 청사진으로 먼저 설치해요.

| 묶음 | 기본 작성 | 함께 볼 수 있는 것 |
|---|---|---|
| 🗺️ 계획·장소 | 일정 이름·일차·날짜·장소·상태 | 달력·타임라인·일차별 보드, 장소 사진, 날씨·플랜 B/C |
| 🎟️ 이동·예약 | 출발/도착·이용 날짜·예약 상태 | 숙소 갤러리, 현지 시각·숙박 기간·잔금 안내 |
| 💴 예산·동행 | 지갑 설정·간편 기록 | 예산 잔액, 인원별 계획 예산, 필요한 경우 동행자·정산 |
| 🎒 준비·자료 | 할 일·준비물 이름·상태·담당자 | 전체/담당자별 진행률, 기한 달력, 구매·귀국 확인·자료 |

목적지·기간만으로 시작하면 기본 네 묶음을 제공해요. 홈은 **진행도 히어로 → 이번 여행 한눈에 → 오늘·다음 일정 → 여행 바로가기** 순서로 요약을 먼저 보여주고, 세부 작성은 네 묶음 화면에서 이어가요. 홈의 **사용할 묶음 선택**에서 체크를 끄면 메뉴에서 빠지고 기록은 남아요. 새 여행에서는 연결 보기와 이동 링크를 해당 여행으로 구분해요.

네 묶음 화면은 상단 컬러 요약 안내와 핵심 DB 하나만 먼저 보여줘요. 장소·예약·지출·준비물의 보조 DB, 수식, 상세 설명은 `상세 보기` 토글 안에 넣어 화면을 단순하게 유지해요.

메인 최상단에는 여행별 **진행 카드**가 있어요. 한 줄 안에서 퍼센트·파스텔톤 두꺼운 막대·완료 건수를 자연스럽게 보여주며, 선택한 묶음의 등록 항목 중 완료 비율을 자동 계산해요. 취소·제외 항목은 빼고, 항목이 없으면 `집계 전 · 등록한 항목 없음`으로 표시해요. `이제 시작`·`마무리 단계` 같은 상태 문구와 세부 항목별 진행률은 접은 상세 보기에서 따로 확인해요. 자동 기준이 충분하지 않아도 `직접 완료`를 켤 수 있고, 작성은 됐지만 검토가 덜 됐다면 `자동 제외`를 켜서 해당 묶음을 진행률에서 잠시 뺄 수 있어요.

인원을 정하면 직접 입력 또는 명단 기준으로 계획 예산을 계산해요. **1인 단가 한도만 적용 인원에 따라 바뀌며**, 실제 결제·환불·기존 분담은 자동 재배분하지 않아요. 사람별 정산은 원거래를 대조한 검토 합계이며 `정산 다시 검토해줘`로 요청할 수 있어요.

## 현재 확인 범위

- 20개 DB의 상세 카드에서 입력과 자동 결과를 구분하고, 기본 화면에서 상세·보조 속성을 숨겼어요.
- 주요 입력 보기·사진 카드·보드의 표시 항목을 줄였어요. 기존 기록·속성·수식은 삭제하지 않았어요.
- 저장된 레이아웃, 입력 구역의 속성 유형, 여행·취소·제외 필터를 다시 확인했어요. 실제 앱·모바일 렌더링 검수는 남아 있어요.
- 환율·날씨·운영 정보는 자동 조회되지 않아요. 미확인 정보는 확인 필요로 남겨요.
- 무료 환경을 고려해 네이티브 차트는 새로 만들지 않아요. 이전 예산 DB의 차트 탭 1개는 삭제 도구/앱 입력 문제로 남아 있어요.
- 플러그인 매니페스트·저장소 마켓플레이스·세 개의 시작 문구를 추가했어요. 실제 ChatGPT/Codex 데스크톱의 표시 위치와 클릭 후 동작은 설치 환경에서 한 번 더 확인해야 해요.

Python·TypeScript·새 의존성은 추가하지 않았어요. 기존 구현·계산 검증·남은 제약은 [구현 기록](docs/implementation-notes.md)에 보존했어요. 스킬 규칙은 [SKILL.md](.agents/skills/souvenir/SKILL.md), 입력 설계는 [간편 입력 규칙](.agents/skills/souvenir/references/input-design.md)에서 볼 수 있어요.

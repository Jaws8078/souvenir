# API 없이 장소를 함께 찾는 흐름

정리일: 2026-11-18

## 방향과 현재 상태

Souvenir의 우선 개발 방향은 **사용자가 키를 준비하지 않고 AI와 대화하며 장소를 찾는 것**이다. 호스트의 웹 검색으로 후보를 조사하고, 사용자가 선택한 장소만 기존 Notion 템플릿에 연결한다.

기존 Google Places API 코드·테스트·로컬 키는 유지한다. 이 문서는 비API 경로의 설계안이며, 실행기의 제공자 선택 로직을 변경한 기록은 아니다. 현재 실행기는 키가 환경변수에 있으면 API를 선택하므로, 비API 경로를 기본으로 고정하려면 키 유무와 별개인 검색 모드 선택을 후속 구현해야 한다.

## 사용자 흐름

| 단계 | 사용자 | Souvenir |
| --- | --- | --- |
| 1. 시작 | `장소부터 찾아보자` | 기존 여행지·인원·취향을 재사용하고 원하는 장소를 묻는다 |
| 2. 조건 | `텐진 근처에서 조용한 카페` | 지역·종류·필수 조건을 정리하고 검색한다. 이미 아는 조건은 다시 묻지 않는다 |
| 3. 후보 | 추천 목록을 비교한다 | 조건 적합성과 확인 근거를 기준으로 최대 10곳을 보여준다 |
| 4. 자세히 보기 | `2번이랑 5번 비교해줘` | 선택한 곳을 더 조사해 장점·주의점·가격·영업정보를 비교한다 |
| 5. 이어보기 | `다른 곳도 보여줘` | 같은 조건으로 이전 후보를 제외한 다음 최대 10곳을 조사한다 |
| 6. 저장 | `2번 저장해줘` | 대상과 저장할 내용을 확정해 현재 여행의 장소 보관함에 반영한다 |
| 7. 확인 | 해당 장소 파트를 연다 | 저장 행·여행 관계·표시 뷰·확인 존을 재조회하고 해당 파트 페이지 링크를 준다 |
| 8. 일정 연결 | `이걸 2일차에 넣자` | 기존 예약·시간·동선을 대조해 변경안을 보여주고 반영한다 |

## 첫 질문

```text
가고 싶은 장소를 편하게 말해주세요.
지역과 장소 종류만 알려주셔도 괜찮아요.

조건을 붙여 말해주셔도 좋아요: 분위기 · 예산 · 영업시간 등

조건이 없으면 여행지와 취향에 맞춰 추천해드릴게요.

입력 예시: 후쿠오카에서 조용히 쉬기 좋은 카페를 찾고 있어요. 1인 1,500엔 이하이면 좋겠어.

다음 할 일: 원하는 장소를 자연스럽게 말해주세요.
```

검색을 시작할 수 있으면 바로 진행한다. 동명 지역이나 지점처럼 결과가 크게 달라지는 정보만 짧게 확인한다. `추천해줘`만 받아도 기존 여행지·취향으로 시작할 수 있다.

## 검색과 사실 확인

1. 목적지·지역·종류·조건으로 호스트 웹 검색을 실행한다.
2. 공식 사이트·공식 메뉴·공식 공지에서 위치·가격·영업시간을 확인한다. 관광청·공공 관광 자료 등 보완 근거도 사용한다.
3. 장단점은 이용 조건상 활용 가능한 공개 방문 후기·기사에서 근거를 찾는다. 원문 전체나 사진을 복사하지 않고 필요한 사실과 짧은 요지만 출처에 연결한다.
4. Google Maps는 특정 장소의 링크 확인과 지도 열기에 사용한다. 내부 리뷰 자동 스크롤·대량 추출·비공식 내부 요청을 기본 수집 경로로 삼지 않는다.
5. 출처의 지역·지점·게시 시점·최근 공지를 대조한다. 다른 지점이나 광고성 소개를 방문자 경험으로 표현하지 않는다.

공개 페이지라고 무조건 수집·재사용 가능한 것은 아니다. 접근 제한이나 이용 조건 때문에 확인하지 못한 부분은 다른 허용 출처로 확인하거나 `확인 필요`로 남긴다.

## 후보 표시와 정렬

기본 표는 **번호 · 장소/지역 · 추천 이유 · 주의점 · 예상 비용 · 조건 확인 · 출처/지도**로 구성한다. 긴 주소·전체 영업시간·여러 후기 인용은 상세 비교 단계에서 보여준다. 출처가 없는 장단점이나 숫자는 채우지 않는다.

- **추천순**: 필수 조건 충족 → 사용자 취향 → 동선 편의 → 근거의 최신성·충분성 순으로 판단한다. Google Maps 순위나 평점순으로 표현하지 않는다.
- **비용**: 메뉴 기준 금액, 1인/전체, 통화, 세금·최소 주문 등 확인된 범위를 표시한다. 메뉴 가격을 실제 1인 총지출로 단정하지 않는다.
- **영업**: 공식 운영시간을 확인한 것과 방문 시점에 실제 영업 중인 것은 구분한다. 시간대·날짜·임시 휴무를 확인하지 못하면 현재 영업 중으로 단정하지 않는다.
- **분위기**: `조용함`은 후기 기반의 경향으로 표시한다. 시간대별 소음·혼잡을 보장하지 않는다.
- **평점·거리**: 출처·평가 수·확인 시점이 있는 경우에만 표시한다. 지도상의 근접성을 실제 도보 시간처럼 제시하지 않는다.
- **조건 상태**: `확인됨 / 확인 필요 / 불충족`으로 구분한다. 필수 조건 불충족은 추천 목록에서 제외하고, 미확인 후보는 조건 충족 후보와 구분한다.

10개를 채우기 위해 조건을 몰래 완화하지 않는다. 확인된 후보가 6개라면 6개만 제시하고, 조건을 넓힐지는 사용자에게 묻는다.

## 장소별 지도 표시

- 채팅 추천 후보마다 확인한 해당 지점의 `[지도] [길찾기]` 링크를 제공한다. 정확한 장소 URL이 없으면 `[지도 검색 · 위치 확인 필요]`로 구분한다.
- 길찾기 링크는 확인한 장소명·주소를 URL 인코딩해 구성하고, 출발지는 사용자가 Maps에서 선택하도록 생략한다. 검증된 Place ID가 있으면 함께 사용한다. API 키는 필요하지 않다.
- 저장한 장소 상세 페이지는 `장소명·짧은 위치 → 큰 지도 → 지도/길찾기 → 정보·메모·출처` 순서의 모바일 1열 구성을 사용한다.
- 여행 중 확인 존은 같은 장소 행의 위치·지도·길찾기를 보여준다. 10개 후보 전체에 지도 임베드를 추가하지 않는다.
- Notion 도구가 지도 임베드를 지원하고 적합한 링크가 있을 때 실제 지도 블록을 넣는다. 지원하지 않으면 링크와 `/maps` 안내를 제공하고, 지도 표시가 완료됐다고 표현하지 않는다.
- 채팅 안의 인터랙티브 지도는 호스트 지원 여부에 따라 달라진다. Markdown 링크만 제공한 경우 지도를 직접 그렸다고 말하지 않는다.

이 규칙은 [대화 흐름](../skills/souvenir/references/conversation-flow.md#장소별-지도와-길찾기--api-없이-표시)과 [데이터 운영](../skills/souvenir/references/data-operations.md#장소-지도-표시)에 반영했다. 실제 Notion 지도 블록 생성·핀 위치·모바일 화면 검증은 아직 남아 있다.

## 장단점 상세 비교

사용자가 고른 장소부터 추가 조사한다. 모든 후보의 후기를 처음부터 깊게 조사해 대기 시간을 늘리지 않는다.

상세 카드는 **맞는 이유 / 장점 / 주의점 / 확인이 남은 조건 / 근거 링크** 순서로 보여준다. 방문 후기와 공식 정보를 구분하고, 서로 다른 경험이 있으면 차이를 설명한다. 후기 한 건의 의견을 여러 사람이 공통으로 말하는 사실처럼 표현하지 않는다. 단점을 찾지 못했다면 `단점 없음` 대신 `확인한 자료에서 구체적인 단점 근거를 찾지 못함`으로 표시한다.

## 다음 최대 10개

호스트는 검색 조건, 이미 제시한 장소 식별 정보, 마지막 후보 번호, 출처와 확인 상태를 대화 세션에서 유지한다. 다음 요청에서 다른 검색어·자료를 조사하되 기존 장소와 같은 지점을 중복 제시하지 않는다. 지점이 다르면 별도 장소로 구분한다.

전체 웹 후보 수는 `미확인`으로 표시한다. 검색 결과 몇 개를 확인한 것을 조건에 맞는 모든 장소를 찾았다고 표현하지 않는다. 조건을 바꾸면 새 검색으로 시작하고, 명시적으로 요청하지 않는 한 이전 후보를 다시 포함하지 않는다. API 페이지 토큰은 사용하지 않는다.

## Notion 저장

후보 검토 중에는 Notion 행을 만들지 않는다. 사용자가 번호로 저장을 요청하면 대상·지점이 명확한 경우 같은 허락을 다시 묻지 않고 저장한다. 추정값·대상 혼동·기존 값 덮어쓰기가 있으면 먼저 확인한다.

저장할 정보는 **장소명·지역·종류·공식 링크·지도 링크·사용자 메모·확인일**, 필요하면 근거가 있는 비용·주의점의 짧은 요약이다. 기존 스키마를 읽어 정확한 속성에 넣고, 요약에는 출처를 연결한다. 출처의 재사용 조건에 맞지 않는 리뷰 원문·사진은 저장하지 않는다. 미확인 값은 비워두거나 확인 필요로 둔다.

각 행에 현재 여행 관계/키를 설정하고, 장소 보관함과 확인 존에서 실제 보이는지 확인한다. `저장됨`과 `화면 표시 확인됨`을 구분한다. 결과 링크는 전체 여행 페이지나 DB 자체 대신 해당 장소 파트 페이지를 사용한다. 저장한 장소를 일정에 넣는 것은 별도 작업이며 자동 배치하지 않는다.

## 검색이 어려울 때

- 웹 검색 도구 없음: 특정 장소 링크·장소명·사용자 제공 자료를 받아 정리한다. 검색을 수행했다고 표현하지 않는다.
- 지도 단축 링크 해석 실패: 공식 링크나 다른 검색 자료로 장소를 확인한다. 그래도 특정할 수 없으면 장소명만 짧게 묻는다.
- 상반된 가격·영업시간: 공식 최신 공지를 우선하고 불일치는 표시한다.
- 적합한 후보 부족: 확인된 수만 보여주고 지역·예산·종류 중 한 조건을 넓힐지 묻는다.
- Notion 저장 실패/불확실: 중단된 항목을 알리고 실제 저장 여부를 확인한 뒤 재개한다.

## 후속 구현·검증

- [ ] 키가 설정되어 있어도 웹 검색을 명시적으로 선택하는 모드와 스킬 호출 규칙
- [ ] 조건 확인 상태·출처·장단점 근거를 후보 계약과 연결
- [ ] 후보 번호와 선택 지점을 유지한 추가 조사·비교
- [ ] 대화 세션 내 다음 10개 중복 제외와 조건 변경 처리
- [ ] 승인된 웹 후보 → Notion 속성 → 장소 보관함·확인 존 실검증
- [ ] 웹 검색 불가·후기 부족·출처 충돌·동명 지점의 회귀 시나리오

기존 API 실험 결과는 [Google Places 검증 기록](google-places-validation.md)에 보존한다.

# Souvenir 후속 개선 메모

작성일: 2026-11-17  
기준 버전: 플러그인 `0.4.6`

이 메모는 현재 구현을 기준으로, 다음 작업의 우선순위와 완료 조건을 정리한 실행 목록이다. 일반 사용자는 이 문서를 읽지 않아도 되며, 개발·검증 작업에서만 사용한다.

## 현재 기준선

- 고정 템플릿 게이트와 Notion 연결·워크스페이스 확인 흐름이 스킬 규칙에 반영되어 있다.
- Google Places API 키가 있으면 API 검색, 키가 없으면 호스트 웹 검색을 우선 사용하고, 웹 검색도 불가능할 때만 실제 Google Maps 장소 링크를 받는 fallback을 사용한다.
- API·웹 검색·링크 모드는 동일한 장소 후보 계약을 사용한다.
- 후보는 추천순으로 최대 10개씩 보여주고, 중복 제거·필터·정렬·현재/전체 후보 수를 함께 기록한다.
- Python 엔진 오프라인 회귀 테스트는 160개 통과(2개 건너뜀) 상태다.
- Notion 쓰기는 사용자 승인, 여행 키 관계, 재조회·검증, 작업 키·lease·충돌 보호를 전제로 한다.

## 다음 작업 우선순위

### P0 · 실제 흐름과 데이터 표시 검증

- [ ] **Notion 종단 간 스모크 테스트**
  - 새 워크스페이스에서 고정 템플릿 확인 또는 복제
  - 장소 자연어 검색 → 후보 10개 제시 → 승인 → 장소 보관함 저장
  - 저장된 장소가 일정·여행 중 확인 존의 해당 파트 블록에 보이는지 확인
- [ ] **반영 위치 검증**
  - 전체 여행 페이지가 아니라 실제로 수정된 파트 블록 링크만 반환
  - DB 뷰 필터가 현재 여행 키/관계만 표시하는지 확인
  - 저장 후 원본 행·요약 카드·확인 존을 다시 읽어 숫자와 사진을 대조
- [ ] **배포본 사전 점검**
  - 원본에 개인 데이터·가상 예시·테스트 행·내부 링크가 없는지 확인
  - 템플릿 복제 권한, 모바일 1열 뷰, 카드 커버, 필수 수식 표시 확인
  - API 키·토큰·쿠키·개인 링크가 저장소와 배포 문서에 없는지 검사
- [ ] **후보 품질 차단**
  - 여행지 불일치 후보, 검색 결과 페이지 URL, 장소명이 없는 링크는 저장하지 않음
  - 실제 장소 URL·출처·확인 필요 상태를 승인 전에 표시

### P1 · 검색과 입력 경험 보강

- [ ] **자연어 조건 파싱 고도화**
  - 지역·장소 종류·분위기·예산·영업시간·세부 지역·거리·동행자 취향을 추출
  - 이미 받은 조건은 다시 묻지 않고, 누락된 조건만 짧게 확인
- [ ] **다음 10개 검색 세션 유지**
  - 검색 세션 ID, 이전 후보 ID, 현재 페이지, 적용 필터를 보존
  - `다음 10개` 요청 시 이전 후보와 중복 없이 이어서 추천
  - 검색 조건을 바꿀 때는 새 세션으로 분리
- [ ] **필터 적용 근거 표시**
  - `적용 확인`, `확인 필요`, `미지원`을 필터별로 표시
  - 웹 검색과 링크 fallback에서 확인하지 못한 영업시간·가격은 추정하지 않음
- [ ] **사진·파일 반영 검증**
  - 항공·숙소·장소·쇼핑에 들어온 사진/파일을 파일 속성과 출처 속성에 함께 저장
  - 카드·갤러리에서 바로 보이는지 확인하고 기존 사진은 요청 없이 덮어쓰지 않음
- [ ] **중단·재개 UX**
  - 로그인 만료, 복제 권한, 네트워크 실패, 검색 실패, Notion rate limit, 사용자 `나중에`를 각각 재개 가능한 상태로 남김
  - 불확실한 쓰기는 자동 재전송하지 않고 실제 Notion 상태 확인을 먼저 안내
- [ ] **템플릿 버전·마이그레이션**
  - 복제본 계약 버전을 기록하고 누락 속성·뷰만 안전하게 보완
  - 기존 사용자 데이터·메모·사진·예약을 보존하고 예시 행을 재삽입하지 않음

### P2 · 배포와 운영 안정화

- [ ] **환경별 검증 매트릭스**
  - Codex·Claude Code·Gemini 로컬 실행기, ChatGPT 웹·모바일, macOS·Windows에서 온보딩과 링크 fallback을 점검
- [ ] **마켓/링크 배포 체크리스트 자동화**
  - README·plugin.json 버전, 템플릿 링크, 복제 허용, 개인정보·비밀 스캔을 릴리스 전에 자동 확인
- [ ] **coordinator 운영 준비**
  - HTTPS reverse proxy, SQLite 백업·복구, 모니터링, 만료 lease 알림을 준비
  - coordinator가 켜진 환경에서 연결 실패 시 안전하게 쓰기를 중단하는지 확인
- [ ] **도메인별 보상 작업**
  - Notion 외부 변경을 자동으로 되돌리지 않고, 충돌·취소·부분 저장의 보상 이벤트를 검토 가능한 상태로 남김

## 완료 판단 기준

다음 항목을 모두 확인해야 해당 개선을 완료로 표시한다.

1. 실제 Notion 복제본에서 재현 가능한 테스트 절차가 있다.
2. 저장 전 승인과 저장 후 재조회가 로그·화면에서 구분된다.
3. 현재 여행의 대응 파트 블록에서 결과가 바로 보인다.
4. 기존 메모·예약·다른 여행의 데이터가 보존된다.
5. API 키가 없는 환경에서도 동일한 후보 계약과 사용자 흐름이 유지된다.
6. 실패 시 데이터가 조용히 누락되거나 중복 생성되지 않고, 사용자가 재개할 수 있다.

## 권장 다음 작업

가장 먼저 **P0 종단 간 스모크 테스트**를 실행한다. 이 테스트가 통과하면 P1의 자연어 조건 파싱과 `다음 10개` 세션 작업을 이어서 진행한다.

## 범위 밖

- 공개 플러그인에 Google API 키를 내장하지 않는다.
- 사용자 승인 없이 Notion에 장소·예약·예산을 저장하지 않는다.
- 확인하지 않은 가격·영업시간·휴무·이동 시간을 만들어내지 않는다.
- 템플릿 원본에 개인 여행 데이터를 포함하지 않는다.

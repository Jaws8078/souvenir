# 구현·검증 기록

이 문서는 입력 화면 간소화 전 README와 단계별 검증 기록을 보존한 자료입니다. 현재 사용 방법과 화면 구성은 [README](../README.md)를 우선 참고하세요. 과거 차트·뷰 이름과 배치는 현재 화면과 다를 수 있습니다.

# Souvenir

Notion 플러그인에 연결해 여행 플래너를 만들고, 새 여행을 계획하고, 기존 일정을 수정하는 여행 도우미 스킬이에요.

## 시작하기

1. Codex에서 이 저장소 폴더를 열어요.
2. Notion 플러그인을 연결하고, 사용할 페이지에 접근할 수 있는지 확인해요.
3. 채팅에 `$souvenir`를 입력하면 세 가지 작업이 나와요. 번호나 작업 이름을 입력해 시작할 수 있어요.

| 선택지 | 하는 일 |
|---|---|
| 1. 여행 플래너 만들기 | 기본 Notion 양식을 만들거나 기존 템플릿을 사용해요. |
| 2. 새 여행 계획 | 목적지와 날짜 또는 기간을 받아 여행 일정을 만들어요. |
| 3. 기존 일정 수정 | 바뀌는 항목을 먼저 보여주고, 확인한 부분만 반영해요. |

템플릿이나 저장 위치를 이미 정했다면 Notion 페이지 링크를 함께 알려주세요. 템플릿이 없어도 기본 양식으로 여행을 시작할 수 있어요.

기본 템플릿은 [Souvenir · 여행 대시보드](https://app.notion.com/p/4141036c4e428195a351c1a8afd23f19?pvs=204)예요. [여행 계획 도우미(제작 중)](https://app.notion.com/p/3cc1036c4e4280508eb9c50b9532885c?pvs=204)의 갤러리·수식·콜아웃을 살리고 메인을 **공통 배너 → D-Day → 선택한 묶음 메뉴 → 오늘·다음 일정**으로 줄였어요. 긴 설명과 예시는 접어서 따로 볼 수 있어요.

| 사용할 묶음 | 구성 |
|---|---|
| 🗺️ 계획·장소 | 개요·취향, 일정·달력·타임라인·일차별 보드, 장소, 날씨·플랜 B/C |
| 🛎️ 이동·예약 | 항공·현지 이동·패스·렌터카, 숙소 갤러리, 예약 상태 보드·달력 |
| 💴 예산·동행 | 지갑 요약·거래·차트, 카테고리 한도, 동행자·역할·분담·정산 |
| 🎒 준비·자료 | 할 일·상태 보드·달력, 준비물·담당자별 진행률, 자료 보관함 |

홈의 **사용할 묶음 선택**에서 체크를 끄면 메뉴에서 숨겨지고 기록은 남아요. 새 여행에서는 묶음 페이지와 모든 연결 뷰를 해당 여행으로 구분해요. 개별 기능을 하나씩 고르도록 질문하지 않아요. 목적지·기간만으로 시작하라는 요청에는 기본 네 묶음을 제공하고 나중에 끌 수 있게 해요.

각 화면은 1열·짧은 컬러 콜아웃·목차·홈 이동으로 맞췄어요. 일정·예약·할 일·준비물·자료에는 핵심 속성만 보여주는 **모바일 목록** 탭도 있어요. 넓은 상세 탭과 기존 달력·보드·차트는 유지했어요. [공통 배너](../assets/souvenir-cover.png)는 실제 여행지 사진이 아닌 추상 이미지예요.

인원은 여행 카드 또는 **예산·동행 → 인원·통화 설정**에서 직접 입력하거나 명단 기준으로 관리해요. 명단의 보류·불참은 제외하고 인원 미정은 그대로 표시해요. 카테고리 한도가 `범위=1인`이면 **1인 단가 × 적용 인원**, 일행 전체면 입력 금액 그대로예요. 항목별로 여행 전체·선택한 동행자·직접 입력 중 기준을 고를 수 있어요. 지갑 준비 총액과 실제 결제·환불은 인원 변경으로 배수 처리하지 않아요. `1인 예산 참고`는 실제 개인 정산액이 아니에요.

동행자·담당·개인 준비물은 사람별 행으로 늘릴 수 있어요. 스킬이 인원 변경 요청을 반영할 때 기존 명단과 담당을 대조하며 과거 기록을 삭제하지 않아요. 사람별 행 생성·담당 재배정과 기존 거래 재분담은 숫자 변경만으로 자동 실행되지 않아요. 예약 인원·객실·분담 변경은 먼저 영향을 확인해요.

카드를 열어 수정하면 표시가 자동으로 바뀌어요. 여행 기간 하나로 출발·종료 D-Day와 몇 박 며칠을 계산하고, 숙소는 현지 시간대에 맞춰 체크인·아웃을 표시해요. 지갑에는 준비한 총액을 입력하고 `금액 입력 완료`를 체크하세요. 사용 내역의 완료된 지출은 차감하고 완료된 환불은 돌려주며, 예정 비용은 별도 표시해요. 다른 통화는 지갑을 나눠 사용해요.

`여행 개요와 취향`은 **방향·속도·선호·주의사항** 탭에서 바로 작성해요. 빈칸을 클릭해 테마·여행 템포·음식·이동·숙소 태그를 선택하고, 하루 주요 일정 수는 숫자로 입력해요. 꼭 할 일·방문지와 주의사항만 짧게 적으면 돼요. 같은 여행 정보에 저장되며 여행 이름을 열면 카테고리별 속성을 한 화면에서 수정할 수도 있어요. 항목은 비워두어도 되고, 예시 여행의 취향은 실제 여행에 적용하지 않아요.

`날짜별 일정`은 **일별 일정·일차별 카드·달력·시간표·확인할 일정**으로 작성하고 확인해요. 일차와 순서부터 정하고, 실제 날짜를 알면 시작·종료 시각을 입력하세요. 날짜가 미정이어도 계획할 수 있고, 날짜와 일차가 어긋나거나 종료 시각이 비어 있으면 확인 목록에 나타나요.

`장소 보관함`은 참고 페이지의 맛집·관광·쇼핑 DB처럼 **지역·세부 지역·종류·예산·결제 수단·TIP·별점·방문 체크**를 제공해요. 지도·사진·영업시간·휴무·확인 근거는 장소 카드를 열어 기록하세요. 일정에서 `장소 카드`를 선택하면 같은 장소 정보와 방문 일정이 연결돼요. 장소를 일정에 담은 상태와 실제 방문 완료를 구분해요. 홈의 `30초 시작 안내 → 작성 예시`에서 필요한 가상 예시만 펼쳐볼 수 있어요.

같은 워크스페이스의 여러 여행은 데이터베이스를 재사용하고, 각 페이지의 연결 뷰는 해당 여행·지갑으로 필터링해요. 다른 워크스페이스에서 이 비공개 템플릿 링크에 접근할 수 없다면 기본 섹션으로 대체해요. 다른 사용자에게 배포할 템플릿 설치·복제 흐름은 아직 별도 검증이 필요해요.

`항공·장거리 교통`은 **여정 카드·구간/시간·예약/탑승·환승/공항 이동·요금/변경** 탭으로 구성했어요. 편도 한 구간씩 추가하고, 출발·도착 시각과 각각의 현지 시간대를 선택하세요. 예약번호·티켓·마감·좌석·수하물·기내식·변경 조건은 카드를 열면 묶음별로 작성할 수 있어요. 다음 편에 `이전 구간` 하나를 연결하면 환승 간격을 계산해요. 실제 환승 가능 여부는 별도 확인이 필요해요.

`현지 이동`은 **구간별 이동·노선/환승·비용/시간·막차/심야 대안** 탭에서 작성해요. 항공편·열차와 일별 일정도 연결할 수 있어요. 아래 **교통카드/패스·택시/호출·렌터카**에서 상품과 서비스를 비교하고 이동 구간에 연결하세요. 렌터카 카드는 인수·반납, 면허, 보험·보증금, 주차·통행료, 주유·충전 조건을 나눠 입력해요. 교통 가격은 계획용이며, 실제 결제는 지갑에 한 번 기록해요. 교통 예시는 별도 `작성 예시` 페이지에 모아 실제 여행 화면에서 제외했어요.

`숙소`는 **숙소 카드·후보 비교·확정 숙소·객실/체크인·비용/취소** 탭을 제공해요. 객실·침대·조식·시설·늦은 체크인·출입 방법과 주변 환경을 나눠 작성해요. 숙박 전체 총액과 세금 포함 여부, 보증금·현장 결제액을 구분하며 세금·보증금을 자동으로 더하지 않아요.

`예약 관리`는 항공·숙소·식당·체험·티켓을 공통으로 관리하는 기존 예약 DB예요. **예약 현황·이용 달력·결제/잔금·마감 관리·후속 작업·바우처/연결**로 나눴어요. 날짜만 정해졌다면 시각은 미정으로 두고, 시간을 확인한 뒤 `이용 시각 확인`을 체크하세요. 총액과 결제액을 확인한 뒤 각각 체크하면 잔금이 표시돼요. 예약과 결제·환불 상태는 별도이며 실제 거래는 지갑에 한 번만 기록해요. 담당자·후속 작업·기한과 QR·바우처 파일도 보관할 수 있어요.

숙소·항공을 예약 관리에 연결하면 상세 카드의 `예약 현황`은 공통 예약 상태를 우선 표시해요. 연결 전에는 기존 상태를 표시하고, 기존 예약번호·티켓·메모는 보존해요. 상태·결제·후속 작업은 연결한 예약에서 수정하세요. 날짜·예약번호까지 자동 동기화되지는 않으므로 일정 변경 시 함께 확인해야 해요. 준비·예약 현황은 예약 관리에 등록한 건을 집계해요. 상세 DB와 기존 보기 탭은 네 묶음의 하위 페이지로 옮겨 원본 데이터와 연결을 유지했어요.

`예산과 지출`은 **통화별 지갑·카테고리 한도·실제 거래**를 구분해요. 예비비·예상액·확정액은 실제 결제와 별개이며, 완료된 환불은 지갑 잔액으로 돌아와요. 결제자·수단·일자, 선결제/현장/잔금, 예약·영수증을 기록할 수 있어요. 환율은 원래 통화 1단위당 기준 통화 금액과 적용일을 확인해 입력해요. 기준 통화 환산을 확인한 지출은 카테고리 차트로 보여줘요. 차트는 환불 전 지출 구성이에요.

`동행자와 정산`은 **역할·담당·사람별 정산·지출별 분담·송금 기록·공동 결정**으로 구성했어요. 균등·비율·개별 금액 분담과 반올림 보정을 지원해요. 분담 기준은 거래 당시 값으로 보관하고 원거래 변경 시 대조 경고를 표시해요.

사람별 정산은 **검토한 합계**를 표시해요. 연결 계산을 여러 번 집계하는 테스트에서 0이 조회되어 자동 합계를 확정값으로 사용하지 않았어요. `정산 합계 검토`에서 결제·부담·송금·수령 합계를 확인하고 통화·검토일·기준 확인을 기록해요. 원거래·환율·분담·송금 변경 뒤에는 다시 검토해야 해요. 스킬에 `정산 다시 검토해줘`라고 요청할 수 있어요. 송금 기록은 실제 이체를 실행하지 않아요.

`준비할 일`에는 시작용 체크리스트 **15개**가 있어요. 여행 전·출발 당일·귀국 전후, 진행 보드·달력·기한 확인·여권/입국 확인 탭으로 관리해요. 담당자와 날짜는 비워두었고, 불필요한 항목은 제외하면 진행률에서 빠져요. 여권·입국 요건은 공식 링크·확인일·결과를 작성하는 칸이며 실제 요건이 확인된 상태는 아니에요.

`준비물`에는 시작용 품목 **8개**가 있어요. 공용/개인·필수·담당자·수량·구매 여부·가방 위치와 계절/날씨/활동 조건을 정리해요. 구매 완료와 짐에 넣기 완료를 구분하고, 귀국 전 소지품도 별도로 확인해요. 전체·담당자별 할 일과 준비물 진행률은 상태 변경에 따라 자동으로 바뀌어요. 예시와 실제 입력은 분리했어요.

`날씨 확인`은 지역별 공식 링크·대상 기간·자료 종류·기온/강수·확인일·다음 확인일을 관리하고 일정·준비물에 연결해요. 실제 예보를 자동 갱신하지 않으며 미확인 수치는 미정으로 둬요. 시작용 자료에는 [기상청](https://www.weather.go.kr/w/index.do)과 [일본기상청](https://www.jma.go.jp/bosai/forecast/) 공식 확인처 링크가 있어요.

**플랜 B·C는 기존 일정 카드 안에 추가했어요.** 날짜별 일정의 `날씨·고정 일정`·`플랜 B·C` 탭에서 실내/실외, 변경 가능 여부, 대안 장소·이동·확인사항, 선택 기준·판단 시점을 작성해요. 대안을 선택해도 원래 일정·시간·예약은 바뀌지 않아요. 실제 반영은 영향을 검토하고 요청한 뒤 진행해요.

`자료 보관함`은 카드·분류별 표·중요 자료·링크/파일 입력·일정/장소/예약 연결·보관 포함 전체 보기로 구성했어요. 이미 예약에 저장한 확인서는 해당 예약에 연결해서 찾아갈 수 있어요.

이번 정리에서는 **새 인원 연동 계산의 실제 결과 재조회와 모바일/데스크톱 렌더링 검수는 완료하지 못했어요.** 기존 Query Data Source 한도 오류를 반복하지 않았으며 화면 접근 도구도 응답하지 않았어요. 이전 절의 계산 검증은 당시 수식에 대한 기록이고 이번 인원 연동 수식의 결과 검증을 의미하지 않아요. Python·TypeScript·새 의존성은 추가하지 않았어요.

## 최상단 가로 여행 계획 진행도

공통 배너와 짧은 시작 안내 아래의 **이번 여행 한눈에** 영역에 D-Day·숙소·여행 지갑을 나란히 배치했어요. 카드 아래의 연결은 바로가기 메뉴와 같은 계획·장소 / 이동·예약 / 예산·동행 화면으로 이어져요. 요약과 상세 관리는 같은 여행의 원본 데이터를 사용하므로 한쪽에서 수정한 정보를 함께 보여줘요. 메뉴와 오늘 일정은 그 아래 전체 폭으로 이어져요.

페이지 최상단에는 차트 기능 없이 **수식 기반의 긴 가로 진행 바**를 배치했어요. 한 줄에 여행·완료율·진행 막대·완료 건수를 보여주고, 파랑/회색 막대는 원래 여행 진행률에 맞춰 채워져요. 무료 차트 한도에 막힌 기존 차트 보기는 데이터 보관함으로 옮겼어요. 개별 퍼센트와 계산 설명은 `세부 진행률 · 계산 기준`에 유지했어요. 대상이 없으면 완료율은 `집계 전`, 건수는 `등록한 항목 없음`으로 표시해요.

수식의 저장·컴파일, 여행 필터·가로 표시 너비와 기존 DB/하위 페이지 보존을 확인했어요. 실제 퍼센트 계산값 재조회와 새 막대의 화면 검수는 기존 도구 제한으로 남아 있어요. 이 퍼센트는 등록된 관리 항목의 진행도이며 예산 사용률이나 여행 날짜 경과율이 아니에요.

## 코드·스킬 로딩 정리 (2026-11-14)

Notion 템플릿·배포 설정·매니페스트·디자인 자산은 변경하지 않았어요. 공통 SKILL.md는 57,476바이트에서 8,555바이트로 줄이고, 상세 규칙은 온보딩·데이터 운영·금액·준비·대안·검증 문서로 분리했어요. 여섯 문서는 기존 내용과 대조했으며 상대 링크만 조정했어요. 저장소 로컬 스킬은 공통 스킬을 읽는 진입점으로 바꿔 두 사본의 내용 불일치와 누락된 대화 흐름 링크를 해결했어요.

설치기는 매핑을 임시 파일에 저장한 뒤 원자적으로 교체하고, 각 원격 쓰기 전후에 진행 상태를 남겨요. 명확한 실패 뒤에는 성공한 페이지·기본 행·본문 묶음·여행 행을 재사용해요. 저장 여부가 불확실한 오류나 강제 종료가 남긴 pending_operation은 자동 재전송하지 않고 실제 Notion과 매핑을 확인하게 해요. 설치 대상이나 매니페스트가 달라지면 기존 ID를 혼용하지 않도록 중단해요. 동일 매핑 파일을 여러 프로세스에서 동시에 실행하는 방식은 지원하지 않아요.

## Python 여행 엔진 (2026-11-14)

템플릿 원본은 유지하면서 Python 사용 범위를 넓히기 위해 `trip_engine.py`를 추가했어요. 일정 겹침·이동 여유·예약 기한·오래된 장소·필수 정보는 `check`, 지갑·지출·환불·분담·송금은 `budget`, 짧은 일정 문장은 `organize`, CSV·JSON·iCalendar·장소 텍스트는 `import`, 오늘/다음 일정·예약 기한·숙소·지갑 요약은 `refresh`로 처리해요. 모든 계산과 확인은 기본적으로 읽기 전용이고, Notion 연결 시 설치 매핑의 관련 DB만 페이지 단위로 조회해요.

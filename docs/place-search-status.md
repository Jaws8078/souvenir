# 장소 검색 기능 현황 메모

기준일: 2026-11-18

## 현재 방향

주된 사용 흐름은 **Google Maps API 없이 AI 웹 검색으로 장소를 찾는 방식**이다. 기존 Google Places API 구현·테스트는 보존한다. Google Maps는 장소 확인·지도 보기·길찾기 링크에 사용한다.

다만 현재 실행기는 환경변수에 키가 있으면 API를 선택한다. **키가 있어도 웹 검색을 기본으로 선택하게 하는 코드 변경은 아직 하지 않았다.** 아래에서 `코드 구현`, `스킬 규칙 반영`, `설계/제안`, `실검증`을 구분한다.

## 기능별 현황

| 기능 | 현재 상태 | 확인 범위 |
| --- | --- | --- |
| 자연어로 지역·종류·조건 받기 | 스킬 규칙 반영 | 호스트 AI가 해석하며 전용 자연어 파서는 아님 |
| AI 웹 검색으로 후보 조사 | 호스트 검색 요청 패킷 코드 + 스킬 규칙 | 엔진이 웹 검색을 직접 실행하지 않음 |
| 추천순 최대 10곳 표시 | 코드 구현 + 스킬 규칙 | 후보 정규화·개수 제한·순위·중복 제거 회귀 테스트 |
| 10곳 미만이면 있는 만큼 표시 | 코드 구현 + 스킬 규칙 | 부족한 수를 임의의 후보로 채우지 않음 |
| 추가 요청 시 다음 최대 10곳 | 후보 offset 코드 + 스킬 규칙 | 웹 검색의 추가 조사·누적 세션 운영 전체는 실검증 필요 |
| 장소명·링크·사진 등으로 장소 입력 | 입력 규칙·링크 파서 구현 | 사진 내용 해석은 호스트 도구가 담당 |
| Maps 일반·단축 링크 해석 | 코드 구현 | 리디렉션·장소명 추출·실패 시 확인 필요 처리 |
| 목적지 일치·동명 지점 확인 | 코드 구현 + 스킬 규칙 | 근거 없는 값은 확인 필요, 불일치 후보는 저장 보류 |
| 장단점·가격·영업정보 비교 | 비API 흐름 설계 | 웹 출처별 근거 수집·필드 연결의 종단 간 구현/검증은 남음 |
| 장소별 지도·길찾기 링크 | 스킬 규칙 반영 | 키 없는 URL 구성 규칙, 지점/주소 확인, 검색 링크 구분 |
| Notion 장소 상세의 큰 지도 | 스킬 규칙 반영 | 도구 지원 시 임베드, 실제 생성·핀·모바일 표시는 미검증 |
| 승인 전 후보 저장 차단 | 코드 구현 + 스킬 규칙 | 임시 후보와 정식 행 구분, 승인 함수 검증 |
| 승인 후 Notion 장소 저장 | 공통 저장 경로 + 스킬 규칙 | 최신 비API 검색→저장→확인 존 전체 실검증은 남음 |
| 저장 후 추가 장소 질문 | 대화에서 제안 | 고정 후속 문구를 공통 스킬에 추가하는 작업은 남음 |
| API 직접 검색 | 코드 구현·실 API 검증 | 보존하는 선택/실험 경로이며 현재 주된 개발 방향과 구분 |

## 최초 질문

현재 `conversation-flow.md`의 장소 보관함 시작 문구다.

```text
가고 싶은 장소를 편하게 말해주세요.

지역과 장소 종류만 알려주셔도 괜찮아요.

조건을 붙여 말해주셔도 좋아요: 분위기 · 예산 · 영업시간 등

조건이 없으면 여행지와 취향에 맞춰 추천해드릴게요.

입력 예시:
후쿠오카에서 조용히 쉬기 좋은 카페를 찾고 있어요. 1인 1,500엔 이하이고 오늘 영업 중이면 좋겠어요.

다음 할 일: 원하는 장소를 자연스럽게 말해주세요.
```

이미 받은 여행지·인원·취향은 재사용하고, 검색을 시작할 수 있으면 추가 설문 없이 진행한다. 예산이나 시간 등은 사용자가 원하는 경우 조건으로 받는다.

## 기본 검색·비교 흐름

1. 지역·장소 종류·필수 조건을 정리한다.
2. 호스트 웹 검색으로 공식 사이트·메뉴·공지·공개 자료를 확인한다.
3. 필수 조건·취향·동선·근거의 최신성을 기준으로 추천순 최대 10곳을 보여준다.
4. 각 후보는 번호·장소/지역·추천 이유·주의점·비용·조건 확인·출처·지도 링크로 비교한다.
5. 사용자가 특정 번호를 고르면 그 장소부터 상세 조사한다. 장점·주의점은 근거를 연결하며 후기 한 건을 공통 평가로 일반화하지 않는다.
6. `다음 10개` 요청 시 이전 지점을 제외하고 추가 조사한다. 총 후보 수는 알 수 없으면 미확인으로 표시한다.
7. 저장을 요청한 장소만 현재 여행에 연결하고 장소 파트·확인 존 표시를 확인한다.
8. 저장 후 다른 장소 찾기·조건 변경·다음 계획 파트로 이어간다. 일정 배치는 사용자가 요청할 때 별도로 진행한다.

10곳을 채우려고 조건을 임의로 완화하지 않는다. 가격·휴무·영업 상태·분위기·이동 시간은 확인한 범위만 표시한다. 특히 공식 운영시간 확인과 현재 실제 영업 여부는 구분한다.

## 지도 표시 기준

- **채팅**: 해당 지점의 `[지도] [길찾기]` 링크. 위치를 확정하지 못하면 `[지도 검색 · 위치 확인 필요]`로 표시한다.
- **장소 상세**: `장소명·짧은 위치 → 큰 지도 → 지도/길찾기 → 정보·메모·출처` 순서, 모바일 1열 구성.
- **확인 존**: 같은 여행의 같은 장소 행에서 위치·지도 링크를 연결한다.
- **임베드 미지원**: 정확한 링크와 Notion `/maps` 안내를 제공하고, 지도 표시 완료로 보고하지 않는다.
- **채팅 지도 카드**: 호스트가 실제 지원할 때만 사용한다. 링크가 지도 이미지로 자동 표시된다고 보장하지 않는다.

Google Maps 내부 리뷰 자동 수집이나 지도 이미지 복사를 이 흐름의 기반으로 사용하지 않는다. 웹 후기 역시 출처별 접근·재사용 조건을 확인한다.

## 저장 뒤 이어갈 질문 — 제안 문구

```text
다른 장소도 더 찾아볼까요? 같은 조건으로 이어서 찾거나 새로운 조건을 말씀해주셔도 좋아요.

예시: 이번엔 숙소 근처 맛집 찾아줘.

다음 할 일: 더 찾기 · 다른 조건으로 찾기 · 다음 계획 파트 중 골라주세요.
```

이 문구는 현재 대화에서 합의한 후속 응답 예시이며, 공통 스킬에 고정 반영된 문구는 아니다.

## 검증 기록

- Google Places 실 API 검증 **11개 통과**: 검색·페이지·필터·언어·정렬 요청·목적지 차단·승인·오류·키 없는 패킷 전환.
- 오프라인 회귀 테스트 **174개 중 162개 통과, 선택 실행 12개 건너뜀**. 2026-11-18 실행 기준이다.
- 실검색에서 최초 6페이지·60개를 확인했고, 주소 언어에 따른 목적지 오판·마지막 페이지 누계·인증 오류 분류를 수정했다.
- 비API 웹 검색의 실제 후보 조사→장단점 비교→Notion 저장→확인 존·지도 표시까지 완료한 실험은 아직 없다.
- API 키와 원본 검색 응답은 이 메모에 포함하지 않는다. API 실험 결과가 비API 흐름의 검증을 대신하지 않는다.

## 다음 구현 순서

1. **검색 모드 분리**: API 코드와 키는 유지하되, 키 유무와 별개로 웹 검색을 선택하도록 연결.
2. **웹 후보 근거 연결**: 장단점·필수 조건 확인 상태·출처·지도 링크를 후보 계약에 반영.
3. **검색 이어가기**: 기존 후보 번호·동명 지점·중복 제외·조건 변경을 세션에 유지.
4. **저장 후 질문 고정**: 추가 장소 찾기·조건 변경·파트 이동을 자연스럽게 안내.
5. **실제 Notion 검증**: 승인 장소 한 곳으로 저장 행·여행 관계·뷰·지도 핀·확인 존을 확인.
